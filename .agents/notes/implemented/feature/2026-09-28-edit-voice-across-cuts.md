# Agent Note: 配音与字幕跨切点、有声区间与起点

Status: implemented

## Problem

[剪辑单的静帧段、运镜与配音](2026-09-28-edit-still-cuts.md) 让每条配音落在自己那一段里，按文件长度核对越界与重叠，
音效只能从文件开头放。用真实关键帧和合成配音剪第 1 集样片时，这三条都卡住了节奏：

- 每句话都得在一张图里说完，成片读起来是「一句一张图」，交底和训话两镜只能靠一张图撑 4 秒；
- 合成配音两头各带约 0.15–0.27 秒静音，按文件核对重叠，「周薄森。」和「到！」之间被迫隔出约 0.45 秒；
- 秒表音效文件前 1.46 秒是空白，滴答只能落在镜头 1.5 秒处，而分镜要 1 秒；开场那句挖苦的文件尾巴带着一声笑，
  只能改写成音效来截掉。

## Decision

**剪辑单写法**（`SKILL.md` 的「剪辑单要求」是唯一出处）

- `配音` 的 `起` 仍相对本段，但声音按成片时间线放，可以说过切点、跨到后面几段（L-cut）；
  `起` 可以为负，最早到上一段开头（J-cut），第一段不能为负。
- 字幕的 `止` 可以超过本段时长，`起` 仍在本段内：L-cut 的字幕写在说话人那一段，J-cut 的字幕写在上一段。
  不另设「续接」写法，一句台词始终只有一条字幕行。
- `音效` 与 `配音` 行末可写 `（起点：<秒>；增益：<dB>）`，两项都可省、顺序不限、各至多一次；
  解析在 `_sound_options`，`SoundEffect` 与 `Voice` 各多一个 `offset`。

**check**

- `probe_audible` 把文件解成 8 kHz 单声道，`_audible_span` 按 20 ms 窗口找出比最响窗口低
  `AUDIBLE_RANGE_DB = 40` 以内的首尾，得到 `Audible(duration, head, tail)`。
- `_voice_spans` 把每句的有声区间摆到成片时间线上（文件零点 = 段起点 + `起` − `起点`，有声区间取
  `max(head, 起点)` 到 `tail`）。`_voice_findings` 按整条片报：起点之后没有声音、说过成片结尾 0.05 秒以上、
  与任何一句重叠（包括别的段跨过来的）。
- `_subtitle_findings` 按整条片报：字幕越过成片结尾、与别的段的字幕同时在屏（不带时间的字幕按整段算）。
  同一段里编号字幕的重叠仍在解析时报。
- 每段只查 `起` 在「上一段开头」到「本段结尾」之间。

**render / verify**

- `_placed_voices` 把配音摆成与音效同形的条目，从 `起点` 放到文件末尾；`_sound_effect_command` 用
  `atrim=start=<起点>:duration=<长>`。起点随渲染出的分段位置走，长度不随：音效的窗口是本段的一截，
  跟着帧取整缩放，配音若也缩放，按帧取整变短的段会把跨过去的台词尾巴截掉。
  跨出本段的部分照常按成片时间 `adelay`，由 `amix duration=first` 截在成片结尾。
- `verify` 的「配音落点」列每句在成片里有声的起止和所属段。

**创作台**：`creator_views` 同样读 `起点`（字段名 `from`）和负的 `起`，对照测试覆盖组合写法与 J-cut。

**验证**：`tests/test_edit_measurements.py` 覆盖 L-cut、说过结尾、只有静音尾巴越过结尾、跨段重叠、
只有静音重叠时可以贴着排、J-cut 及其两个边界、起点前移与起点越过有声部分、字幕跨段与三种冲突、
括号写法与五种拒绝、有声区间的计算；真实渲染一段配音从第一段说进第二段、第二段的音效从文件第 1 秒放起，
按频段核对两者各自出现在该在的窗口。11 处守卫逐条改掉，全部变红。

## Alternatives considered

- **跨段的字幕在下一段写一条「续」。** 最强理由是每条字幕都落在自己段里，旧检查不用改。不用：同一句台词被拆成两行，
  文字核对要拼起来才能对上剧本，改一段的时长要同时改两处；一行字幕加上整条片的重叠检查更简单也更严。
- **J-cut 不做，配音只能往后跨。** 最强理由是少一种情况。不用：在语法里只是允许 `起` 为负，边界（上一段开头）一句话说得清，
  检查照样按整条片算。
- **用 `silencedetect` 找有声区间。** 最强理由是 ffmpeg 自带。不用：它按绝对分贝判静音，响度不同的文件要各调阈值；
  相对最响处 40 dB 对每个文件都成立，纯 Python 算也便于测试。
- **配音再加一个「止点」用来截尾。** 最强理由是能直接去掉句尾的笑。不用：多数情况下尾巴该留，让它跨到下一镜；
  真要截时写成带 `起点` 的 `音效` 即可，不为少见情况多一个字段。

## Consequences

- **收益**：一句话可以从说话人说到听者的反应上，静帧成片不再是一句一张图；配音可以按有声部分贴着排；
  音效能从文件中段放起，落到分镜要的那一帧。
- **代价**：配音核对从逐段变成整条片，报错里要写出成片秒数和另一段的 ID 才看得懂；改一段的时长会影响跨过它的配音和字幕，
  check 会报出来但不会自动挪；有声区间的阈值对很轻的气声和尾音会判成静音。
- **已知上限**：画面文字仍然只落在自己段里；J-cut 最多提前一整段。
