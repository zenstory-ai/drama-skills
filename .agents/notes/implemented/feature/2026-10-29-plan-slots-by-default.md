# Agent Note: 缺参考图时默认写 PLAN 挂图计划

Status: implemented

## Problem

v0.6.5 加入 `PLAN-...` 挂图计划后，图片不进项目也能写图生视频提示词，但它只是三条路之一：项目里找不到图时，分镜和视频提示词都先写「待补参考图」、列出缺口、停在视频提示词之前，等创作者在「放图进项目 / 写 PLAN / 改文生视频」里选一条。创作者一句都没说时，路由文档把它当成「还在等图」。

大多数创作者本来就在自己的生成界面里出图、挂图，只要一份文字提示词和逐镜挂图清单。对他们来说，每次都会被拦下一轮，而且得事先知道要说「我自己挂图」，看起来就像这套技能「必须先有图」。

## Decision

把没有另作选择时的默认路径从「待补并停下」改为「写 `PLAN-...` 并照常交付」：

- 分镜：项目里没命中的图默认写成 `PLAN-...`。起始帧定位到本镜 `SHOT-...`；人物、地点、道具定位到已有 `IMG-...` 板子。还没有板子的项不硬造定位符，在本轮报告里点名，建议先补图片提示词。`SHT-23` 补上这条默认。
- 视频提示词：缺图时请分镜 owner 写 `PLAN-...`，然后照常写完；完成报告附逐镜挂图清单、没有板子可挂的项，以及另外两条路（放图进项目改绑 `REF-...`、明确改走文生视频）。
- 路由与创作者文档：四种准备结果的含义不变，只说明默认取哪一种；「待补参考图」只在创作者说过要先等图进项目时使用。README FAQ 与全流程指引同步。

检查脚本不变：`PLAN-...` 的语法、定位符解析、待补阻止最终视频提示词、`PLAN-...` 不能投产都沿用原有校验。

## Alternatives considered

- **保持「待补并停下」，只在报告里把 PLAN 放到第一位**：不改默认，创作者仍有完整选择权。未采用：停下本身就是摩擦，而这一问对大多数创作者的答案都一样；挂图计划是可以原地改成 `REF-...` 的文本，默认写它不会替创作者做出不可逆的决定。
- **没有 `IMG-...` 板子的人物也写 PLAN，定位符改指《视觉设定.md》条目**：每一项缺图都能有槽位，一致性信息不会丢。未采用：这会给 `PLAN-...` 增加一种定位符，牵动检查脚本与生产选择器的契约；视觉设定条目也不是可复制的出图提示词，创作者拿到它仍不知道该挂哪张图。改为在报告里点名、建议补板，补完再加槽位。
- **缺图时默认改走文生视频**：交付最快。未采用：违背「没有手工指定不等于选择文生视频」这条不变式，静态视觉锚点替代不了真实参考图的一致性。

## Consequences

- **收益**：在自己工具里出图的创作者，一次请求就能拿到图生视频提示词和逐镜挂图清单，不用再学一句特殊说法。
- **代价**：想用本套件投产的创作者，现在默认拿到的是 `PLAN-...` 镜头，要把真实文件放进项目、改写成 `REF-...` 后才能预览生产（正文不用改）；生产技能遇到 `PLAN-...` 时照旧提示这一步。没有 `IMG-...` 板子的人物不会出现在挂图清单里，跨镜一致性只靠起始帧和连续性锁，靠报告里的点名提醒补板。
