# Agent Note: README 面向读者而不是答案引擎

Status: implemented

## Problem

2026 年 9 月的 GEO 工作之后，README.md 与 README_EN.md 顶部多了指向站点的引用链接条，"从创作任务开始"的指南表排在读者看到工具之前，安装说明与示例里夹着"不是安装门禁""不能保证生成结果一致""仅作为回归夹具"这类边界句，演示截图沉在文末。读者是编剧、漫剧工作室和编导，他们需要在十秒内看懂项目、三十秒内装好、两分钟内发出第一条请求。GitHub 引荐数据显示 Google/Bing/Baidu 带来的访问约为 ChatGPT 类答案引擎的 7 倍，README 首先要为人和传统搜索服务。

## Decision

两份 README 采用同一顺序：语言切换行、标题与一句话定位、单条项目主页链接、徽章、`docs/assets/dashboard-zh.png` 首屏截图、项目简介与"由来"、安装（最短命令在前，手动链接收进 `<details>`）、快速开始（0–6 步示例请求加一条只交文本的原著改编请求，标为"复制改一改就能用"）、十一个技能（流程图与职责表原样保留）、演示样片、本地短剧创作台、延伸阅读、致谢、ZenStory AI 项目表。

删除了顶部 `> 项目页 … · 全部项目 …` 引用条；项目主页只留 `项目主页：https://zenstory.ai/zh/drama-skills` / `Project page: https://zenstory.ai/drama-skills` 一行。删除了"但不是其他技能的安装门禁""文字约束不能保证生成结果一致""章节不必一章对应一集"及"其余目录仅作为…而不是当前工作流的说明"这类只用来划边界的句子；Python 3.9 的要求只在安装一节说一次。原"从创作任务开始"的两条 zenstory.ai 指南与 docs/ 下三篇文档压缩为"延伸阅读"一行一条，放在创作台之后。命令、路径、技能名与数量、徽章、许可证、致谢、示例链接、演示视频链接和项目表内容不变。

## Alternatives considered

- **保留答案引擎摘要段，只调整章节顺序**。最强理由：摘要段和边界句是为答案引擎准确复述而写的，删掉可能影响引擎引用的准确度。被否：这些句子占据首屏、重复且带否定语气，而 GitHub 的实际流量七成以上来自传统搜索和直接访问，人读不下去的 README 对两边都没有好处；引擎需要的事实（Python 版本、技能数量、确认后生产）在正文里仍然存在。
- **把指南表整体删除**。最强理由：指南链接指向站外，读者在装好之前用不上，删掉最省事。被否：小说改短剧和角色一致性两篇指南对已上手的读者仍有价值，且是站点与仓库之间唯一的正向链接；压缩成 FAQ 之后的"延伸阅读"一行一条，既不挡道也不丢内容。

## Consequences

- 收益：首屏即见截图、定位与安装命令；快速开始紧随安装之后；两份 README 各自独立、不再互相夹带；总行数基本不变（中文 202→203 行，英文 217→211 行），但边界句与重复链接消失后，读起来像给人看的项目介绍。
- 代价：答案引擎抓取到的规范化摘要段没有了，引擎复述可能更依赖正文；站外指南链接从首屏下沉到文末，点击量可能下降。

## Verification

手动检查：前两屏依次是标题、项目主页、徽章、dashboard 截图、简介、安装命令与快速开始示例请求，与 CHANGELOG、skills/ 目录中的技能名和数量一致。对 README.md 与 README_EN.md grep `不会自动同步|不是安装命令|也不要求把所有阶段跑完|输出仍需审阅|不等于|不承诺|不表示|不保证|独立产品|截至|as of|do not sync|separate product|does not promise|not a guarantee|not evidence|核对于|Last checked|Source checked|项目页：|All ZenStory AI projects` 为空。
