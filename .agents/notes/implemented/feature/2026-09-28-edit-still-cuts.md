# Agent Note: 剪辑单的静帧段、运镜与配音

Status: implemented

## Problem

静态漫剧（关键帧加配音）在 `docs/comic-drama-workflow.md` 里可以跳过《视频提示词.md》，却没有办法装成成片：
`edit_tool.py` 的每个 `CUT-` 都必须来自一个 `MOTION-` 视频，没有《视频提示词.md》时 check 直接报「无法核对」。
这条路线的创作者手上是已接受的关键帧和逐句生成的配音，想用同一份剪辑单、同一套字幕、画面文字、音效和响度出片。

## Decision

**剪辑单写法**（`skills/short-drama-edit/SKILL.md` 的「剪辑单要求」是唯一出处）

- `- 来源：SHOT-... · <图片>` 或 `IMG-... · <图片>`，图片为 png / jpg / jpeg / webp。来源 ID 决定段的种类：
  `MOTION-` 配图片、`SHOT-`/`IMG-` 配视频都在解析时报错。`Cut.motion` 仍存来源 ID，`Cut.still` 由前缀算出。
- 静帧段入点 `0.00`、出点等于时长、时长不短于 `STILL_MINIMUM = 0.50`，在 check 里报；
  有静帧时交付规格必须写「画幅与帧率」，与视频混剪时每个视频段的画幅帧率须等于它。
- `- 运镜：固定|推近 n%|拉远 n%|左移 n%|右移 n%|上移 n%|下移 n%`，n 为 1–30 的整数，不写为固定；
  写在视频段上、写错值都在解析时报错。方向是镜头的方向：左移时取景框向左。
- `- 配音 N：<起> <路径>（增益：<dB>）`，编号、单条不编号、重复字段的规则走 `_field_entries`，
  增益与音效共用 `_gain`。视频段也可写，叠在原声上，不替换原声。

**check**

- `_source_findings`：每种前缀只在剪辑单用到时才去读对应文档（`视频提示词.md`、`分镜.md`、`图片提示词.md`），
  缺文档或 ID 不在其中都报。
- 覆盖：有视频段时查《视频提示词.md》，有 `SHOT-` 静帧时查《分镜.md》，只有 `IMG-` 静帧时不查分镜覆盖。
  一镜只需一个下落：`MOTION-` 的「分镜」镜头以静帧进片即算用上；`SHOT-` 的视频进片或 `MOTION-` 写进未采用也算有下落；
  只把 `SHOT-` 写进未采用时，对应的视频仍要说明。`_unaccounted_shots` 加了 `accounted` 参数承接这些。
- 配音：起点在本段内、文件存在；有 ffprobe 时量文件长度，`起 + 长度` 超出时长 0.05 秒以上、同段两句重叠都报。
  素材比剪辑单新的提醒对静帧段看配音文件，不看图片。

**render**

- 静帧段由 `_still_command` 出画：`-loop 1` 读图，`_still_filter` 等比铺满交付画幅后居中裁切；
  有运镜时接 `perspective`（`eval=frame`、三次插值），四个角每帧按余弦缓动的取景框计算，
  推拉改变取景框大小，平移时取景框固定为 `1/(1+n%)` 并从一边走到另一边。
  音轨是 `anullsrc` 静音，采样率与声道取第一个视频段的原声，没有视频段时为 48 kHz 立体声，
  这样按流拷贝拼接时不会从第一个静帧起解错。
- 配音由 `_with_voices` 转成从起点放到文件末尾的 `SoundEffect`，与音效走同一个 `_placed_sound_effects`
  和 `_sound_effect_command`，随后照常测响度、标准化。
- 自动接镜：`SHOT-` 静帧从该 SHOT 追场景并参与；取样用 `_still_stats` 读整张图铺满后的样子，
  因为 `fps` 会丢掉单帧图、对 JPEG 做 `-ss` 读不出帧。
- `verify` 另列「配音落点」；切点亮度与坏帧报告不区分段的种类。

**验证**：`tests/test_edit_measurements.py` 覆盖解析与拒绝、静帧时间规则、ID 解析、纯静帧与混剪的覆盖、
混剪的画幅核对、配音越界与重叠；有 ffmpeg 时真实渲染一段推近加配音、一段左移，核对帧数、画幅、帧率、时长、
推近与左移的方向、缓入缓出、配音窗口有声而窗口外无声、两段参与自动接镜、无疑似坏帧。17 处守卫逐条改掉，全部变红。
本机另做过视频（单声道 44.1 kHz）与静帧混剪，拼接后完整解码，响度 −16.01 LUFS。

## Alternatives considered

- **用 zoompan 做运镜。** 最强理由是它就是为这件事设计的，一个滤镜、单帧输入。不用：它按整像素取景，
  慢推会抖。1080×1920 实测逐帧运动的抖动（相邻两帧位移差的均方根），推近 0.34 px、平移 0.84 px；
  先放大 4 倍再 zoompan 降到 0.14 与 0.23 px；`perspective` 为 0.10 与 0.11 px，渲染时间与 4 倍放大相当。
- **`perspective` 前再放大 2 倍。** 最强理由是源图比交付画幅大时推近能多保留细节。不用：实测平滑度几乎不变，
  渲染时间约 2.5 倍；关键帧通常与交付画幅相当。
- **静帧的音轨固定为 48 kHz 立体声，视频段也统一转成它。** 最强理由是简单、与需求原文一致。不用：把单声道对白升成立体声
  会低 3 dB（画面文字那篇笔记里实测过），而不转换时流拷贝拼接会解错；让静音去匹配视频更省事也不动原声。
- **只要剪辑单里有静帧，就不查视频提示词覆盖。** 最强理由是规则更少。不用：混剪时某条视频既没用、镜头也没以静帧进片，
  会无声无息地从成片里消失，这正是覆盖检查要抓的。
- **`IMG-` 静帧也按图片提示词查覆盖。** 最强理由是对称。不用：图片提示词里多是角色板、场景板，本就不进片。
- **配音写成 `<起>-<止>`，与音效同形。** 最强理由是少一种语法。不用：配音要整句放完，`止` 只能由文件长度决定，
  写出来的数字要么多余、要么截断台词；让 check 用实际长度核对更可靠。

## Consequences

- **收益**：静态漫剧从关键帧和配音直接出片，字幕、画面文字、音效、响度、自动接镜与 verify 的报告都照常可用；
  可以在视频不可用的镜头上先用关键帧顶上；配音放不下、互相重叠在渲染前就会报出。
- **代价**：`Cut.motion` 的名字不再准确（存的是任意来源 ID），为了不动既有调用方而保留；配音核对要 ffprobe，
  没有时报未测；运镜只有七种、只能匀速缓动，要关键帧动画或视差需要外部工具；创作台的剪辑单视图仍只认 `MOTION-` 来源，
  静帧段在那里还不显示。
- **已知上限**：成片的格式时长比各段之和略长（本机实测 0.03–0.1 秒），来自拼接、混音与响度标准化后的音频尾部，
  走的是视频段同一条路；视频流本身帧数准确；
  覆盖只追 `视频提示词.md` 的「分镜」一行，写错这一行时混剪的对应关系会断。
