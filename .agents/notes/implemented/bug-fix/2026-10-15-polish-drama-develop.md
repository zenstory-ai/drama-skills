# Agent Note: 开发文档与独立运行、索引和来源事实契约对齐

Status: implemented

## Problem

五步精修回查了 `short-drama-develop` 的阶段契约、模板和 `episode_intake.py`，发现三处文案会引导 agent 违反既有约定：

- `multi-episode-intake.md` 把 `verify` 通过当成来源未变化的证明，但脚本只核对总长度、跨度、顺序与行/字节对应，不能发现保持这些结构的等长原地改写。既有 STY-18 与[去除人工哈希的决定](../../implemented/simplification/2026-08-18-no-hand-maintained-hashes-in-artifacts.md)已说明这一限制。
- 同一参考强制通过 core 发布索引和地图，没有交代独立安装的落盘分支，与 `stage-contract.md` 的可选项目集成冲突。独立运行原则见[自包含技能决定](../../implemented/architecture/2026-07-26-self-contained-skills.md)。
- `adaptation-craft.md` 把尚未安排可见载体或延后集号的不可改来源事实降为“备注”，与 STY-23 要求补齐落点的义务冲突。`episode-design.md` 又称纯功能描述“不会被任何门拦下”，忽略了 STY-24 的语义审查。

## Decision

开发文档按既有职责补齐分支：编辑来源即重建索引；集成项目继续用 core 发布，独立运行则在本地核对候选与当前文件差异后保存；没有落点的不可改事实保留其约束力并补齐规划。明确结构校验与语义审查的能力边界。

同时将少量未分清层次的表述对齐已有规则：人物跨集变化统一记录与逐集结果分开；前提装置的接受、生效与披露分开；生活流题材使用项目传入的制作形态，不自行召回其他技能的形态卡。现有数字只保留为项目起点、示例或可覆盖的工艺参考。

独立复核进一步将默认下游交接对齐 `剧本.md` → `视觉设定.md`，移除单集卡/实现块的旧前提；审查摘要继承 STY-07 的“创作者已接受改动除外”，避免否决已授权的改编。

## Alternatives considered

- **给索引增加内容摘要**：能自动发现等长改写，但会改变脚本与产物结构，也重开已有的哈希取舍。本轮只对齐文档与现有能力，不新增检测机制。
- **统一要求安装 core**：发布路径最单一，但会取消已承诺的独立安装能力。保留 core 的集成路径并写清独立分支。

## Consequences

- 收益：创作者和 agent 能区分机械验证、来源编辑责任与语义义务；独立使用不再卡在不存在的 core 上。
- 代价：独立运行仍需 agent 核对并保存候选，来源的等长改写仍无法自动检出。该限制由编辑后重建的流程承担。
- 所有改动限于开发技能文档；命令、JSON、规则 ID/等级和既有示例保持不变，不声称新增脚本校验。
