# Agent Note: 剪辑的同场景自动接镜、切点亮度与坏帧报告、对白入出点默认

Status: implemented

## Problem

维护者看样片时指出「闪帧」和「频繁切镜、节奏乱」，查到三个原因：

- **合成出的坏帧。** 早先在 Remotion 里用 `OffthreadVideo` 把字画在拼接素材上，素材帧时间略不规整（29.96 fps），
  解出一帧顶部串进别的镜头画面。现行的[透明叠层加 ffmpeg 合成](2026-09-27-edit-screen-text-overlay.md)不在浏览器里解码画面，
  避开了它，但交付前没有任何一步能发现这类帧。
- **切点亮度跳变。** 各段独立生成，同一场景相邻两段的亮度差可到约 35（0–255），切过去像闪了一下。
  剪辑单只有逐段手写的 `画面：亮度/饱和/色温`，`_shot_match_filter` 的文档写明工具从不自己测量和调整。
- **对白入出点。** 生成的对白镜晚开口、句后拖尾。从素材起点切、出点放在「最后一个转写词 + 0.3 秒」，切点又晚又松；
  转写杂音把一个单音节「嗯？」镜拉到 5 秒。

## Decision

**自动接镜**（`edit_tool.py`）

- 场景由 `_scene_keys` 追出：CUT 的 `MOTION-...` → `视频提示词.md` 该条的「分镜」→ `分镜.md` 该 SHOT 的「来源」里的场景 ID
  （`SCENE_ID`）。跨场次的镜头以全部 ID 为键，追不到的为 None。
- `_scene_runs` 取相邻且同键的连续段为一组；插叙的同一场景是不同组，None 不入组。
- `_plan_shot_match`：组内既没写校正、也没写 `画面：不校` 的段才参与；这样的段不足两个的组不测量。
  `_channel_stats` 按 `fps=4,scale=64:-2` 取样该段源区间，算 RGB 各通道的均值与标准差；
  组内取中位数作参照，`_match_toward` 让均值与标准差各走 `SHOT_MATCH_STRENGTH = 0.7` 的距离，
  增益夹在 0.6–1.6，偏移按夹过的增益算，使均值仍落在目标上。滤镜是一个 `lutrgb`，每通道 `val*增益+偏移`。
- `_picture_plan` 决定每段的滤镜：写了 `画面` 校正用 `_shot_match_filter`，否则用自动接镜，否则不加。
  写了校正或 `不校` 的段不计入中位数。
- 关闭：交付规格 `- 接镜匹配：无`（或 `关`）→ `Delivery.shot_match = False`。
- render 输出「自动接镜」：各段的增益与偏移；关闭时写明是剪辑单关的；追不到任何场景时写「未执行」。
- 规则登记为 `EDT-20`（craft_default）；做法写在 `references/generated-footage.md` 的「接镜与色彩一致性」。

**verify 的逐帧报告**

- `_grey_frames` 把成片按 90×160 灰度逐帧解出。
- `_cut_jumps`：按分段实测时长累计出切点，报告切点后第一帧与前一帧的平均亮度差，标「同场 / 换场 / 未知」；
  绝对值超过 `CUT_JUMP_NOTICE = 20` 的写进「请逐帧查看」。
- `_suspect_frames`：与前后两帧的平均绝对差都超过 8、而前后两帧彼此的差不到其中较小者一半的帧。
  硬切只与一侧不同，匀速快动作的前后两帧彼此差得更多，都不会被列出。
- 疑似坏帧落在某条画面文字起点后 0.15 秒内时标「画面文字入场」，面板入场的故障效果据此区分。
- 两项都只进报告，verify 仍返回 0。

**对白入出点**：`references/cut-craft.md` 写成默认做法（`EDT-19`，craft_default）：开口前约 0.25 秒入，
台词结束后留约 0.4 秒反应再出，整段不短于约 1.2 秒，只按属于本句台词的发声定位。check 没有测量发声区间，
这条不做机械检查。

**Remotion 叠层**：`assets/remotion/README.md` 写明叠层渲成透明再合成，也是为了不在浏览器里解码画面。

**验证**：`tests/test_edit_cut_continuity.py` 覆盖增益与偏移的算术、增益上下限、写明校正与 `不校` 不参与也不计入中位数、
关闭开关、只按相邻同场景分组且孤段不解码、场景追溯、坏帧检出与三种不误报（匀速快动作、阈值下的抖动、硬切）、
切点亮度报告与只列超阈值的一条、入场标注、读不出成片时报未测；有 ffmpeg 时真实渲染两段亮度差约 60 的纯色素材，
verify 测得切点变化 17（约 30%）。18 处守卫逐条删除，全部变红。样片上同一做法把最大切点跳变从 34.5 降到 18.1，均值 5.6。

## Alternatives considered

- **只执行剪辑单写明的校正，工具从不自己测量调整。** 最强理由是每一处改动都在文档里，审查者看得见。不用：
  逐段独立生成的素材几乎每个同场切点都要手写，实际没人写，成片照样闪；自动接镜的数值列在 render 输出里，
  写明的校正仍然优先，审查可见性没有丢。
- **把各段拉到组内中位数（强度 1）。** 最强理由是切点最平。不用：全画面统计受景别、服装面积和背景影响，
  拉满会把特写和远景的正常差异也抹掉；0.7 在样片上已把跳变压到不再像闪。
- **在全片或相邻两段之间匹配，不分场景。** 最强理由是不依赖分镜文档。不用：日景切夜景、闪回的亮度差是有意的，
  跨场景匹配会把它们拉平；追不到场景时不动比猜更安全。
- **疑似坏帧阻断交付。** 最强理由是坏帧确实是缺陷。不用：画面文字的入场故障、闪光类表演也会命中，
  阈值判断不了创作意图，只能指出该看哪一帧。
- **check 按转写结果检查对白入出点。** 最强理由是能机械抓出拖长的镜头。不用：本技能不带转写工具，
  为此加一个依赖不值；杂音问题本身就出在转写上。

## Consequences

- **收益**：同场景切点的亮度跳变默认就被压低，用过的数值留在输出里；解码错位这类单帧问题和残余的切点跳变有了具体时间点可看；
  对白镜的入出点有了可照做的默认值。
- **代价**：render 对每个参与接镜的段多一次小尺寸解码；verify 在 Python 里逐帧比对，一分钟 30 fps 的成片约多两秒；
  自动接镜依赖《分镜.md》的「来源」写对场景 ID；同一场景内有意的光态变化要逐段写 `不校`。
- **已知上限**：匹配只用全画面的均值与标准差，局部偏色（只有脸偏黄）不处理；一组只有一个可参与的段时不接镜；
  坏帧夹在切点上（前后两帧属于不同镜头）时检不出；亮度变化只比切点两侧各一帧。
