# Agent Note: 全量精简技能指令中的人类培训说教、低频分支、空泛套话与重复规则

Status: implemented

## Problem

经历多轮扩充与可读性润色后，套件内 13 个技能（12 个公开创作技能与 `maintainers/skills/short-drama-knowhow`，共 154 个 Markdown 文件、20,428 行）残留三类稀释 Agent 注意力、浪费上下文窗口的指令噪音：

1. **面向人类培训或课堂教学的指令与低频边缘分支**：部分 `SKILL.md` 和 `references/*.md` 把 Agent 当成写作训练营的新手学员，写入面向人类心理建设的说教、用户提问句式教学、小样本实验次数日志（如 `9 次均…3 次全对`、`相似度 0.09–0.46`、`盲评清晰度 3.9/5`）、绑定特定本机环境的命令或极少出现的边缘情形（如轮胎机位、罕见怪异排版）。
2. **模糊、大差不差、读完没有决策增量的套话**：部分章节用正确但无信息量的泛泛之谈、空泛导语/总结段、无链接的 `## 目录` 列表或空白练习表充当工作流步骤，Agent 读完得不到具体改写动作或明确的判别边界。
3. **跨位置、跨文件的重复指令未清理干净**：
   - **单文件内多重重复**：同一条规则常在文件导语、正文章节、“常见失败模式”和末尾“完成前自检”里用相近措辞重复多遍；
   - **同技能内跨文件重复**：`SKILL.md`、`references/stage-contract.md` 与各专题 `references/*.md`、`form-cards/*.md`、`genre-cards/*.md` 反复抄写同一套阶段所有权声明、四级规则分级定义、题材分支或参考图槽位语法；
   - **跨技能重复**：上游或下游技能在自身参考文件里重述另一技能的内部细则，而非只声明交接边界与路由目标。

## Decision

全量逐文件审阅并精简全部 154 个技能 Markdown 文件（154/154 文件均完成修剪，总行数从 20,428 行降至 8,569 行，净减 11,859 行 / -58.1%）：

1. **剔除人类培训口吻、实验过程流水账与低频场景指令**：删除面向人类初学者的心理疏导、课堂练习式导语、小样本实验次数与盲评打分流水账（保留提炼出的可执行创作与提示词规则，如常速字数、首帧开口延迟、非实拍媒介声明等），移除低频特例与特定运行环境模型硬编码。
2. **删除模糊、同义反复、无指导价值的空话**：删除全部 154 个文件中的无链接 `## 目录` 列表、空白练习表、空洞导语/收尾套话和无法转化为具体检查或改写动作的泛泛之谈；保留具体因果、正反例对照与边界条件。
3. **合并与删除重复指令**：
   - 单文件内：移除文末与正文重复的“常见错误 / 完成前自检 / 审查问题”复述段，修正因删节产生的章节跳号；
   - 同技能内：四级规则分级统一归口到 `skills/short-drama/references/knowhow-index.md#规则分级`；阶段所有权与规则表归口到各技能 `SKILL.md` 与 `references/stage-contract.md`；`genre-and-hook-playbook.md` 删除与 `genre-cards/*.md`、`episode-design.md` 重复的分题材段落；`form-cards/*.md` 删除与正文及 `production-form-profiles.md` 重复的末尾汇总表；
   - 跨技能：只保留交接契约与 `$skill-name` 路由，删除越界复述其他技能内部规则的段落。
4. **保持结构契约与测试不变量完整**：保留 `EXPECTED_KNOWHOW` 要求的全部参考文件、`stage-contract.md` 规则 ID、文档内 `#anchor` 链接、创作者五份 Markdown 模板字段与测试引用的精确契约短语。

## Alternatives considered

### 只清理各技能的 `SKILL.md`，跳过 `references/` 下的专题文件与题材卡

- **最强理由**：`SKILL.md` 是入口文件，改动范围小（仅 13 个文件），风险低且耗时短。
- **为何不用**：用户明确要求“一定要全部文件都过一遍”，且大量重复免责声明、人类培训式说教、文末重复自检表和空泛套话恰恰堆积在 `references/*.md`、`form-cards/*.md` 与 `genre-cards/*.md` 中；只改 `SKILL.md` 无法真正消除上下文噪音。

### 直接合并或删除部分 `references/*.md` 文件

- **最强理由**：减少文件数量在表面上最直观。
- **为何不用**：`tests/test_creator_first_golden.py` 的 `EXPECTED_KNOWHOW` 与技能内单跳链接结构明确约束了各技能的标准参考文件集合，按专题拆分本是为了让 Agent 按需加载（Progressive Disclosure）。问题不在文件名拆分，而在每个文件内部塞入了重复的通用声明、人类培训废话与同义反复。

## Consequences

- **收益**：
  - 全部 154 个技能指令文件密度显著提升（平均压缩 58.1%），Agent 每次加载 `SKILL.md` 或专题 `references/*.md` 时只读到直接指导判断、生成或校验的干货规则与高质量正反例；
  - 消除同一规则在单文件内四处复述、同技能内多文件粘贴的维护负担，避免后续修改一处而遗漏另一处。
- **代价**：
  - 涉及全部 13 个技能目录的 154 个 Markdown 文件逐一审阅与两轮修剪，同步更新了文档内 `#anchor` 标题锚点与 `.clawhub/publish.json` 发布清单摘要。
