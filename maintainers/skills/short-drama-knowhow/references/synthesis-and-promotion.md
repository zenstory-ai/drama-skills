# 脱敏改写、规则归纳与分级维护

## 从单点观察到条件化经验

先顺着项目文稿与经核实的成片表现讲透某做法解决了什么具体难题，分清观众看点预期与表面套路、巧合共现与真实因果、单部剧个人口味与跨题材可迁移方法。

提炼时把具体做法归纳为：`观众已知信息 → 本场难题 → 调度或提示词做法 → 画面可见表现 → 必保上游设定 → 不适用情形`。

比如遇到“多人同框画面乱、观众看不过来”的抢戏问题，可归纳为视线焦点分配做法：场内只留一个主动作，给其余角色分别安排接收反应、克制掩饰或做出抉择的具体状态，并写明视线焦点在何时从谁身上交接到谁身上；这样既能稳住群像层次，又不会定死“群像戏一律只准一个人动”的教条。切忌照搬特定平台的私有参数、内部编号、原稿字句或罕见桥段组合，也不要把单个项目的个人口味（如“多切空镜、不铺配乐”）拔高成全行业通则。

## 反例排查与适用边界

起草或修订前逐一核问：

1. 换到相近题材或不同人物关系里，会不会破坏观众原本期待的看点？
2. 观察到的好效果，究竟来自当前环节的写法，还是上游剧本铺垫、参考图质量或后期剪辑里的另一环？
3. 上游文稿里顺理成章的要求，传到下游提示词后会不会变成直白说教旁白，或超出当期模型的稳定生成边界？
4. 新出现的反例是在推翻这条经验，还是说明需要把适用前提收得更窄？

能讲清边界时，明确写出适用前提与不适用时的替代做法；成因尚有冲突时暂缓合入，不靠样本票数多少强行定论。

## 脱敏与去复刻改写

1. 删净连接信息、本地路径、来源名称、内部编号、人员、项目名、角色名、机构名与独有世界观设定。
2. 删掉原稿字句和连续措辞片段，只保留对因果关系、观众知情状态、人物动作与视听做法的抽象说明。
3. 打散罕见的“题材 + 人物关系 + 场景 + 道具 + 反转方式”组合，抹除可反推原项目的独有桥段特征。
4. 把内部临时格式或单项目数值约定改写为通用用途说明，不把偶然数字定成硬门槛。
5. 另起炉灶，换全新的题材、人物关系、空间环境与表演动作重编虚构示例（仅替换人名、地名、性别或年代仍属变相照搬）。
6. 拿草稿反查内部研究笔记：只要仍能凭独特顺序、用词习惯或设定组合认出原项目，就继续抽象重写或直接放弃；新旧对照关系绝不带出授权隔离区。

## 按规则等级落盘（切断门禁膨胀）

公开改动按规则等级轻重分流，**不再要求每次经验沉淀都捆绑新增审查扣分细则（`rubric_proposal`）**：

- **`craft_default` / `taste_option`（经验建议与风格选项）**：默认只写进对应阶段技能的 `references/` 参考指南（必要时补充全新编写的简短虚构示例），写清要解决的问题、适用条件与例外边界，**不新增审查阻断项、扣分门禁或校验脚本报错**。完成脱敏自查并通过仓库回归测试即可合入。
- **`structural_invariant` / `reviewed_invariant`（阻断级门禁规则）**：仅在缺失该约束必然引发跨阶段结构断层、上下游事实矛盾或生产交付事故时设立。除参考说明与客观判定标准外，须先通过 [blind-forward-eval.md](blind-forward-eval.md) 的匿名对照盲评，并将门禁增设理由、备选方案取舍与影响范围记入仓库 `.agents/notes/` 决策笔记。

## 旧规则的降级、收窄与废止

一旦真实创作反例、成片实测或下游模型能力演进表明某条既有规则管得过宽、频繁误伤合理写法或已成过时教条，**无需换题重跑双盲评测**：凭明确反例或模型演进事实，直接将其降级为 `craft_default`、收窄适用前提或从参考文档与审查清单中删除，跑通仓库现有回归测试即可合入。涉及重要门禁撤除或跨文件契约调整时，同步在 `.agents/notes/` 更新或新增决策笔记，版本回溯直接依托 Git 提交历史。
