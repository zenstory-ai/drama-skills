# 全新上下文盲测协议（Fresh-agent Blind Forward Eval）

## 目标与角色隔离

验证候选是否帮助新 agent 在陌生题材中做出更好的创作判断，而非复述学习材料。候选作者、全新上下文执行者（fresh agent）与独立审查者（independent reviewer）三者严格分离；参与摘取、卡片合成或候选写作的 agent 不得担任最终审查者。

执行者只接收用户式任务、公开可用上下文、一个匿名 skill 版本和合成输入；不得读取私有来源、观察卡/决策卡、去标识映射、作者诊断、预期答案或另一组输出。

## 准备评测包

为同一目标建立匿名 `baseline` 与 `candidate` 包，除候选 `reference` / `rubric` / `fixture` 外保持任务、上游限制和交付格式一致。任务组合须覆盖候选声称适用的语境、一个边界语境、一个潜在反例，以及从编剧到分镜/提示词的文本传递；严禁使用来源人物、原句、情节顺序或罕见设定组合。

每个任务提供：自然的用户创作或审查请求、完全合成的故事约束与已有文本产物、允许与禁止修改的边界、需提交的目标文本、缺失信息处理要求，以及禁止连接非公开来源和禁止生成/查看媒体的声明。候选作者只写任务，不写标准答案；由不知匿名映射的协调者分配版本并保存原始输出。

## 运行盲测

1. 为每个任务启动干净上下文的 fresh agent，以真实用户口吻要求其使用分配到的匿名 skill 完成任务，不透露被测规则，也不补充候选作者解释；若 agent 提问，只提供预先允许且两版本一致的信息。
2. 协调者单独保存 prompt、skill 版本 hash、输入 hash、原始输出、工具调用摘要和未完成原因，不附入供盲评者阅读的产出。
3. 换新上下文运行对照版本，防止跨轮污染。
4. 生成供盲评者阅读的匿名副本：剥离绝对路径、包目录、工具读取清单、分组身份和版本映射，仅保留创作产物与不暴露分组的范围声明，并对匿名副本做 hash 与泄漏扫描。

## 盲评 rubric

Reviewer 在揭盲前针对具体证据逐项比较，不靠总分或关键词打分自动胜出：

- `dramatic_reasoning`：期待、阻碍、行动、信息变化与兑现是否构成可解释因果；
- `character_agency`：人物是否用符合处境的可表演行动推进，而非被机制搬运；
- `genre_transfer`：是否服务当前题材与受众承诺，而非复制单一题材表皮；
- `boundary_judgment`：在反例或不适用语境下能否换法、缩窄或拒绝套用；
- `production_translation`：剧本意图传到资产、连续性、分镜、关键帧与提示词时是否保持；
- `creative_variance`：不同任务是否出现有意义的机制变体，而非同句式、同节拍和同镜头模板；
- `instruction_cost`：候选是否增加无关流程、过度解释或妨碍创作；
- `privacy_and_scope`：是否只用合成/公开材料、无来源指纹、无连接尝试、无媒体调用。

每项记录输出位置、影响、偏好与置信度。若各有优势，指明候选应缩窄到哪些条件；若差异来自偶然文风或执行失败，记为 `inconclusive`。

## 独立审查交接与结果判定

1. **揭盲前**：只向独立 reviewer 提供匿名输出、合成任务、匿名包 hash、泄漏扫描结果和公开 rubric；reviewer 完成逐项偏好、边界问题与初步 verdict 后冻结评审。
2. **揭盲后**：提供版本映射、公共候选包、无敏感内容的证据摘要及冲突与边界清单，核对两包是否只差目标改动、任务是否真实检验候选且未提示答案、边界任务是否体现判断而非机械匹配、以及是否存在泄漏或近似复刻。
3. **生命周期决定**：给出 `promotion`（需明确独立批准与可回滚最小 diff）、`narrow-and-retest`（退回缩窄边界与合成任务）、`hold`（保留问题与下次对照意图）或 `retire`（记录无增益、过拟合或边界失效原因），并按 [promotion-ledger.md](promotion-ledger.md) 登记。
