# Agent Note: 质检与投产之间的四处死路

Status: implemented

## Problem

创作者反映，项目卡在质检环节出不了片，还在反复消耗 token。逐条核对后确认有四处，都是文档或检查器把流程引到一个出不去的状态：

1. **续接段没有出口**。视频提示词第 15 步默认让同一连续时空的相邻正式段组成「实际视频 + 实际尾帧」接力链。可是内置 `$short-drama-produce` 的 creator-first 来源选择器只能解析图片和角色参考音频，绑定不了续接视频，所以第二段起一直是「待续接、不可提交」。原文只让生产阶段「报告接口缺口并保留已选路线」，同时禁止改成文生视频或省略选择器。唯一的出口是「创作者明确要求独立重生成」，但从来没有哪一步去问创作者。
2. **同路径双槽**。分镜 SKILL、图片提示词 `common-recipe.md`、路由的 `creator-documents.md` 和 `reference-roles.md` 都写着「一张图承担两件事就拆成两个槽位」，`creator_markdown_check.py` 只拒绝路径和用途都相同的槽位。生产端 `production_tool.py` 却要求绑定路径唯一，job 绑定还必须逐项等于来源声明。结果是作者写出、检查器放行的声明，生产端永远 prepare 不过，退回作者后又按同一条规则写回来。
3. **响度没有容差**。剪辑的完成条件写的是「成片响度落在交付目标上」，`sound-and-subtitles.md` 又承认两遍归一化不保证达到目标，不达标就继续在外部处理。没有容差，-16.4 对 -16 也算不达标，智能体会反复渲染。
4. **成片审查没有判据**。`production_outputs` 和 `full_episode` 列在审查范围里，「只读对应资料」却没有给它们配资料。现有的处置表（保留、后期处理等）挂在 `project_calibration` 下，`REV-11` 又规定其他范围的 finding 只能写 `not_applicable`，而 `REV-02` 要求每条 finding 都有 required fix。

第 4 条先用合成案例跑了基线：12 段生成视频的观察记录，其中 8 段干净；3 段有小瑕疵，分别是一帧撕裂、台词晚 0.3 s、背景群演复制 0.5 s；1 段关键道具整段没出现。按原文执行，4 段都被送去重新生成，另有 3 条提示词修订，结论是一个笼统的 REVISE，没有说其余段可以先剪。

## Decision

- **续接**：保留第 15 步的默认和接力优于独立生成的理由。新增一条：项目走内置路径、本集有续接链、生产档案还没有 `continuation_route` 时，视频提示词在交付报告里，或生产阶段遇到「待续接」段时，问创作者一次，二选一：
  - `independent_starts`：每段从自己的已接受起始帧生成。写明代价是后一段不再继承上一段实际生成的动作、节奏和声音。补救用分镜跨镜转场里「切点那一格由同一张已接受的图承载」的做法。
  - `relay_external`：保留续接，后续段在创作者自己的工具里提交。

  选择经路由技能已有的决策写入，记进 `creator_authority.production_profile.choices.continuation_route`。`project_tool.py` 的 `project_video_model_profile` 会把它带进 `status`，后续阶段读到就不再问。选独立起点等同于创作者明确要求独立重生成，按原有规则重新起链。
- **参考槽位**：一张图只占一个槽位，`用途` 写主要作用，第二个作用写进「控制」。两个作用分属两张图时才写两个槽位。`creator_markdown_check.py` 对同一定位符的第二个槽位报错，不论 `用途` 是否相同，错误信息给出合并写法。这条检查对 REF 路径和 PLAN 条目都生效。生产端代码不变。
- **响度**：`EDT-12`（craft_default）扩成：完成时报告实测整合响度和真峰。默认容差是距目标 ±1 LU，真峰不高于声明的上限；没有声明时，按内置归一化使用的 -1.5 dBTP。创作者可以在 `交付响度` 一行改写。外部处理一次后仍有小幅超出，就报告给创作者，不自行迭代。`edit_tool.py verify` 原来只报告数值、不与目标比较，所以不改代码。
- **成片审查**：新增 `short-drama-review/references/generated-media.md`，由 SKILL 的范围路由指向它。新增 `REV-15`（craft_default）：先逐段判断是否完成镜头职责，再把瑕疵分成剪掉、后期可修、保留、必须重出四类。单帧或不到一秒的故障、轻微音画偏移、背景群演短暂重复默认不阻断交付，创作者可以改。只有镜头没完成职责、剪辑也接不住时才判必须重出。结论分可交付、带备注交付、先修再交三种，修改清单只列必须重出的段，复审只读重出的段。必须重出之后选哪种处置，沿用项目校准的判据，不再复述一遍。`REV-11` 注明生成素材审查改用 `REV-15` 的四类。

同一份合成案例改后重跑：只有关键道具缺失的那 1 段要重出，另外 3 处交剪辑，其余 11 段直接进剪辑。基线和改后的记录都放在仓库外的工作区，没有提交。

## Alternatives considered

- **续接默认改成独立起点，续接改为可选**：最强的理由是内置路径马上就能跑通，不用多问一句。不用，因为接力在动作、表演和声音连续上确实更好；而且项目可能本来就用外部工具提交，那时默认独立会白白丢掉连续性。问一次的成本低，能保住创作者真正想要的路线。
- **让生产选择器支持绑定续接视频**：最强的理由是从根上消除缺口。不用，因为这要扩展来源声明语法、job schema 和 adapter 契约，属于另一项接口工作。本次只让当前的缺口有一个明确的出口。
- **让生产端接受一个绑定承担多个用途**：最强的理由是作者可以照旧写两个槽位。不用，因为 `reference_bindings`、供应商 role 映射和 prepare 的逐项比对都按「一个文件一次绑定」设计，改动面大；而一个槽位加上「控制」本来就能表达第二个作用，`reference-roles.md` 里一张角色板同时固定长相和造型的写法已经是这样。
- **在 `verify` 里加响度合格判定**：最强的理由是数值比较是确定性的工作。不用，因为 `verify` 目前只测量、不下结论，容差又可以由创作者改写。加判定等于新增一个解析契约，本次的问题靠写明默认容差就能解决。
- **把成片审查并进项目校准，直接放开 REV-11 的处置**：最强的理由是不用新增文件。不用，因为项目校准针对的是改提示词的诊断，前提是有绑定版本的观察记录；成片审查的首要问题是这段能不能交给剪辑，判据不同。

## Consequences

- 收益：内置路径遇到续接链时有了明确的二选一，选过一次就不再被拦住。作者、检查器和生产端对参考槽位的要求一致。剪辑完成有了可以停下的条件。成片审查不再把亚秒级噪声送去重新生成，修改清单有了边界。
- 代价：已有文档里同一路径写了两个槽位的，跨文档检查现在会报错，需要合并一次；CHANGELOG 写了升级步骤。选独立起点的项目，切点处的连续性会弱一些，要靠共享切点图补救。`REV-15` 的默认分类依赖观察记录的质量，观察漏掉的瑕疵仍然是未知。成片审查只用一份合成案例自检，同一个 agent 既写了指引又执行了审查，还需要独立 reviewer 实跑来验证。
