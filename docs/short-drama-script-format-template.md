# 短剧剧本格式模板：场景、动作和对白怎么分

一个项目先选定一种剧本格式，然后按同一套写法标出集数和场次，让看得见的动作单独成段，每句对白都写明说话人；音效、画面文字和连戏备注只在制作必须知道时才加。下面给出可复制的 Markdown 骨架和一段原创示例，也说明用 AI 整理旧稿后要对照原稿查什么。

## 先定格式，再填集名和场次

同一个项目只保留一份可编辑的剧本作为全剧唯一的剧情定稿。分镜、图片和视频提示词、制作清单都直接引用它，不在下游各自改写剧情。本仓库用的 Markdown 格式由五类行组成：

| 行 | 示例 | 作用 |
|---|---|---|
| 集标题 | `# EP001 【集名】` | 稳定的集 ID，改集名时 ID 不变 |
| 场景标题 | `## EP001-SC001 内 · 社区服务台 · 傍晚` | 场景 ID、内景或外景、地点，以及对拍摄有用的时段 |
| 动作 | `林遥把登记回执推回窗口。` | 观众能看见、演员能演出来的行为 |
| 对白 | `林遥：我五点前交过。` | 角色名在前，台词在后，说话人始终明确 |
| 制作标签 | `[画面文字] 登记时间：16:52` | 只记观众必须看清的画面文字或制作必需的信息 |

可复制的空白骨架，标签行按需选用，不要求全填：

```md
# EP001 【集名】

## EP001-SC001 内 · 地点 · 时间/天气

（可见、可表演的动作）

角色名（可选的表演提示）：台词

[OS] 角色名：同一场景里画外说话人的台词

[VO] 角色名：不在现场的主观声音或旁白叙述

[SFX] 会改变注意力、行动或剧情信息的声音

[画面文字] 显示位置：观众必须读清的准确文字

[连续性] 前文已建立、后面容易漏掉的状态

[转场] 有叙事作用的转场
```

场景标题里的空间写内、外或内外；时间和天气只在影响行动、表演或跨场连戏时才写。景别、镜头运动、焦段和视频生成参数不写进故事剧本，逐镜拍法另看[分镜脚本怎么写](short-drama-storyboard-script-template.md)。稳定的场次编号和统一标题方便下游分镜引用，本身不决定这场戏写得好不好。

## 把可见动作和角色对白分开写

动作段写正在发生、能演出来或看得见的事；动作重心、剧情信息或人物站位一变就另起一段。对白写成 `角色名（可选提示）：台词`。括号里的提示只写演员能做出来的具体动作选择（例如压低声音免得门外的人听见），不要堆砌愤怒、悲伤、激动这类抽象情绪词。

| 原写法 | 建议写法 | 原因 |
|---|---|---|
| `抽屉里的东西：一张回执。` | `抽屉半开，露出一张回执。` | 行首短语加冒号，容易被误判成角色台词 |
| `她很紧张地看着柜台。` | `她把回执压在手心，手指停在签名处。` | 用看得见的动作把情绪演出来 |
| `办事员：（叹气）你先等等。` | `办事员（把复印件收回文件夹）：你先等等。` | 括号提示给到和当下局面相关的具体动作 |

对白有没有张力，取决于说话人的目的、人物关系、潜台词和这场交锋改变了什么；本场目标和对手筹码在构思阶段就要定好，剧本格式只负责把定下来的剧情写清楚。

## 制作标签只标必需的信息

在本仓库的 Markdown 格式里，六个制作标签的用法如下：

| 标签 | 用于 | 不要用来 |
|---|---|---|
| `[OS]` | 同一场景中画外说话人的对白 | 代替明确的说话人姓名 |
| `[VO]` | 不在现场的主观心声或旁白叙述 | 偷懒替代本该拍成画面的可见动作 |
| `[SFX]` | 会改变人物注意、行动或剧情信息的声音 | 罗列无关紧要的全部环境底声 |
| `[画面文字]` | 观众必须读清的显示位置（如手机屏幕、回执单）和准确文字 | 重复普通的道具外观描写 |
| `[连续性]` | 后面容易漏掉、又影响剧情连贯的状态 | 把整套人物设定再抄一遍 |
| `[转场]` | 有明确叙事用意的转场衔接 | 提前写成完整的后期剪辑单 |

有些团队习惯用另一种片场制作稿格式：行首 `△` 写环境或空镜，`▲` 写人物动作，角色名后的 `OS` 常用来表示内心独白。同一个 `OS`，在那套片场制作稿格式里是内心独白，在上面的 Markdown 格式里则是画外对白。两套都能用，开稿前定好项目用哪一套，同一份剧本里不要混用；也不必把其中任何一套当成全行业唯一的标准。

## 原创示例：服务台复核登记时间

下面是一段为演示格式写的虚构片段，没有拍摄过：

```md
# EP001 【回执复核】

## EP001-SC001 内 · 社区服务台 · 傍晚

林遥把那张手写回执拍回窗口台面，食指点住右上角写的“18:10”。

林遥：看清楚，我是五点前交的材料，你给我写成六点过十分，存心卡我截止时间是吧？

[OS] 走廊里的同事：别吵了，系统后台的机打回执刚吐出来。

办事员转身从打印机扯下热敏回执，扫了一眼，递向林遥。

[画面文字] 机打回执首行：提交时间 16:52

[画面文字] 机打回执次行：补打时间 18:10

办事员把机打回执塞到林遥手里。

[连续性] 林遥右手攥着机打回执；那张手写回执仍摊在窗口台面上。
```

场景标题交代何时何地，动作行写看得见的行为，角色名锁定说话人；画外台词和画面文字只在推进剧情时出现，最后一行记下交接之后两张回执各在哪里。后面做分镜时如果要改动这些剧情细节，先回剧本改好，不要在分镜或提示词里悄悄改掉。

## 用 AI 整理旧剧本后，对照原稿复核

把原稿、选定的格式说明和角色名单一起交给 AI，只让它做排版与结构整理：标出集名和场头标题，拆开动作段与对白行，按规则补上必需的制作标签。格式没交代清楚、说话人不明或原文有歧义的地方，让它标成待确认，不要瞎猜。

复核时对照原稿重点查四件事：说话人有没有张冠李戴；动作和对白的先后顺序有没有乱；有没有把原稿的心理描写擅自改成 `[VO]` 或 `[OS]` 台词；场次、时间和物件交接有没有被多写或漏掉。格式整理完，仍需作者自己核对原意有没有走样。分集节奏和事件顺序在大纲阶段定，这一步只管把每场戏清清楚楚落到剧本纸面上。

## 用本仓库的 skill 怎么做

对应的 skill 是 [short-drama-write](../skills/short-drama-write/SKILL.md)，它按本仓库的 Markdown 格式编写或整理 `剧集/EP001/剧本.md`，也能直接读取上面提到的三角符号片场制作稿格式。在 Claude Code 里输入 `/short-drama-write`，在 Codex 里输入 `$short-drama-write`，整理旧稿时可以这样说：

> 按本项目的 Markdown 剧本格式整理我给的原稿，只整理集名与场头标题、可见动作、角色对白和必要的制作标签。严格按原稿和角色名单来，别自己加人物、加戏、改台词原意或乱补道具交接；OS/VO 含义或说话人拿不准的地方列出来问我，整理完顺手列一下改动点方便我核对。

## 常见问题

**△ 和 ▲ 是短剧剧本的固定行业标准吗？**

不是。它们是一部分团队常用的片场制作稿格式约定，本仓库的 Markdown 格式不用这组符号。开稿前选定一套格式，照那套符号规则写到底就行。

**剧本里的 OS 和 VO 有什么区别？**

看项目采用哪套格式。本仓库的 Markdown 格式里，`[OS]` 是同一场景里画外说话人的对白，`[VO]` 是不在现场的主观心声或旁白；三角符号片场格式则常把角色名后的 `OS` 当成内心独白。项目开头写明用哪一套就行，别在同一场戏里混用两套定义。

**剧本里要写景别、推拉摇移和焦段吗？**

本仓库的剧本格式把镜头语言留给分镜阶段，剧本只管场次划分、可见动作、角色对白和必要的制作提示。如果团队习惯在剧本里带机位提示，在项目约定里提前说清即可。

**AI 能直接把旧剧本转换成新格式吗？**

可以先让 AI 出一版格式整理稿，但一定要留着原稿逐项核对。说话人、动作先后、台词用字、时间和道具去向都可能在转换时走样，拿不准的地方由作者拍板，别让模型自己脑补。
