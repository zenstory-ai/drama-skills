# Agent Note: 九组生成对照的落地：逐切关键帧、近景面部识别板、首尾帧补前序、站位锚点要在地点图里看得见

Status: implemented

## Problem

技能里有几处写法没有用真实生成核对过，或者根本没有写：

- Seedance 2.5 多镜容器只有一句「不自动保证跨镜一致性」，依据是一组只挂一张起始帧的对照，没有说每切挂自己的关键帧会怎样。H3 有「多镜容器：每切一张关键帧」小节，Wan 3.0 有一段讲同一做法，2.5 没有。
- H3 的近景说话镜没有起始帧、身份槽只挂全身身份板时，脸会漂。`$short-drama-image-prompts` 早就定义了面部识别板，但分镜和视频提示词都没说什么时候挂它、两张图怎么绑到同一个主体。
- 要在已接受片段前补一段前序时，Seedance 2.5 方言只说「动作要无缝接下去时优先用延长」，agent 照做会得到接缝硬切、顺序颠倒的成片。
- 站位规则（分镜 `SHT-30`、视频提示词「空间连续」）要求按固定锚点写，但从没检查这个锚点在挂的地点图里有没有；地点板又只保留一至三个强锚点，分镜点名的锚点很容易不在图里。

2026-11-01 用 Seedance 2.5 与 H3 跑了九组对照，每组先用现行写法生成作基线。画内招牌文字一组的基线已在天花板，候选两臂没有生成；三人同框一组的基线也在天花板，两条候选照常跑完作确认。片段抽帧、打乱并隐去所属写法后由同一个模型盲评，另测 NCC、切点等指标。完整数字在 `evaluations/model-behavior-probes.md`。

## Decision

四组候选写法胜出，落成下面四处改动；每处的证据只写在规则所在的文档里。

### Seedance 2.5 per-cut keyframe container

`seedance-2.5.md`「生成与参考」新增「多镜容器：每切一张关键帧」小节，结构与 H3 的同名小节一致：把相邻镜头装进一个容器是 `taste_option`，默认仍逐镜生成；选了它就按 `craft_default` 写——每个成员镜头都有已接受的起始帧，关键帧按切序排在参考清单前面，第一行写对齐句，各时间段写「以 @图片N 为画面」。正文记下它换不来的四件事：参考模式没有首帧位、开场不锁定（要接上一段真实尾帧仍逐镜用 `first_frame`）；切点仍偏早；台词可能溢进旁人的无声反应镜，生成后回听；紧贴关键帧时，反应镜容易停在关键帧画的静态。原来那句「一组对照没有改善……」改成只说「不自动保证跨镜一致性」并指向新小节，对照数字只在新小节里讲一次。不设切点误差或 NCC 门槛。H3 容器的决定见 [2026-09-26-model-probe-round](../testing/2026-09-26-model-probe-round.md)。

### H3 close-up face board

`minimax-h3.md`「每张图带什么、不带什么」新增一段 `craft_default`：脸占画面大块、没有起始帧锚住脸、身份槽只有全身板时，给同一角色再挂一张同一 Look 的面部识别板作第二个 `用途：身份` 槽，`subject_definitions` 把两张绑到同一个主体，`retention_analysis` 写明哪张管五官、哪张管体态与服装。小样本数字和「两种挂法都把人拍老，面部板不能代替生成后比脸」只写在 `minimax-h3.md` 这一段。分镜 SKILL 的「输入参考图」加一句，条件与 H3 这条相同（本镜没有 `用途：起始帧` 锚住脸、身份只有全身板，且目标方言收第二个身份槽）：这类镜头可再挂面部识别板，缺板按第 6 步的缺板做法点名。图片提示词 `character-and-look.md` 给面部识别板补一句：与身份板从同一张已接受身份锚点出图、同一 Look。

### Seedance 2.5 prequel via first/last frame

`seedance-2.5.md` 的 `extend` 条目末尾加一条 `craft_default`：延长只往后接，正文写「之前」也没用；要在已接受片段前补前序，用首尾帧，把原片第 0 帧作 `用途：结束帧`，拼接时去掉重复的末帧，再检查接缝处动作是否骤停、电平是否突降。这条只写在 `extend` 条目，「两端都锚」不重复；把延长生成的新段裁出来放到原片前的补救做法不写进技能。

### Blocking anchors visible in the location image

`production-prompt-grammar.md`「空间连续」加一条 `craft_default`：挂了地点图时，锚点选这张图在本观察面里看得见的固定物；一组实测里点名图里没有的大件，模型每次补出不同的一件，常挡住原有家具，甚至改掉房间格局。看不见就换锚点或换方位变体，都不行就回上游记 `creator_decision_needed`；锚点在图里也要生成后对照验收。证据只写在这一条，自检清单加一问。分镜这一侧在 `SHT-30` 第一条与 `stage-contract.md` 的 SHT-30 行写明锚点从哪里选：锚点从《视觉设定.md》该地点已记下的固定物里选，需要条目里没有的东西时点名、建议 `$short-drama-assets` 补，不自行添进场景。站位两层写法的原决定见 [2026-10-20-scene-blocking-and-camera-terms](2026-10-20-scene-blocking-and-camera-terms.md)。

### Probe-only rows

其余五组只在 `evaluations/model-behavior-probes.md` 追加观察行，技能正文不动：三人同框单人说话、画内招牌文字是否被念出两组的基线已在天花板；打戏头尾没人动的时间、围攻中等待的对手、运动参考只取节奏三组的候选都不如现行写法。后三组与打戏决定有关的事实补进 [2026-10-29-fight-craft](2026-10-29-fight-craft.md)。

## Alternatives considered

- **Seedance 2.5 把逐切关键帧容器设为默认**。最强理由：生成次数降到三分之一，3 次里 2 次盲评追平单独生成再剪接的上限。不用：参考模式没有首帧位，开场接不上一段真实尾帧；一处失败要重出整组；逐镜生成还能单镜重跑、单镜审查。
- **Seedance 2.5 容器继续只在首尾帧模式挂关键帧 1**。最强理由：开场与关键帧几乎完全一致，男方的反应演得更足（3 次都睁大眼，1 次明显放低杯子）。不用：第 2、3 切换了背景、男方脸型漂移，盲评 3/3/3 对 4/5/5。
- **面部识别板写成所有近景的必挂项**。最强理由：两个角色的盲评前两名都是加面部板的片段。不用：只测了 H3 上无起始帧的夜景近景这一种镜头，第二张图和绑定文字同时变化，还占一个参考槽；带起始帧的近景脸已经有锚。
- **面部识别板只在分镜里写，不改图片提示词**。最强理由：改动最少。不用：板子是图片提示词出的，不写明从同一身份锚点出图，两张身份图可能是两张脸，第二个身份槽反而制造冲突。
- **补前序改用裁剪延长段**。最强理由：额外加跑的这一组 3/3 盲评 5/5，比首尾帧的 4/5 还高。不用：它不在对照设计内，是事后加跑的；能成立靠的是延长模型看过原片、又被要求停在原片首个姿态，返回的码率还明显降低。
- **视频提示词遇到图里没有的锚点时，在正文里把它描述出来让模型补**。最强理由：不打断流程，分镜写什么就生成什么。不用：实测三次补出三个不同的书架，同一场多镜接不上，其中两次还挡住了图里原有的沙发。
- **在 `SHT-30` 里直接要求锚点必须出现在地点板上**。最强理由：从源头堵住。不用：分镜写站位时地点板可能还没出，板子也只画一个观察面；分镜能保证的是锚点来自地点条目，看不看得见在挂图那一步核对。

## Consequences

- **收益**：Seedance 2.5 有了与 H3、Wan 3.0 对齐的逐切关键帧写法，并写明它换不来什么；近景身份有了第二张图的挂法和出图来源；补前序不再误用延长、做出顺序颠倒的成片；站位锚点由分镜从地点条目已有的固定物里选，挂图时再核对一次图里看不看得见。
- **代价与局限**：落地的四组每个条件只跑 3 次、一个场景，盲评由同一个模型判，结论是「这一组里更好」，不是成功率。逐切容器的音频未转写，台词可能压进静默反应镜；面部识别板没解决夜景近景把人拍老；首尾帧补出的前序在接缝处仍有动作骤停、电平下降；锚点只测了一个房间、一个大件锚点。分镜多了一类需要点名的缺口（地点条目里没有的锚点），近景镜头多占一个参考槽。
