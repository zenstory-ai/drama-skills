# Seedance 2.5 提示词方言

只在目标档案明确写 `target_video_model: seedance-2.5` 时使用。推荐档案：

```json
{
  "target_video_model": "seedance-2.5",
  "video_prompt_dialect": "seedance-2.5",
  "video_prompt_language": "zh-CN",
  "native_duration_seconds": {"min": 4, "max": 30},
  "supported_generation_modes": ["text", "reference", "edit", "extend"],
  "audio_generation": "same_pass"
}
```

## 生成与参考

- 单镜按“主体 + 动作 + 场景 + 光色 + 运镜 + 风格 + 约束”写清动作先后与触发；多镜或长叙事按 `镜头 1 [0:00–0:03]：` 写不重叠、无缝衔接的时间段（终点等于总时长，时间戳仍有生成偏差，不作音节同步保证）。
- 每次提及素材重复绑定具体职责（`人物 @图片1`、`@视频1 的表演节奏`），多镜容器共用一份参考清单并重映射 `@图片N`。

### 多镜容器：每切一张关键帧

**`taste_option`**：相邻镜头可装进同一次参考模式生成，每切挂各自的已接受关键帧；默认仍逐镜生成。
**`craft_default`**：采用时须满足：
- 每个成员镜头都有已接受起始帧图片（缺一张即逐镜生成）；成员资格与容器算术按[交付形态](delivery-profile.md)记账，各切关键帧排在参考清单最前，共用身份/地点图排在后面。
- 正文首行写对齐句：`@图片1、@图片2、@图片3 依次是镜头 1、镜头 2、镜头 3 的画面`，各段写 `镜头 2 [0:03–0:06]：以 @图片2 为画面，……`。
- **容器边界**：每切挂关键帧的第 2、3 切构图与身份显著优于只挂首张，但有四点限制：① 参考模式无首帧位，开场不严格锁定（需接上一段真实尾帧时改用 `first_frame` 逐镜生成）；② 切点常偏早，需按实际切点剪辑；③ 台词可能溢入相邻无声反应镜，生成后须回听；④ 反应镜易停在关键帧静止态，需明显变化时把关键状态画进关键帧或拆出单生。

### 反应镜：保留可见反应链（`craft_default`）

按“触发 → 人物处理 → 当前景别可读的可见反应 → 落点”展开可见反应链，不只写抽象情绪词，也不套用 H3 的“情绪点名 + 两处泄露 + 1.5 秒内落下”配方。

### 两端都锚：`用途：起始帧` 与 `用途：结束帧`

- `first_frame` 与 `last_frame` 各收一张图，各自占用一个连续的 `@图片N` 序号（不跳号）；尾帧生产入口见 `$short-drama-storyboard` 的“首尾成对”，未提供尾帧时在正文写明终点。
- 锁开场构图须用 `first_frame`（在参考模式里写“@图片1 是开场画面”无法锁住首帧构图）。首尾帧与其他参考能否混用按目标接口核对。

### 音色参考

接口支持 `reference_audio` 时，在本镜写一行 `参考音频`（单独字段，不混入 `输入参考图`），正文按 `顺序` 写“沈一舟说话时音色参考 @音频1”；绑本句合成音时模型仍会重新发声而非原样播放，生成后须逐镜回听。

## 编辑与延长（`任务类型`）

提示词意图须与 `omni_reference_task_type` 一致（不一致会被 2.5 语义复判报错），目标模型为 2.5 时在 `MOTION-...` 的 `生成方式` 后加一行 `- 任务类型：reference | edit | extend`：

| 字段 | 回答什么 | 取值 | 决定方式 |
|---|---|---|---|
| `生成方式` | 本镜是否送图 | `文生视频` / `图生视频` | 由「输入参考图」是否为空机械推出（`creator_markdown_check.py` 核对） |
| `任务类型` | 参考、编辑或延长 | `reference` / `edit` / `extend` | 创作决定，不从关键词猜测（非 2.5 方言不写此行） |

- `reference`：基于素材生成新视频，写明具体借用职责。
- `edit`：点名 `@视频1` 写“保留 A、B，只修改 C”（API 要求 `ratio: adaptive`、`duration: -1`，基本保持源片时长；换更长对白须先核对源片发声窗口）。
- `extend`：写“在 @视频1 的基础上续写 N 秒”并从实际终点写唯一动作与新终点（API 要求 `ratio: adaptive`；可另绑实际尾帧为 `@图片1` 锚定新段开场状态）。同一连续时空第二段起默认走 `extend`（真实输入未就绪时标“待续接、不可提交”，不绑 `@视频1`/`@图片1`）。
- **`craft_default`（向前补拍）**：`extend` 只接在 `@视频1` 之后（不支持在 `@视频1` 之前续写）。需在已接受片段前补拍时，改用首尾帧：抽原片第 0 帧绑 `用途：结束帧`，前序起点绑 `用途：起始帧`，拼接时去掉重复末帧并检查接缝动作与电平。

## 对白、声音与文字

- 可辨对白写进完整声音时间线的 `{角色用中文说：“逐字台词”}`（单镜只出现一次，中文不加语言前缀，非中文标明语言；视觉时间线只写口型同步）；音效写 `<声音>`，音乐写 `（音乐）`。上游已排除外语前导、语气词、额外人声或重复时，在声音时间线末尾写一次“对白直接从指定中文首字开始；不生成外语前导、语气词、额外人声或重复对白”。
- 显式开启字幕才用 `【字幕】`；默认禁字幕写“全程无字幕、无对白文字叠加”且不含 `【】`。
- **手机通知防浮层**：2.5 常把手机通知画成画面浮层气泡或乱码计数器，须明写“通知只在手机屏幕里亮起，画面上不出现浮层”，需要显示的数字交剪辑叠加。

## 时长

手动整数时长为 4–30 秒，对白/VO/OS 按 [performance-action-timing.md](performance-action-timing.md) 预算（`extend` 只预算新增片段）。普通生成/参考支持 `duration: -1`（4–30 秒自适应），固定时长交付仍显式传正整数。API 返回的 `duration` 为按帧数向下取整的近似秒数，回测须实测媒体时长与尾音完整性。
