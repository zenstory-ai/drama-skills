# Agent Note: 核心创作路由与五文档核对保持一致

Status: implemented

## Problem

逐份五步精修核心技能 18 份文档时，发现几处文案与现有实现或已接受契约不一致：画面代称被写成中文名始终自动加入，非中文正文的代称检查被限定到已被镜头引用的人物；实际解析只在未声明代称时回退条目名，检查覆盖所有人物。完整五文档检查器要求五份文件都存在，说明却要求每次局部创作后直接运行，容易把合法的独立阶段误报成缺上游。

Look Development 参考仍以 `purpose: lookdev_frame`、`role`、`must_not_control` 指导当前落盘，参考图说明未在首次定义时区分 REF 与 PLAN，制作形态说明又同时要求每段仅一张卡和混合形态取两张卡。形态卡中的部分绝对表述还会越过已有身份、连续性或剧本声音权限，例如无条件省略不变层、二维身份层永不重画、接触一律有声。补拍指引还会引导同一镜头建立多个正式 MOTION，违反检查器对 SHOT/MOTION 一对一的现有要求。

既有决定见[五份创作者文档](../architecture/2026-08-22-creator-first-five-documents.md)、[规则四级分级](../architecture/2026-07-16-rule-tiers-and-script-boundary.md)与[声音参考绑定](../feature/2026-09-28-voice-reference-binding.md)。本次沿用这些决定，不改变脚本行为或规则等级。

## Decision

按 `creator_markdown_check.py` 的实际解析说明代称和完整检查条件；局部任务只核对当前已有文档，不为运行检查补造文件。核心工作流明确旧项目只读留存、新根目录逐集转移确认，Look Development 与参考绑定改用当前 Markdown 概念。制作形态按普通单形态与明确分层的混合形态分别说明，保留专业方法并注明身份、连续性与剧本事实的优先权。补拍/替代比较先记录在当前条目的普通说明中；独立补拍先回分镜落实 SHOT，再建立匹配 MOTION，正式正文仍一镜一条。导出说明补齐实现已包含的剪辑单，节奏档案值明确不携带自身 status。

## Alternatives considered

- **只润色措辞，保留旧字段与检查入口**：修改少，旧结构化读者也熟悉。未采用：当前入口会继续引导 agent 建立第二套创作真相，或把脚本的缺文件报告当成局部请求失败。
- **修改检查器兼容文案**：可以让字面说明成立。未采用：本轮范围是文档精修，既有实现与契约已经明确，文档应准确描述它们。

## Consequences

- **收益**：核心路由、文档格式、参考职责与当前脚本事实一致，独立阶段与混合形态的边界更清楚。
- **代价**：结构检查仍不能证明语义覆盖与画面效果；形态方法仍需按项目选择，不能由固定配额代替判断。
- **验证**：18 份文档各五步、共 90 项证据已记入本轮覆盖记录；27 个既有 fenced blocks、所有引用块、配对例句、四级分级表和冲突优先级保持原文。核心 17 项 self-test 与 8 项既有定点测试通过；临时目录复现未声明/显式/无三种代称、未引用人物的非中文检查、局部文档缺文件返回，以及同 SHOT 多 MOTION 拒绝。全量与浏览器检查由主任务统一执行。

最终复核：独立review修复形态卡范围矛盾：单一形态读一张，已声明混合形态按层读取所需两张，继续避免预加载全部。
