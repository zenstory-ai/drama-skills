# 短剧剧本格式模板：场景、动作和对白怎么分

一个项目先选定一种剧本格式，然后按同一套写法标出集数和场次，让看得见的动作单独成段，每句对白都写明说话人；声音、屏幕文字和连续性标签只在制作必须知道时才加。下面给出可复制的 Markdown 骨架和一段原创示例，也说明用 AI 整理旧稿后要对照原稿查什么。

## 先定格式，再填集名和场次

同一个项目只保留一份可编辑的剧本作为文字事实的来源。分镜、图片和视频提示词、制作清单都引用它，不各自改写剧情。本仓库用的 Markdown 格式由五类行组成：

| 行 | 示例 | 作用 |
|---|---|---|
| 集标题 | `# EP001 【集名】` | 稳定的集 ID，改集名时 ID 不变 |
| 场景标题 | `## EP001-SC001 内 · 社区服务台 · 傍晚` | 场景 ID、内或外、地点，以及对后续有用的时段 |
| 动作 | `林遥把登记回执推回窗口。` | 观众能看见、演员能执行的行为 |
| 对白 | `林遥：我五点前交过。` | 角色名在前，台词在后，说话人始终明确 |
| 制作标签 | `[画面文字] 登记时间：16:52` | 只记观众必须读到的文字或制作必需的事实 |

可复制的空白骨架，标签行按需选用，不要求全填：

```md
# EP001 【集名】

## EP001-SC001 内 · 地点 · 时间/天气

（可见、可表演的动作）

角色名（可选的表演提示）：台词

[OS] 角色名：同一场景里画外说话人的台词

[VO] 角色名：不在现场的主观声音或叙述

[SFX] 会改变注意力、行动或信息的声音

[画面文字] 载体：观众必须读清的准确文字

[连续性] 前文已建立、后面容易丢的状态

[转场] 有叙事作用的转场
```

场景标题里的空间写内、外或内外；时间和天气只在影响行动、表演或连续性时才写。景别、镜头运动、焦段和视频生成参数不写进故事剧本，逐镜方案另看[分镜脚本怎么写](short-drama-storyboard-script-template.md)。稳定的 ID 和能解析的标题方便下游引用，但不说明这场戏写得好不好。

## 把可见动作和角色对白分开写

动作段写正在发生、能演出来或看得见的事；动作焦点、信息或空间关系一变就另起一段。对白写成角色名（可选提示）：台词。提示只写一个演员能执行的选择，例如压低声音免得门外的人听见，不要堆愤怒、悲伤、激动这类同义情绪词。

| 原写法 | 建议写法 | 原因 |
|---|---|---|
| `抽屉里的东西：一张回执。` | `抽屉半开，露出一张回执。` | 行首短语加冒号，容易被当成角色台词 |
| `她很紧张地看着柜台。` | `她把回执压在手心，手指停在签名处。` | 让能演的动作承担情绪 |
| `办事员：（叹气）你先等等。` | `办事员（把复印件收回文件夹）：你先等等。` | 提示写的是和当下行动有关的做法 |

对白有没有张力，取决于说话人的目的、关系、潜台词和这场谈话改变了什么；场景目标和对手筹码是剧作层面的决定。格式只负责把已经定下的故事事实写清楚。

## 制作标签只标必需的信息

在本仓库的 Markdown 格式里，六个标签的用法如下：

| 标签 | 用于 | 不要用来 |
|---|---|---|
| `[OS]` | 同一场景中画外说话人的对白 | 代替明确的说话人 |
| `[VO]` | 不在现场的主观声音或叙述 | 藏起本该写成动作的可见行为 |
| `[SFX]` | 会改变注意力、行动或信息的声音 | 罗列全部环境声 |
| `[画面文字]` | 观众必须读清的载体和准确文字 | 重复一般的道具描述 |
| `[连续性]` | 后面容易丢、又影响故事的状态 | 复制整套人物设定 |
| `[转场]` | 有叙事作用的转场要求 | 写成完整的剪辑方案 |

有些团队用另一种生产格式：行首 `△` 写环境或空镜，`▲` 写人物动作，角色名后的 `OS` 常用来表示内心声音。同一个 `OS`，在那套格式里是内心独白，在上面的 Markdown 格式里是画外对白。两套都能用，开稿前写明项目用哪一套，同一份剧本里不要混用；也不要把其中任何一套说成全行业统一的标准。

## 原创示例：服务台复核登记时间

下面是一段为演示格式写的虚构片段，没有拍摄过：

```md
# EP001 【回执复核】

## EP001-SC001 内 · 社区服务台 · 傍晚

林遥把那张手写回执拍回窗口台面，食指点住右上角写的“18:10”。

林遥：看清楚，我是五点前交的材料，你给我写成六点过十分，存心卡我截止时间是吧？

[OS] 走廊里的同事：别吵了，系统后台的机打回执刚吐出来。

办事员转身从打印机扯下热敏回执，扫了一眼，递向林遥。

[画面文字] 提交时间：16:52

[画面文字] 补打时间：18:10

办事员把机打回执塞到林遥手里。

[连续性] 林遥右手攥着机打回执；那张手写回执仍摊在窗口台面上。
```

场景标题交代何时何地，动作行写看得见的行为，角色名锁定说话人；画外台词和屏幕文字只在故事需要时出现，最后一行记下交接之后两张回执各在哪里。后面做分镜时如果要改这些场景事实，先回剧本改，不要在分镜或提示词里悄悄改掉。

## 用 AI 整理旧剧本后，对照原稿复核

把原稿、选定的格式说明和角色名单一起交给 AI，只让它做结构整理：标出集和场景标题，分开动作与对白，按选定规则加必需的标签。格式没说明、说话人不明或原文有歧义的地方，让它列为待确认，不要猜。

复核时对照原稿看四件事：说话人有没有被换掉；动作和对白的先后有没有变；标签有没有把角色的内心活动自动改成 VO 或 OS；场景、时间和物件交接有没有被补写或删掉。格式整理不能代替作者确认语义有没有变。分集节奏和事件顺序在大纲阶段决定，这一步只检查每场戏落到剧本文字后是否清楚。

## 用本仓库的 skill 怎么做

对应的 skill 是 [short-drama-write](../skills/short-drama-write/SKILL.md)，它按本仓库的 Markdown 格式写或整理 `剧集/EP001/剧本.md`，也能识别上面提到的三角符号格式。在 Claude Code 里输入 `/short-drama-write`，在 Codex 里输入 `$short-drama-write`，整理旧稿时可以这样说：

> 按本项目的 Markdown 剧本格式整理我给的原稿，只处理集和场景标题、可见动作、角色对白和我要求的制作标签。只用原文和角色名单，不新增人物、对白、动作、因果、时间、声源或物件交接，不改台词意思。OS/VO 的含义、说话人或格式拿不准的地方标为待确认。输出整理稿和逐项差异，供我复核。

## 常见问题

**△ 和 ▲ 是短剧剧本的固定行业标准吗？**

不是。它们是一部分团队的生产格式约定，本仓库的 Markdown 格式不用这组符号。开稿前选定格式，再照那套格式的符号含义写。

**剧本里的 OS 和 VO 有什么区别？**

看所用的格式。本仓库的 Markdown 格式里，`[OS]` 是同一场景里画外的对白，`[VO]` 是不在现场的主观声音或叙述；三角符号格式常把角色名后的 `OS` 当内心声音。项目写明用哪一套即可，不要在一场戏里混用两套定义。

**剧本里要写景别、推拉摇移和焦段吗？**

这套格式把它们留给分镜或摄影方案，剧本只保留场景边界、可见动作、对白和必要的制作信息。团队用别的格式，就在项目约定里先写明。

**AI 能直接把旧剧本转换成新格式吗？**

可以先让 AI 出一版整理稿，但要保留原稿逐项比对。说话人、动作顺序、对白、时间和物件状态都可能在整理时被改动，拿不准的交给作者确认，不让模型自己补全。
