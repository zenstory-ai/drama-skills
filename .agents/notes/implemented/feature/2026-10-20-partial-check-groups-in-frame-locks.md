# Agent Note: 跨文档检查支持局部核对、交付分组与「入画」锁范围

Status: implemented

## Problem

v0.9.1 发布前的主工作流实跑（新项目只给原著，分阶段由独立 agent 接续）暴露了三处检查盲区：

- `creator_markdown_check.py` 缺任一文档就直接返回“缺少创作文档”。资产、图片提示词、分镜三个阶段的产物都要等视频提示词写完才第一次被机械核对；分镜阶段的 agent 只能补桩文件才查出两处来源引文覆盖错误（SHT-26）。`creator-documents.md` 却写着“局部任务只核对当前已有文档”，与脚本行为不符。
- 多镜容器真正提交给执行端的“组正文”没有落点也没有检查。实跑里在组正文写入剧本没有的台词，检查器仍报 OK；锁面、引文都碰不到它。`delivery-profile.md` 只说要写“交付分组”章节，没有可解析格式。
- 连续性锁的镜头范围只能写 `全集` 或 `SHOT-...` 列表，而锁由资产阶段写，那时还没有镜头 ID；写 `全集` 又会把服装锁面压给不出现这个人的镜头。实跑只能写成不受校验的“拟定锁面”，也没有文档规定分镜后由谁回来转正。

另外 `_sections` 把最后一个 `SHOT`/`MOTION` 一直切到文件末尾，写在末尾的报告里的 `- 时长：` 会被读成最后一镜的重复字段。

## Decision

- 检查器新增 `--partial`（`validate_episode(..., partial=True)`）：只核对已有文档，需要缺失文档的规则跳过，既不报通过也不报失败；五份都缺时报“没有可核对的创作文档”。默认仍要求五份齐备，完整交付的判定不变。CLI 在局部通过时输出 `OK（局部）` 并列出未核对的文档。五个阶段技能与 `creator-documents.md` 改为每写完一份就带 `--partial` 核对。
- `视频提示词.md` 新增 `## GROUP-<EP>-<n> · 名称` 条目：`成员`、`时长`、`理由` 与 `### 可复制提示词`。检查器核对成员是已有 MOTION、按分镜顺序相邻、不跨场次、一个镜头只进一个分组（VID-15）、时长等于成员之和（VID-13）、正文引文可在上游找到（VID-25），以及覆盖任一成员的锁面出现在组正文里。同一地理/资产链与蒙太奇判断仍归审查。检查器拆出 `validate_documents(texts, project_root, partial)`，`validate_episode` 只负责读文件；没有项目根时只跳过 REF 文件是否存在和项目提示词语言。创作台用同一个函数判定分组能否并入复制队列：检查器对分组本身、其成员 MOTION 或成员镜头报了任何问题，或有不点名的文档级问题（镜头与 MOTION 未一一对应、标题重复），就按逐镜显示并给出提示，绝不让坏分组藏起、打乱或替换提示词。并入的分组在队列里按顺序占一条，成员逐镜正文仍在镜头详情里；成员的搜索结果打开镜头详情，分镜不在时打开分组卡。设定视图把 `入画` 按「视觉依据」展开成实际镜头。内置生产工具仍只接受 `MOTION-*` 来源，分组正文由创作者复制到自己的生成工具，文档已写明。
- 连续性锁的镜头范围新增 `入画`：展开为「视觉依据」列出该锁所在条目的所有镜头，所以锁必须写在某个人物、造型、地点或道具条目下。服装这类只在部分景别看得见的事实写在 `造型` 条目下。资产阶段即可写出最终锁行，不再需要转正。
- `_sections` 的条目在下一个任意 `## ` 标题处结束。

## Alternatives considered

- **局部模式作为默认**：每次运行都能查到点东西。未采用：完整交付的判定会悄悄放宽，缺一份文档也能得到 OK；保持默认严格、局部显式开启。
- **为每个阶段写单独的小检查器**：各阶段只看自己的文档。未采用：跨文档规则正是这些阶段之间的交接，拆开后同一条规则要实现多次；同一个检查器按已有文档裁剪更一致。
- **锁范围用人物名列表或景别规则**（如“除特写外”）：表达力更强。未采用：景别要从自然语言里猜，不是确定性判断；「视觉依据」已经是“这一格里有什么”的唯一记录，复用它最直接。
- **组正文检查 Seedance 整数秒**：实跑里 8 组因半秒成员时长无法提交。未采用：整数秒是目标模型的约束，属于方言，不是所有执行端都有；文档里写明，检查器只做与模型无关的算术。

## Consequences

- **收益**：资产、图片提示词、分镜阶段写完就能拿到机械反馈；真正提交的组正文受到与逐镜正文相同的引文与锁面约束；锁在资产阶段一次写对。
- **代价**：`--partial` 跳过的规则不会提醒，使用者要看清输出里的“未核对”列表；`入画` 让「视觉依据」多了一层后果，分镜列错条目会让锁面要求跟着错；`GROUP` 条目让视频提示词多一种结构，逐镜与组正文仍有重复。
