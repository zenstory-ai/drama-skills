# Agent Note: 创作台对标主流 AI 短剧 / 漫剧工具后的改进提案

Status: proposed（第 1–3 项已落地，见 [实现笔记](../../implemented/feature/2026-09-26-dashboard-progress-first-screen-copy.md)；第 4–7 项仍是提案）

## Problem

创作台（见 [单页创作台](../../implemented/feature/2026-08-06-single-page-creator-dashboard.md)、[五文档](../../implemented/architecture/2026-08-22-creator-first-five-documents.md)）把五份 Markdown 原样渲染成一列正文。用 `examples/creator-first/EP001` 加 8 集、3 张出图和一份审查意见搭样例项目，在 1440×900 与 375×812 实测，并对照主流工具，发现两类问题。

**现有缺陷（实测）：**

1. **正文不在首屏**：只要项目有媒体，1440×900 下阅读区顶端在 995px，375 宽下在 2065px；这违背「始终可见的当前正文」。手机上读到一半想换文档，要往回滚约两屏才能碰到目录。
2. **分集进度判断错了**：`episodePresentation` 只认旧的 `shots.jsonl` / `keyframes.jsonl`，不认 `分镜.md` 和 `视觉设定.md`。
   - 已有剧本、视觉设定和分镜的一集仍显示「剧本就绪 · 可继续做资产与分镜」。
   - 只有 `图片提示词.md` 的一集显示「提示词就绪 · 可在 skill 中确认投产」。
   - 所以下一步建议是错的。
3. **第 7 集起不显示**：`slice(0, 6)` 截断了分集条，标题写「8 集可浏览」，却只出 6 张卡，也没有「更多」入口。
4. **ID 被改写**：`fileLabel` 把文件名转成小写，并把连字符换成空格，于是 `SHOT-EP001-001.png` 显示成「shot ep001 001.png」，`EP001-审查.md` 显示成「ep001 审查」。审查意见还被放进「全剧」组，没跟本集放在一起，分集卡上也看不到「有审查意见」。
5. **Markdown 渲染器不认表格、链接和图片**：剧本里的对白、`[VO]` 与动作都排成同样的段落；可复制提示词没有复制按钮，只能手选。

**主流工具有而我们缺的**（多数来自评测文章、教程和开源工具的 README、截图与前端源码；「未证实」表示只有二手来源）：

- **云端 AI 漫剧平台**（几家国内平台）：
  - 画布或时间轴上剧本与分镜并排，分镜卡可拖动排序、右键重新生成。
  - 资产库分人物、场景、道具，人物带表情和状态变体。
  - 逐镜按「镜号 / 时长 / 景别 / 画面 / 台词 / 运镜」组织；分镜宫格带逐镜时长与台词；整集审阅后再批量出视频。
  - 有的宣称有 agent 标出穿帮与服装错误，UI 形态未证实。
- **开源桌面 / 本地工作台**：
  - 分集卡带进度：状态、成片进度（如 20/20）、过期产物数、成本、「阶段 3/4」。
  - 镜头列表：左侧镜头列表加右侧详情，列表行有缩略图、镜号、时长和三到四态状态徽章；部分有逐镜版本历史。
  - 画布派：画布加助手，付费生成前弹出计划卡和报价确认。
  - 多数本地优先，部分用本地数据库。
- **另一套开源短剧 skill 的离线 HTML 报告**：
  - 剧本报告：KPI 带之后先放「时长仪表」，每集一条「台词 / 动作 / 目标区间」轨道；台词排成三列网格：说话人加表演提示、台词、复制。
  - 分镜报告：「节奏带」按时长比例画每镜，按景别深浅着色；段卡依次是主分镜图、子分镜缩略条和逐镜行（起始秒 · 时长 · 景别 · 人物道具 chips）。缺图就显示占位，原则是「不猜、不骗」。
  - 角色报告：左栏角色列表可搜索，右侧是设定图、信息卡和提示词复制。

所有工具都有的：逐镜的结构化一览（时长、景别、台词、缩略图）、总时长对照目标、资产卡、一键复制提示词。我们的数据其实都在 `分镜.md` 与 `视觉设定.md` 里（`## SHOT-… · 标题` 加 `- 时长：`、`- 景别/机位：` 等字段，见 `skills/short-drama/references/creator-documents.md`），只是没有按结构展示。

## Proposal

按「创作者价值 ÷ 实现成本」排序。原则不变：仍是单页，结构化视图只是同一篇正文顶部的摘要，不是另一个模式或标签页；解析失败时静默回退到现在的正文渲染；只读，不加生产动作。

1. **修正分集进度与标签**（价值高，成本很低）——已落地
   - 改动：
     - `episodePresentation` 按五文档与 `制作成果/` 推导，每张分集卡显示五个小点（剧本、视觉、分镜、图片、视频）加媒体数。下一步只根据「缺的第一份文档」给出。
     - 分集条去掉 `slice(0, 6)`：超过 6 集时改成紧凑网格，或者横向滚动。
     - `fileLabel` 对非固定名文件保留原大小写，只去掉扩展名。
     - `审查/<EP>-审查.md` 归入对应的分集组，并在分集卡上显示「有审查意见」。
   - 文件：`skills/short-drama/assets/dashboard/app.js`、`styles.css`。
   - 测试：
     - 扩展 `tests/test_dashboard_server.py` 里现有的 node 用例（`test_frontend_overview_summarizes_without_owning_production`），断言上述几种文档组合各自给出的标签。
     - 新增一例 8 集项目，断言 8 张卡都在。
2. **让正文回到首屏**（价值高，成本低）——已落地
   - 改动：
     - 概览收成一行紧凑带：标题、状态、四个数字、分集小卡横排。
     - 「已有制作成果」画廊移到概览带里的一个折叠行，或者移到正文之后。
     - 窄屏在阅读区上方加一条吸顶小栏，显示当前文档名和一个「目录」按钮，点了滚回目录。它不是抽屉或标签。
   - 文件：`index.html`、`styles.css`、`app.js`。
   - 测试：在 `tests/test_dashboard_browser.py` 新增用例。在带媒体、8 集的项目里，1440×900 和 375×812 两种尺寸下，`#documentPane` 顶端都小于视口高度（手机上以「阅读当前剧本」之后的位置为准），且没有横向滚动。
3. **可复制提示词加复制按钮**（价值高，成本很低）——已落地
   - 改动：`### 可复制提示词` 与 `### 冻结关键帧提示词` 下面的引用块和围栏代码块，右上角加「复制」按钮。复制内容就是渲染前的原文行，多行引用按换行拼接。只写剪贴板，不连任何外部服务。
   - 文件：`app.js`（`renderMarkdown`）、`styles.css`。
   - 测试：
     - node 断言按钮携带的文本与源文件逐字一致，含 `examples/creator-first/EP001/视频提示词.md` 的多行引用。
     - Playwright 授予剪贴板权限，点一次按钮，读回剪贴板内容。
4. **分镜顶部的「镜头一览」与总时长**（价值最高，成本中）
   - 打开 `分镜.md` 时，正文上方渲染一张表：镜号、标题、时长、景别/机位、起点 → 终点（截断）、声音，每行链接到下面同一篇正文里对应的二级标题。
   - 表头显示「共 N 镜 · 合计 X 秒」。若 manifest 有 `format.target_seconds_per_episode`，再显示「目标 Y 秒」和一条仪表；这需要 `project_tool status` 把 `format` 的创作者安全子集交给前端。
   - 缩略图只取该镜 `输入参考图` 里 `用途：起始帧` 的 `REF-…` 路径，而且要在树里存在、未超出预览上限；没有就显示「未绑定起始帧」。不按文件名猜图，原因见下。
   - 文件：`app.js`（新增 `parseStoryboard`、`renderShotSummary`，并导出给测试用）、`styles.css`；如需 target，再改 `skills/short-drama/scripts/project_tool.py` 的 status 输出。
   - 测试：
     - node 用 `examples/creator-first/EP001/分镜.md` 断言得到 8 镜、合计 50 秒。
     - 一例 Python 对照测试：同一份夹具上，JS 解析出的镜号与秒数和 `creator_markdown_check._sections` / `_declared_seconds` 的结果一致，防止两套解析漂移。
     - Playwright 断言有 REF 且文件存在的镜出缩略图、没有的出占位，点表行跳到对应标题。
5. **剧本排版**（价值中，成本低）
   - 改动：
     - `角色（提示）：台词` 渲染成说话人加台词两列（参照上述离线报告的台词网格）。
     - `[VO]`、`[OS]`、`[SFX]`、`[画面文字]`、`[转场]` 渲染成小标签。
     - 场次标题拆出内外、地点、时间三个 chip。
     - 只在 `剧本.md` 生效；格式约定已禁止把含冒号的动作写成对白。
   - 文件：`app.js`、`styles.css`。
   - 测试：node 用 `examples/creator-first/EP001/剧本.md` 断言对白行数与说话人集合；Playwright 回归，确认注释剥离不受影响。
6. **视觉设定资产卡**（价值中，成本中）
   - 改动：
     - 打开 `视觉设定.md` 时，顶部按「人物 / 造型 / 地点 / 道具」分组出卡片：名称、识别锚点首句、本集造型、连续性锁（锁面作为 chip）。点卡片跳到对应正文。
     - 第二步做跨集聚合：同名条目出现在哪几集。
   - 文件与测试：同第 4 项的模式。
7. **全文搜索**（价值中，成本中高）
   - 现在只搜标题和集号。要搜全文得新增服务端只读端点 `GET /api/search`，并沿用路径包含、符号链接拒绝和预览上限。
   - 文件：`skills/short-drama/scripts/dashboard_server.py`、`app.js`。
   - 测试：`tests/test_dashboard_server.py` 覆盖越界路径、隐藏根不命中、大小上限。
   - 排在最后。

**刻意不做**（受约束或已被否）：

- **无限画布或节点编排**（多家云端平台的做法）：858bba1 已否。
- **「生成 / 重新生成 / 批量出片」按钮与逐镜 take 历史**：创作台 never 提交生产。
- **拖拽重排镜头**：重排是改正文，而且牵涉镜号稳定，应交回对话。
- **团队空间、在线状态、配额、评论批注**：仅回环、单人本机。
- **时间轴剪辑或导出第三方剪辑工程**：归 `short-drama-edit`。
- **版本回滚 UI**：会成为第二个真相来源，交给 git 或导出。
- **3D 片场或全景**。
- **把一览做成独立的「分镜模式」或标签页**。

## Alternatives considered

- **服务端解析，新增 `/api/storyboard`，直接复用 `creator_markdown_check.py`**
  - 最强理由：只有一份解析器，不会漂移。
  - 暂不采用：
    - 现在所有 Markdown 都在前端渲染；这个检查器的解析是为了报错而写的，容错取向相反。
    - 新端点会增加一块需要安全评审的 API 面。
  - 改用对照测试兜住漂移。若第 4、6、7 项都落地，届时应重新评估，改成统一的服务端摘要端点。
- **分镜提供「表格 / 正文」切换**
  - 最强理由：扫读和细读各得其所，也是主流工具的常见做法。
  - 不用：切换就是第二个视图模式，违反「不提供 tabs 或高级模式」。摘要放在正文上方、点击跳转，一次滚动就能兼顾两者。
- **镜头左列表 + 右详情的三栏工作台**（多个开源工作台的做法）
  - 最强理由：开源工具里最成熟的镜头交互，适合逐镜细读和改动。
  - 不用：它等于第二套阅读区和选中状态，与「选择只在阅读区原地替换」冲突。主流做法里真正服务阅读的是「一览 + 跳转」，第 4 项已经覆盖。
- **按文件名 `制作成果/images/SHOT-…png` 配缩略图**
  - 最强理由：生产适配器的示例输出正是这个命名，不用等 REF 绑定就能出图。
  - 不用：分镜与视频提示词技能都规定「不靠相似文件名猜图」。没绑定的图挂在镜头旁边，会被当成已确认的起始帧；上述离线报告同样选择缺图时明说。
- **每镜显示生产状态徽章（已出图 / 已出视频 / 待审）**
  - 最强理由：云端平台普遍都有，最能回答「这一集还差什么」。
  - 暂不采用：状态只能从命名约定推测，同上会误导。只显示 REF 已绑定的事实。
- **把概览做成可折叠，或者默认收起**
  - 最强理由：改动最小。
  - 不用：折叠状态本身就是隐藏模式；而且首屏问题在手机上主要来自分集条和画廊的纵向堆叠，收起不能根治。

## Consequences

- **收益**：
  - 修掉三处会误导下一步的展示错误。
  - 正文回到首屏。
  - `分镜.md` 能像主流工具的镜头表一样扫读时长、景别和起止，而真相仍是同一份 Markdown，保存路径不变。
  - 第 1–3 项合计预计不到 200 行，可以先发。
- **代价**：
  - `app.js`（现 1263 行）会继续变大，第 4–6 项大约再加 300–400 行。
  - 五文档是「建议格式，不是 schema」，偏离格式的文档只能回退到纯正文，创作者不会被告知为什么没有一览。
  - 前端与 `creator_markdown_check.py` 形成两套解析，靠对照测试维持一致。
  - 总时长仪表依赖 `status` 多交出 `format` 字段，要确认它不含内部路径，并通过 `creatorProjection`。
- **已知上限**：
  - 主流工具的对比大多来自评测文章与教程，需登录的云端平台应用内页面没有实看；各工具「逐镜状态」「版本历史」的 UI 形态未证实，不作为设计依据。
