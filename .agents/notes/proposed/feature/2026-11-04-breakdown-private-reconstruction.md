# Agent Note: 对标拆解增加私有还原层——剧本、物料、逐镜事实与提示词草稿

Status: proposed

翻转 [对标拆解技能](../../implemented/feature/2026-11-03-benchmark-breakdown-skill.md) 里「不复制对标的情节、台词与人物」与「它不写剧本、视觉设定」两处边界；原笔记的测量、对照与出片验证部分不变。

## Problem

创作者要的拆解是能还原：拿到一部对标，能看到它的剧本、角色与场景物料、每一镜怎么生成。现在的 `short-drama-breakdown` 只量、拆、比：BRK-02 规定报告和交接不带剧名、人名、台词和桥段，阶段契约写明不写剧本与视觉设定，脚本也没有看片和听片的能力（不做识别，画面只有每镜中点一帧）。

2026-11-04 对比了 awesome-short-drama-skills 列表和延伸检索出的 13 个同类项目。列表的全流程组 23 个仓库里，除本套件外没有成片拆解模块；能还原的几家在别处：VediotoScripts 一次性产出分场剧本、画风圣经和逐镜关键帧与视频提示词（不是可复用技能，校验器写死 32 镜）；minimax-h3-video-reverse-skill 从逐镜事实契约编译 H3 提示词并有校验器，但写明没做过生成对照；剧灵把视频交 qwen-vl 加专门转写还原剧本，带平台抓取。没有一家用生成结果验证反推。

同日在本机实测 Antigravity CLI（`agy` 1.5.0）：一段 60 秒三维国漫片段，`gemini-4-argon-high` 约 6.5 分钟给出 20 镜逐镜表、还原剧本、物料表和逐镜提示词。切点误差约 ±0.5 秒，但烟雾、火光、闪白过渡的换镜它找得到，`measure`（阈值 0.28，该段最大帧差分 0.22）全部漏掉。把烧录字幕裁掉后在新目录里重跑：Argon 按音轨逐字转出那句台词、时间对得上；`gemini-3.8-flash-high` 回答收不到音频。Argon 第一次运行时自称「只收到每秒一帧、没有音频」，与裁字幕的结果相反；同一工作目录里连续调用会把前一次看到的内容带进下一次回答。

## Proposal

### 两层产物

- **还原层**：放在 `输入/对标/<REF-ID>/还原/`，含逐镜事实 `timeline.json`、跨集人物表 `cast.json`、还原剧本、物料卡、提示词草稿和保真度验证记录。它只供本技能读，用来提炼机制、和本项目对照；不进 `项目开发/`、交付、示例或任何公开文件。
- **机制层**：现状不变，`项目开发/对标拆解.md` 只写机制候选、差距表和实测，按 BRK-02 去掉对标的名字、台词和桥段。
- **授权外流**：BRK-01 登记的允许用途为 `owned`（创作者自有）或 `licensed`（已获授权，记录依据）时，还原层可以交给 `$short-drama-assets`、`$short-drama-video-prompts` 等当起点；其余用途下还原层不出 `输入/对标/`。

### 规则改动

- **BRK-01** 登记增加两项：允许用途取 `study`、`owned`、`licensed` 之一，以及是否允许把原片上传到外部模型服务。上传原片到 Gemini 本身就是一次外传，没登记允许就只用本机测量。
- **BRK-02** 改写：对标原片、转写、拼图与还原层只放在 `输入/对标/<REF-ID>/`；报告和交接不带对标的剧名、人名、台词与独特桥段，BRK-11 允许的交接除外。
- **BRK-11**（`structural_invariant`）：还原层只在允许用途为 `owned` 或 `licensed` 且记录了依据时交给下游。脚本能核对登记文件。
- **BRK-12**（`reviewed_invariant`）：还原层每个字段标证据类型（`measured`、`observed`、`inferred`、`unavailable`）和镜号；时间以 `measure` 的切点为准，模型报的切点落在测量切点之外时标冲突、交人判断，不自动删也不自动收。
- 技能 description 与阶段契约第一段改成：只还原对标、只写进 `输入/对标/`，不写本项目的剧本、视觉设定、分镜或提示词。

### 看片走 agent 一侧，脚本只做确定性工作

- 新参考资料 `references/reconstruct.md`：通道选择（agy 加 `gemini-4-argon-high`；每次调用新建空目录；先用裁掉字幕的十几秒片段确认能听到音频，不信模型对自己输入的描述）、整集一遍加逐镜一遍、输出 schema、说话人与人名只从名条、称呼、字幕取并进 `cast.json`、对白三档（字幕实录 / 转写与字幕互校 / 推断）。
- `breakdown_tool.py` 新增子命令，只用标准库加 ffmpeg：
  - `audio`：`silencedetect` 与 `ebur128`，给出有声区间与响度，没有字幕时也能粗看对白节奏（分不清对白与配乐，标 `measured` 但写明盲区）；
  - `shots`：按测量切点切出每镜小段（H.264、不超过 720p）与首、中、尾三帧，写 manifest，供逐镜那一遍用；
  - `reconcile`：读 `timeline.json`，核对时间轴连续不重叠、每个字段有证据类型和镜号、模型切点与测量切点的偏差（列冲突，不阻断）、`cast.json` 之外的人名（列出，交人判断）、登记用途与交接是否相符（BRK-11，阻断）。
- 保真度验证并入 BRK-09 的出片验证：还原对白与字幕算字错率；用 `plan` 量还原剧本，与原片的 `measure` 比首句、有声占比和镜长；挑 3–5 镜用提示词草稿各生成 2 次，盲判。生成的复刻镜头只放在 `还原/验证/`。

## Alternatives considered

- **只在 `owned`/`licensed` 时才允许还原，学习用途不还原**。最强理由：最不容易出事，现有 BRK-02 一字不改。不用：创作者拆对标的主要目的就是学习，学习用途拿不到逐镜事实，机制提炼仍靠每镜一帧和人眼，还原的价值大半落空；而私有目录加流向规则已能挡住台词和人物进本项目。
- **像 VediotoScripts、剧灵那样直接全量复刻，还原结果直接流向下游**。最强理由：最贴近「还原出剧本、物料、提示词」的字面要求，少一层授权判断。不用：下游剧本与提示词会带上别人的台词和人物，违背套件「改编不改写原著」与原创边界，创作者发布后承担侵权风险。
- **把 Gemini 调用写进 `breakdown_tool.py`**（用 urllib 调 Gemini Files API）。最强理由：一条命令出全部结果，fps 与片段起止能精确设定。不用：原笔记已因联网与依赖否决过把识别放进脚本；规则分级规定脚本只做确定性工作，语义字段归 agent 与审查者；本机也没有 API key，可用的通道是已登录的 agy。
- **把还原剧本、物料直接写成 `short-drama-write`、`short-drama-assets` 的格式**。最强理由：还原稿能直接被下游读，`plan` 能直接量。不用：自包含约定不允许引用别的技能的文件，复制一份格式会漂移；还原层只写本技能定义的逐镜事实与简明剧本，授权外流时由下游技能按自己的格式改写。

## Consequences

- **收益**：拆解能给出逐镜事实、还原剧本和物料，机制提炼有了比每镜一帧更完整的证据；`audio` 与 `shots` 不依赖任何模型也能补上有声区间和镜内运动；模型切点与测量切点互相校正，烟雾、闪白这类过渡不再整段漏掉；自有作品（续作、重制）能直接复用还原层。
- **代价**：放宽了一条 `structural_invariant`，CHANGELOG 记为变更并附迁移说明；私有目录只是约定，挡不住人手复制；原片上传到 Google 要创作者逐部同意；agy 一集 60 秒约 6.5 分钟，长剧成本随集数线性增长；Argon 的时间码只到约 0.5 秒、说话人靠推断，人名在冷门作品上可能编造；`licensed` 靠创作者自述，套件核实不了。
- **未验证**：长于 2 分钟的整集是否要分段；逐镜一遍的成本；提示词草稿在 H3 上的还原度（原笔记已测出三维文生守不住画风，复刻三维对标大概率要挂起始帧）。
