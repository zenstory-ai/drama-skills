# Agent Note: 剪辑单的画面文字、音效与 Remotion 叠层的字体修复

Status: implemented

## Problem

剧本用 `[画面文字]` 写系统面板、带倒计时的任务、屏幕上的粉丝数。视频模型写不对字，分镜和视频提示词
把这些留作后期：画面里只有空白屏幕和留出的空间。剪辑阶段却只能烧字幕，留白一直空着。手工给一部样片
做过一版叠层，路上碰到两个 Remotion 问题：

- `font.ts` 的 `assertFamilyResolves` 在 macOS 上误报。浏览器的中文兜底本身就是 PingFang，
  `"PingFang SC", "__no_such_family__"` 与 `"__no_such_family__"` 测出同样宽度，字体明明在却报缺失，
  挡住了合法渲染。无头 Chrome 实测：默认字体栈、单独的 `"PingFang SC"`、`"Times New Roman"` 全被误判。
- `waitForFonts()` 挂住渲染。并发 2、合成里有 `OffthreadVideo` 时，某个渲染页里 `document.fonts.ready`
  一直不 resolve，第 415–475 帧附近 28 秒超时。改成「`fonts.ready` 与 3 秒计时器先到者」之后，
  同一部样片仍在第 475 帧超时：那个页里计时器也没有触发。

维护者同时要求：字幕句末不带标点、句中停顿换空格；样式后续要重做，样式代码按类型隔离；
画面文字出现时常要配提示音。

## Decision

**剪辑单写法**（`skills/short-drama-edit/SKILL.md` 的「剪辑单要求」是唯一出处）

- `- 画面文字 N：<起>-<止> <样式> <项>｜<项>…`，样式为 `卡片` / `系统面板` / `任务面板` / `角标`。
  单条可不编号，编号规则、相对 CUT 入点的时间与字幕相同。解析与字幕共用 `_field_entries`。
- `任务面板` 与 `角标` 可在末尾写 `（倒计时：<秒>）` 或 `（倒计时：接续）`。接续值由 render 按成片时间
  算出：上一个倒计时的值减去两者起点之差，写的人不用换算跨 CUT 的实际时长。
- 三种面板共用顶部一个位置，角标一个位置；同一 CUT 内同一位置重叠在解析时报错。
- 相邻 CUT 的同一条画面文字首尾相接（≤0.05 秒）时合并成一段，角标跨镜不重新入场。
- `- 音效 N：<起>-<止> <路径>（增益：<dB>）`，增益 −40 到 +6，可省。

**check**（`edit_tool.py`）：画面文字每一项归一化后必须是 `剧本.md` 某条 `[画面文字]` 行的子串（只查这些行，
台词里有同样的字不算）；时间在本段区间内；「接续」之前成片里确有倒计时；音效文件存在、时间在本段内。
素材比剪辑单新的提醒扩展到画面文字与音效时间。

**render**

- 字幕、画面文字、音效共用 `_timeline`：按渲染出的分段实测时长累计，窗口按实测/声明比例缩放。
- 画面文字只走 Remotion。合成 ID 改为 `Overlay`：画面文字在下、字幕在上，一遍渲进透明 VP8，
  ffmpeg 叠到未改动的画面上。字幕走 ffmpeg 路线时这一遍不带字幕，ASS 在叠层合成之后烧，压在画面文字上。
  产物改名为 `叠层.webm` / `叠层.props.json`，props 里是 `screenTexts`（成片秒数与已解析的倒计时）。
- 没装 Remotion 且有画面文字时报错，给出 `cd <工作区> && npm install`，并说明画面文字没有别的路线。
- 音效先混成 `成片-含音效.mp4`，响度两遍测量在它上面做。`amix normalize=0`，原声不被压低；
  原声的声道布局保持不变（强制升成立体声会让单声道对白低 3 dB，测试里实测到）。
- 字幕显示形式由 `_display_line` 生成：去掉句末标点，句中 `，。、；：` 换空格，ASCII 标点句中不动
  （`1,000,000`）。SRT、ASS、叠层都用显示形式；剪辑单与 check 用原文。`SUBTITLE_KEPT_END_MARKS`
  现在为空，留给保留 `？！` 的决定。
- `verify` 按分段实测时长列出画面文字与音效在成片里的起止秒，供抽帧和回听。

**Remotion 源码**（`assets/remotion/src/`）

- 每种样式一个组件（`screen/Card.tsx`、`SystemPanel.tsx`、`TaskPanel.tsx`、`CornerChip.tsx`），
  同一 `StyleProps`；颜色、入场、淡出、位置在 `screen/tokens.ts`。尺寸以画面高度的 1/100 为单位。
  倒计时数字用同一字体族的 `tabular-nums`，不再引入第二个等宽字体栈。
- `rules.mjs` 放不需要浏览器的判断，纯 JavaScript，测试用 Node 直接导入：
  - `familyIsMissing`：去掉字体栈里的通用族名，把具名族分别接在 `serif` 和 `monospace` 前测宽，
    与只有该兜底时相比，两边都相同才判缺失；测宽样本追加拉丁字母。
  - `mustWaitForFonts`：只有页面声明了网络字体（`document.fonts.size > 0`）且未加载完才等；
    叠层只用本机字体，所以不注册等待。真要等时仍用 `settleWithin` 限时。
  - `secondsLeft` / `formatCountdown`：`ceil(倒计时 − 帧号/fps)`，帧的纯函数。

**验证**：`tests/test_edit_screen_text.py` 覆盖解析与拒绝、check 的溯源/越界/接续、props 的成片时间与
倒计时接续及合并、ffmpeg 字幕压在叠层之上、缺 Remotion 的报错、字幕显示形式、音效只在窗口内且不压低原声
（有 ffmpeg 时跑真实混音）、字体判断、倒计时、等待判断（有 Node 时跑）。16 处守卫逐条删除，全部变红。
本机实测：合成工程 `check` 通过、`render` 出片，抽帧看到四种样式、倒计时逐秒走、角标接续值正确、字幕无句末标点；
缺失字体族渲染时报错退出；样片 2487 帧、并发 2 全部渲完（164 秒），原先在第 475 帧超时。

## Alternatives considered

- **画面文字走 ASS 兜底，ffmpeg 路线不依赖 Remotion。** 最强理由是零依赖、默认路线就能出片。
  不用：面板底色、发光、逐条入场都要拿 ASS 绘图指令手搓，倒计时要每秒一条事件，写出来的东西还得维护
  两套外观；样式马上要重做，两套只会翻倍。需要 Remotion 时明确报错比出一版难看的面板更好判断。
- **倒计时只写数值、角标各自写秒数。** 最强理由是没有「接续」这个额外概念。不用：跨 CUT 的成片时间取决于
  分段实测时长，写的人算不出来，差一帧就跳秒。
- **允许画面文字的时间越过本 CUT 出点，让角标一行跨多镜。** 最强理由是写起来最短。不用：会破坏「时间落在
  本段内」这条与字幕一致的检查，删一段或换镜序时画面文字会悄悄挂到别的镜上；改成相接合并。
- **限时等待 `document.fonts.ready`（3 秒）。** 最强理由是对网络字体也安全。实测不够：挂住的渲染页里
  计时器同样没有触发，仍在同一帧超时。保留为声明了网络字体时的路径，本机字体直接不等。
- **字体检测只换一个兜底（`serif`）。** 最强理由是比两次测宽省事。不用：所要字体恰好像该兜底
  （`"Times New Roman"` 对 `serif`）时会误判缺失；测试里这一条会变红。

## Consequences

- **收益**：剧本里的画面文字可以按原文落到成片上，并由 check 追到 `[画面文字]` 行；倒计时逐帧确定；
  提示音与面板同一时刻写在同一个 CUT 里；macOS 上 Remotion 路线不再被误报挡住，也不再卡在字体等待。
- **代价**：有画面文字的片子必须装 Remotion（及其许可证条款）并承担逐帧渲染的时间与内存；Node 端的判断
  测试在没有 Node 的环境里跳过，真实混音测试在没有 ffmpeg 的环境里跳过；叠层产物改名，
  依赖旧文件名 `字幕叠层.webm` 的外部脚本要改。
- **已知上限**：样式是样片外观的移植，等待重做；`？！` 是否保留待定；音效只从文件开头截取，
  不支持从文件中段取声或淡入。
