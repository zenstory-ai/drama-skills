[review-method.md](review-method.md)。本文展开 `REV-08` 与 `REV-09`：检查具体

**每个环节都会成为下一环节的输入。审查必须指出丢失了哪项故事意义、状态、原文内容
或制作要求，以及应由哪个技能修复。**

## 一、先分清什么问题必须阻断

- `structural_invariant`：可见引用、明确时长、同一区间摄影机指令冲突、已声明
  起点/终点不一致等可以直接证明的问题；本地检查可以阻断。
- `reviewed_invariant`：剧情意义是否丢失、人物反应是否承接后果、动作是否可执行、
  指令是否被改写；审查者引用资料给 `REVISE`。
- `craft_default`：常用镜头、密度、布光、提示词组织方式；只能给警告，并允许
  创作者说明理由覆盖。
- `taste_option`：气质、镜头偏好、节奏风格与表现强度；不得单独成为质量缺陷。

不要把“和示例不一样”写成审查问题。先说明违反了哪个已确认事实，或会造成什么
下游损失。

## 二、跨环节常见返工原因

### 1. 覆盖丢失

剧本中的动作、台词、反应、可读文字或转场在分镜/提示词中消失，或一个缩短后的
重试提示词只保留漂亮画面，却不再完成同一叙事职责。

检查：

- 是否能从剧本的每个制作相关段落直接追到承担它的镜头或声音；
- 每个有明确来源的动作是否只实现一次；
- 关键结果落地后，观众是否能看到受影响者的反应或后果；
- 重新编组前后，原文段落、镜头目的、起点/终点与声音引用是否仍相同。

### 2. 表演只有标签

“震惊、愤怒、电影感”没有触发、处理、选择与落点，删掉台词后只剩静态姿势。
修复不是堆更多同义词，而是把故事变化落成注视对象、手部选择、重心、停顿、距离、
呼吸或道具处理。

### 3. 空间与状态漂移

人物位置、朝向、手、持物、伤势、造型、时间、天气或光线在相邻镜之间无原因变化。
先核对负责环节的起止边界和资产版本；若剧情确实需要变化，向对应技能
请求状态或镜头修改，不在提示词里偷偷补故事。

选择性环境变换还要核对 `VID-11`：触发、准确目标范围、结束几何/状态与保持项
是否同时存在；相邻但非目标的人物、道具、文字承载面和空间锚点是否保持原位置、数量与
状态。只写“门消失”“地面折叠”而不写留下什么及什么必须不变，属于无法确认能否执行的问题。

### 4. 文本与声音边界混乱

- `exact-readable` 道具文字与全局 `no-text` 同时出现；
- `no-text` 或 `exact-readable` 镜头绑定了带冲突标牌、界面、号码、水印或字幕的参考图，
  却只追加负面词，没有裁切、清理、遮罩、替换或退回参考图负责方；
- 身份、构图、尺度或效果参考没有说明可参考内容和不可照搬内容，导致它把图中
  没有来源的人物、服装、文字、道具或事件带入当前提示词；
- VO/OS 被写成角色对口型说话；
- 提示词新增来源没有的台词、音乐、爆炸或环境事件；
- 角色名/资产引用进入台词内文；
- 音效、环境底噪与对白方向没有来源或相互遮蔽。

目标模型画音同轨时（`VID-23`），检查声音内容、时序、发声边界是否符合来源，
总结是否错误地引入不存在的声音层。无对白镜也应交代需要的底声或静默。
H3 无非画内配乐时，`non_diegetic_music: N/A` 是有效的空形式。

按实际遗漏、矛盾与影响报告问题，不因出现 `No dialogue` 或第二个否定句判错，
不把 H3 的小样本表现套到所有同轨模型上。相关证据指向同一个问题时合并报告。

### 5. 负面补丁淹没动作

为防止模型缺陷叠加大量禁令，真正的起点、动作、表演与终点被挤成几句。
只保留目标模型已确认需要的条件规则；把故事与连续性要求留在权威规格，不在
每次失败后永久增加一条全局禁令。

### 6. 版本和执行状态冒充内容权威

同一集、镜头或提示词可能保留多个历史版本。审查前先读取当前 creator-visible 文档，并按文件名、
标题 ID 和文中明确写出的母版/替代关系判断当前版本；文件更新时间、编号大小、默认展示项或最近一次
执行状态只能帮助定位，不能替代创作者当前决定。下游仍引用旧标题时，即使内容看似合理也要报告
版本引用过期，而不是把旧稿重新解释成现行要求。

生成或处理任务的技术状态只说明某次执行结束到哪一步，不证明语义质量。任何状态为成功的
历史记录都必须写明当时准确的提示词标题、资产/镜头引用与配置；审查仍比较这些文字是否
覆盖当前创作者可见文档。没有看过媒体时，不得从技术状态、重试次数或结果地址声称画面、
表演、文字和连续性已经正确。

## 三、指令优先级与改写回归（REV-09）

同一提示词可能同时接收故事、分镜、项目风格和目标模型约束。按以下顺序处理：

1. **已确认的故事事实与对白/文字内容**：不能被视觉偏好改写；
2. **已确认的镜头覆盖、目的、起点、终点与时长**：运动规格只能实现，不能
   重定边界；
3. **已确认的资产身份/版本与连续性变化**：绑定正确状态；
4. **创作者已确认的视觉方向和制作配置**：规定摄影、节奏、声音
   与文本策略，但不能覆盖前三项；
5. **目标模型条件**：只处理表达与已知能力边界；无法实现上层要求时报告内容丢失，
   不能静默删除；
6. **装饰性偏好**：镜头花样、泛质量词和未选择的建议最先让位。

若两条同级的已确认规则明确冲突，阻断并交回各负责技能或创作者决定；不要用“最高
优先级”措辞覆盖另一条事实。

### 每次重写或重编组后的回归表

| 义务 | 来源证据 | 改写前实现 | 改写后实现 | 结果 |
|---|---|---|---|---|
| 原文覆盖 | 段落/覆盖引用 | 【填写】 | 【填写】 | 保留/丢失/改变 |
| 镜头目的 | 镜头引用 | 【填写】 | 【填写】 | 保留/丢失/改变 |
| 起点/终点/时长 | 边界引用 | 【填写】 | 【填写】 | 一致/冲突 |
| 资产/连续性 | 绑定/变化引用 | 【填写】 | 【填写】 | 一致/漂移 |
| 对白/文字/声音 | 准确引用 | 【填写】 | 【填写】 | 一致/新增/遗漏 |
| 项目配置 | 创作者决定引用 | 【填写】 | 【填写】 | 遵守/例外/冲突 |

同一剧本重新拆分或压缩提示词时，要额外比较镜头覆盖、每镜目的、总时长与镜头分组、
角色/造型等资产绑定，以及必须照抄的台词、文件名、命令或屏显文字。提示词变短
可能只是删掉重复描述，不自动证明内容更准确；若剧本没变而资产版本或必须照抄的文字
变了，必须有单独的上游变更依据。

**`reviewed_invariant · REV-09`**：正确引用了角色、场景和物品，只能证明绑定存在，
不能证明提示词覆盖了原动作、反应、台词与已确认的项目指令。审查者必须比较
改写前后必须保留的内容。

缩短修改若形成补拍或替代版，必须在 `视频提示词.md` 中标明版本类型、同一文件内的母版或补充
`MOTION-...` 标题，并把每项原文要求对应到当前版本或说明去向。普通母版不为“没有版本关系”制造
占位账目。补拍默认不替代母版；替代版只能提出替代请求，最终由审查结论直接指名保留哪一个标题，
不能让两个版本互相声明对方才是当前版本。若有内容丢失，再由
分镜或视频提示词技能决定保留其他镜头、拆镜、延长、删减或请求上游修改。

## 四、各环节证据问题

### 剧本

- 当前目标、阻碍、选择和局部结果能否在场上看见？
- 升级是否改变权力、信息、关系、资源、物理状态或代价，而非重复加大音量？
- 集尾钩子是否由本集已落地结果造成？
- 前史是否只通过当前需要的行为、证据、关系摩擦或有策略的对白进入？
- 对白策略、声音与信息权限是否区分人物？

### 资产与图片提示词

- Lookdev 人物、地点和高压力测试帧是否投影同一组可观察视觉规则？`role: style` 是否只控制
  声明的色彩、材质、阴影、景深或密度，而没有接管身份、地理、剧情状态或道具文字？
- 每项细节是否服务识别、复用、状态、功能或连续性？
- 身份与造型、地点与观察方向、道具与状态是否分开？
- 白底/方位/产品板是否写入了只属于具体镜头的情绪、构图或光线？
- `exact/graphic/no-text` 文字政策是否与提示词一致？
- 输入参考图的可见文字也符合该政策吗？不符合时是否记录了检查和处理方法，而不是指望
  `no-text` 删除参考像素？
- 每张参考图的 `role`、可参考内容与不可照搬内容是否明确？构图、尺度或效果参考有没有
  改写本来不该由它决定的身份、内容、文字或状态？
- 像素、文字、水印或裁切检查是否有准确的观察记录；没有时是否明确写“未观察”，
  而不是从文件引用或负面词推断已经看过输入参考图？
- 定点修改是否写准确目标、`changes` 与 `preserve_set`？
- 同一地点在同一时间/天气 state 下的各观察方向板，主光来源、冷暖主次、光比方向与实际
  灯具开关是否对齐（`IMG-10`）？不一致时是否有已记录的成因与对应 delta？逐板单独看
  都成立不能作为通过依据，必须并排比同组板。

### 分镜与关键帧

- 关键场次若用了场次视觉计划，开场与结束的观众立场、空间压力、摄影节奏、反应落点和声音
  运动是否共同完成同一转向？普通场景没有计划不构成缺陷。
- Coverage audition 是否比较了真正不同的信息时机、观看位置、表演所有权和最终画面，并绑定
  创作者选择？固定宫格、方案数或景别比例不能当通过条件。
- 每个镜头为什么独立存在，改变了什么注意、压力、信息或观看位置？
- 建立镜头、反应镜、插入镜头或重新解释前镜的镜头是否有职责，而不是凑数量？
- 关键帧是否只有一个可冻结时刻？每张关键帧是否声明了它冻结的是哪一端，并绑定该镜头
  对应的边界字段（`SHT-17`）？**尾帧是 `end_boundary` 的投影，不是第二个终点权威**——
  尾帧与镜头终点不一致时，缺陷记在尾帧上。首帧是否只写 start 事实、尾帧是否只写 end
  事实，两张有没有互相借用？**关键帧数量不是检查项**：默认一张首帧，只在交付工作流真的
  消费尾帧时才有第二张，缺尾帧本身不是缺陷。
- 本镜交出首尾帧时，中间是否有必须被观众看到的动作只靠插值兑现？若有，是该拆镜或把该
  动作移到某一端，而不是在运动规格里多写一句描述。
- 每个已经设计好的镜头是否先独立成立，再进入生成单元编组？
- 裁切、遮挡、背影或画外处理是否遵守 `audience_visibility`：既不提前泄露，也不
  遮掉本镜必须传达的证据或接收反应？
- 覆盖记录里的本集时长总和是否等于各镜头已接受时长的算术和（`SHT-16`）？覆盖列出的
  每个镜头是否要么进了总和、要么显式挂在 `unresolved_durations` 里？**镜头无声地不进
  总和才是缺陷；时长未定并显式挂起不是。** 项目声明了每集目标时长时，是否绑定该字段并
  写出带符号差值与处置？**差值本身不写成阻断项**——目标时长是创作者的计划而非质量门槛，
  只在账目算错、有镜头漏掉或处置缺失时提缺陷。
- 交付面遮挡区是否已声明（`SHT-15`）？**未声明时本规则不生效**：确认它被记为未解决即可，
  不要因此提缺陷，也不要用通用安全框代替声明。已声明时才检查：本镜必须被读到的内容
  （脸与眼神、证据上的可读文字、决定性手部动作）是否只落在这些区域里？镜头是否绑定了
  该声明的具体版本？声明改版后受影响镜头是否重新核对过？

缺少制作输入时只阻断它所支持的交付判断，不阻断文本候选预览，也不把整个镜头笼统判死：

- 缺逐字台词：只阻断具体时长、台词表演与口型可行性，不能自编台词补洞；
- 只有签名职责、没有正式签名字形：只阻断该承载面的 `readable` 文字投产；若已接受文字政策
  允许 `postproduction`，仅预留承载区可以继续，不能臆造笔迹；
- 没有创作者声明的播放面遮挡区：只阻断播放面避让核验与整体 `delivery-ready`，画面候选照常
  预览，不能拿通用安全框代替。

这些状态证明的是输入和文本准备度，不证明媒体结果质量；只有全部适用范围都为 `ready`，
才可声称整体 `delivery-ready`。输入补齐后只重审受影响范围。
若镜头写着空白承载区却让人物认出该签名/文字，直接报告语义矛盾；不能用“后期再加”倒推
当前帧已经具备角色接收和观众阅读所需的证据。

### 视频提示词

- 多人物镜头中，真正承担变化的人是否用所需的 receive、mask/visible leak、choice、landing
  体现立场差异，且表演信号在当前景别可读？没有变化的旁观者是否没有被迫填写 arc，
  `attention_handoffs[]` 是否只记录真实注意交接？
- 第一动作是否能从已确认的关键帧/起点接起？
- 有序动作能否在镜头时长内保住故事动作、表演、对白与落点？
- 摄影机是否由注意、压力或揭示驱动，并且区间不冲突？
- 环境/声音是否有已确认的依据？
- 选择性折叠、消失、替换或复原是否声明目标范围、结束几何和 `preserve_set`，且没有
  连带改变非目标人物/道具/文字/空间锚点？
- 结束报告是否逐项等于分镜规定的连续性终点？
- 交付容器里装了几个已接受镜头？容器时长是否正好等于这些镜头已接受时长之和（`VID-13`）？
  多镜容器的成员是否来源顺序连续、共享同一条绑定链、不跨场次，且每个成员仍能单独审查？
- 空间或被摄主体的跳变是否只落在成员镜头边界上？落在某个成员的计时段内部即为段内藏切；
  容器时长与成员之和不符另记一条算术缺陷，两者不合并成同一条 finding。
- 把本集各容器的成员展开取并集，与覆盖记录的本集镜头集合对账（`VID-15`）：有没有镜头
  出现在两个容器里，或者既没进容器也没作为散镜交付？**逐个容器都正确不能代替这次全集
  对账**——重复计入和无人认领这两种错误在单容器视角下都看不见。容器侧的总时长是否与
  `SHT-16` 的镜头侧总时长相等？
- 配乐意图是否写成了相对相邻镜的进入/退出/让路，而不是各镜独立描述一段音乐？相邻镜的
  标注能否接上（`VID-14`）？**提示词或规格文本**是否要求单镜自带配乐床，或与"配乐归
  时间线层"的已接受方案冲突？成品里究竟有没有烧进音轨**不能由本环节判断**——只有已授权的
  文字观察记录报告了该问题时才据此写 finding，否则保持 `unverified`，不从文本推断混音结果。
- 参考帧已有的外观是否被无谓重复，反而增加漂移？
- 补拍版或替代版是否把每项原文要求分别对应到运动字段或说明去向，并写明
  母版或补充运动记录 ID；若请求替代母版，下游审查结论是否完成覆盖与连续性复核？

## 五、生产纪律

1. **先核对原文覆盖，再选择密度**：镜头数量从意义、动作边界和反应职责推导，不从
   固定拍镜比倒推。
2. **从动作量反推时长**：必须保留的动作、对白与落点放不下时，删减、
   拆镜或请求修改；不靠加快所有动作硬塞。
3. **每组交付只使用一套明确配置**：不要混用两套模型条件或相反的服装/
   光影托管策略。
4. **文本策略双重核对**：提示词约束与资产文字政策都要一致；后处理能力不能
   为矛盾提示词开脱。
5. **定点修改一次改一个意图**：同时显式冻结不变项，记录该修改影响哪些下游。
6. **重试按被拒的那一项路由**：每次重投先写清这次改了什么。拒绝原因指向某项输入时，
   先改那一项再投——指向台词或提示词文字就改写该句，指向参考图就换图或修掉图上被拒
   的部分，指向音频就重录或换音源。被拒的台词改写成同样完成这一拍的另一种说法，
   不是把这一拍删掉。只有拒绝原因不落在任何具体输入上时，原样重投才算一次合理尝试，
   同一输入连续原样重投不超过两次，之后改内容或退回负责环节。审查问题写在该改的那项
   输入上。每次记录失败、改动与 `preserve_set`。
7. **长范围先建连续性记录和检查点**：可一次做完整原文覆盖，但接受、审查与回滚仍按
   创作者能理解的阶段进行。
8. **视频提示词阶段发现故事问题就退回负责环节**：不让提示词用新台词、动作或状态替剧本补洞。

## 六、审查问题怎么写

合格的审查问题：

> `SHOT-014` 的原文段落要求听者在指控后把钥匙交回，当前运动说明只覆盖说话
> 人并以其特写结束；这删除了关系权力转移，也使下一镜“钥匙已在桌上”的起点
> 无来源。由分镜技能补反应或交接镜头，或由剧本技能明确删除转手；不要只在
> 运动说明末尾发明钥匙落桌。

不合格的审查问题：

> 镜头太少、不够电影感、没有按参考比例、AI 味重。

`REV-08` 和 `REV-09` 都要求产物引用、具体资料、影响、修改要求、负责技能、
严重程度与状态。固定字数、镜头数、比例和示例相似度只能帮助提问，不能替代
上述证据。
