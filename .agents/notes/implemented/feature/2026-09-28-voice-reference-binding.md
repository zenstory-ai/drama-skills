# Agent Note: 视频提示词绑定角色参考音频

Status: implemented

## Problem

真实模型探针：把角色自己的 TTS 片段（说的是另一句话）作为参考音频绑给视频生成，一个模型上两名角色的
说话人相似度都从约 0.3 升到 0.69，口型与不绑时接近；另一个模型上两人里只有一人改善。声音身份早已在上游
决定——`voice-direction.md` 把每个角色的参考音频记在《视觉设定.md》人物条目下——但五文档路线没有地方
把它绑到某一镜：「输入参考图」只收图片，封闭用途表没有「音色」，校验器拒绝音频；内置 adapter 能处理
`reference_audio`，却没有从五文档到 job 的路径。

## Decision

**写法**（唯一出处：`skills/short-drama-video-prompts/SKILL.md` 骨架段落）

- `MOTION-...` 在「输入参考图」下加一行
  `- 参考音频：REF-<slot>（顺序：<n>）· <音频路径>《<中文名>》（用途：音色；角色：<人物名>；控制：…；不得控制：…）`，
  多条用 `；` 连接。复用 REF 槽位语法，只多一个 `角色`。
- 音频 `顺序` 与图片分开从 1 数，对应 `@音频N` / `<Audio N>` / `音频N`；图片编号不动。
- 《视觉设定.md》人物条目用一行 `- 声音参考：<路径>（…；状态：<admission_status>）` 记录已选参考，路径打头；
  没有时写 `待选型`（`voice-direction.md`「写入 视觉设定.md」）。

**校验**（`creator_markdown_check.py`，VID-27，`structural_invariant`）：语法与分隔；槽位不重复且不与图片槽位重名；
顺序从 1 连续；用途只能是 `音色`；路径是项目内可读文件（与 REF 图片共用 `_check_project_file`）；控制与不得控制
不冲突；角色是 `人物` 条目且一人只绑一条；角色在本镜可复制正文里说出《剧本.md》记在其名下的台词：引号或
`<d>` 内的汉字与本镜来源场次里一段对白相同（四字以上可为子串）。对白按整段读，跨物理行的段落与 `[VO]`/`[OS]`
一样算一句，段落与标签规则照写作技能 `screenplay_index.py` 在本脚本里镜像一份，不跨技能导入。
同一句属于多人时，引文前的分句只点名其中一人（人物名或画面代称）才归给他，否则报「看不出是谁在说」；路径等于该人物 `声音参考` 的路径，缺行、待选型、不一致
各有一条提示。「输入参考图」里出现音频文件或 `用途：音色` 时直接指向这一行；SHOT 写了这一行也报错。
参考状态（AST-09）和绑定后声音是否真的对上仍归审查与回听。

**生产**（`production_tool.py`）：`prepare` 从 MOTION 解析这一行，要求 job 的 `reference_bindings` 在图片之后
按音频顺序逐条出现、`order` 接续、role 为 `reference_audio`，且只有这些槽位能用该 role；漏掉声明的音频即失败。
adapter 配置的 profile 可声明 `reference_roles`；`run` 在读确认、快照输入之前检查：声明了就只放行列出的 role，
没声明时拒绝 `reference_audio`。内置视频编译器本来就按素材类型分别计数，`@音频1` 自然成立。

## Alternatives considered

- **把音频塞进「输入参考图」并给用途表加「音色」** —— 最强理由：一行清单回答全部素材，不用新字段。
  不用：三种方言都按类型分别编号，混在一个字段里要么让图片编号跳号，要么让 `顺序` 不再等于正文标签；
  分镜也会被迫登记一个与画面无关的输入。
- **只靠内置 adapter 的 role 校验和外部 adapter 契约（「保留或拒绝」）** —— 最强理由：不改配置格式，
  内置编译器对不认识的 role 已在提交前报错。不用：同一个内置 adapter 可能配到不收音频的型号，外部 adapter
  可能静默丢弃；声音漂移接口不报错，只在成片里听得出来，所以要由部署方显式声明。
- **「是否说话」看分镜「声音」字段** —— 最强理由：分镜本来就逐镜写谁开口。不用：那一行是自由散文，
  「应声」「一句」之类写法无法可靠解析；正文里的逐字台词已受 VID-25 约束，按剧本说话人对照更确定。

## Consequences

- **收益**：角色音色能从视觉设定一路绑到生产请求，每一步都可核对；图片编号与既有文档不受影响；
  漏绑或送到不收音频的模型都在花钱之前失败。
- **代价**：多一行字段和一条结构规则；要投产音频绑定的部署必须在 adapter 配置里补 `reference_roles`；
  「说话」判定依赖正文逐字引用台词，只写说话方式不写原句的正文会被判为不说话；「声音参考」行首次有了
  固定写法，此前自由书写的记录需要改成这一行才能被绑定。
