# 逐章提取

## 提取什么

一章提取一份 `chapters/ch-<N>-extract.md`，`<N>` 用索引里的 `sequence`。

**第一行是标题**：`# ch-<N> <原文章节标题>`（原文无标题则只写 `# ch-<N>`，不自拟）。其下固定五段：

1. **概要**：3–5 句，回答「读完这章，谁的处境、认知或筹码和读完上一章时不一样了」，不写流水缩写或「因为…所以…」串联。
2. **情节点**：见下。
3. **载体记录**：见下。
4. **出场人物**：原样记录本章称谓及本章内作用，**不做跨章归并**（归并属 S4）。
5. **未决项**：本章无法判断的指代、时间关系或矛盾，逐条列出。

## 情节点写法

每个情节点一行，四段用 `|` 分隔：

```
P1 类型 | 白描 | 涉及：称谓、物件、地点 | 功能：这一步改变了什么
```

`P<n>` 在每章内编号（跨章引用时带 `ch-<N>`）。文件记录原著路径及本章索引范围，每条结论附具体原文行号；情节点定位可写在白描段中，保持四段顺序。

- **`P<n>` 与类型之间、类型与 `|` 之间各留一个半角空格**（供机械自检 grep）。
- **类型**取自：`行动`、`对话`、`信息`、`转折`、`铺垫`、`兑现`、`状态`。
- **白描**是可观察事实：谁做了什么、说了什么、什么被看见。
- **功能**回答改变了什么：权力、信息、关系、暴露、资源、时间或代价（至少一项）。
- **`功能：` 是情节点第四段专用标记**；概要、载体记录、未决项中改写为「作用」「起到的效果」，防自检计数失真。

通常约 150–200 字原文对应一个情节点；服务同一戏剧目的的连续微动作合并为一条。

## 白描与叙事框架词

白描只写**原文已有的可观察事实**，不把心理断言、作者意图或叙事概括当证据：

| 禁止 | 正确 |
|---|---|
| 通过对话，郑松得知张子豪在韩国训练 | 吴志斌告诉郑松，张子豪在韩国训练 |
| 林风展现了自己的实力 | 林风三招击败对手，围观者倒吸一口凉气 |
| 邵阳感到心碎和愤怒 | 邵阳撞见宋丽与旁人相拥，脚步顿住，攥紧的拳头慢慢松开，一言不发转身离开 |
| 这一章为后文埋下伏笔 | 管家把一枚旧钥匙放进抽屉最里层，没有说明用途 |

**原文为内心独白或第一人称叙述时**，照录其说出或想出的那句话本身（如「他在心里说这次真的完了」），不替其总结心理状态（如「他感到绝望」）。

## 载体记录

每章至少写一条（标准章节通常 2–5 条），拆分「本章必须让读者知道什么」与「原文用什么把它写成场景」，供 S5 判断 `needs_carrier`：

| 字段 | 写什么 |
|---|---|
| 关键信息 | 本章必须让读者知道、误判、期待或确认的事 |
| 原文载体 | 作者用了哪些事件、对话、反应、细节、误导、回扣把它写成场景 |
| 通道 | 原文主要靠哪种方式传达：可见行动 / 对白 / 心理叙述 / 叙述者旁白 / 信息密度 |
| 对读者的作用 | 好奇、期待、压抑、爽、心疼、紧张、甜、热血中的哪几种 |

五种通道对应不同改编去向：

- `可见行动`、`对白`：人物当场动手、亮物证或开口交锋，下游通常能直接拍（`screen_ready`）；
- `心理叙述`、`叙述者旁白`：靠内心盘算、回忆往事或作者总结背景，下游需改成可见动作、物证或简短画外音（`needs_carrier`），纯文字诡计则舍弃（`prose_only`）；
- `信息密度`：表面是平淡日常或背景铺陈，实则密集交代后续冲突必需的规则、家底、人物关系底色或时间死线。例如兄妹俩刚赶走抢房的二叔，隔壁奶奶端来鸡肉炖蛋，妹妹吃两口推给哥哥，哥哥吃完取下墙上父亲留下的柴刀和猎矛准备趁大雪封山前上山——表面是日常吃饭，实则立住护着兄妹的邻里与封山前必须进山换粮的生存死线。标注此项以防下游误作水章砍掉。

过渡章同样写清它维持了什么期待或缓和了什么情绪，不写「无」。

## 机械自检

写入磁盘后由主线程执行以下检查，通过后再发布：

```bash
F=项目开发/source-analysis/chapters/ch-${N}-extract.md
P=$(grep -cE '^P[0-9]+ ' "$F")
grep -cE '^P[0-9]+ [^|]+\|[^|]*[^|[:space:]][^|]*\|[^|]*涉及' "$F"   # 必须 == $P
grep -cE '^P[0-9]+ .*\|.*\|.*\|[^|]*功能：' "$F"                     # 必须 == $P
grep -hoE '^P[0-9]+ [^|]+' "$F" | awk '{print $2}' | sort -u        # 必须 ⊆ 类型表
awk '/^## 载体记录/{f=1;next} /^## /{f=0} f&&/^\|/{n++} END{print n+0}' "$F"  # 必须 >= 3
```

- 载体表计数 `< 3`（表头与分隔行占 2 行，至少需 1 行数据，且只数 `## 载体记录` 节内表格行）、白描或功能段计数 `< $P`、或类型超出枚举时，修正后再发布。

## 并发与串行

- **并发**：每批 5–8 章，一批全部写完并更新 `_progress.md` 后再发下一批。子任务提示必须带材料授权前缀（声明为创作者合法持有的虚构作品、只读转化性分析、通俗题材黑暗元素照常提取），防子代理误拒。
- **串行**：不支持子代理或已在子代理上下文中运行时，主线程逐章提取并跑同一套机械自检。

## 失败处理

| 情况 | 处理 |
|---|---|
| 子代理崩溃、超时、空输出 | 同条件重试 1 次 |
| 机械自检不过 | 带上失败项重写本章 1 次 |
| 重试仍失败 | 标记 `⚠️ 跳过`，写入 `_progress.md` 失败记录 |

单章失败不阻断其余章提取；S2 结束前统一补齐缺章，覆盖率仍不足时停止并报告，不进入 S3。章内个别片段跳过时，逐章提取及下游聚合产物均须注明缺失范围。
