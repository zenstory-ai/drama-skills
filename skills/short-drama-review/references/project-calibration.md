# 项目级试跑与生产反馈校准

校准只读取创作者提供或授权形成的**文字观察记录**，用来改进当前项目的提示词与镜头设计。
本技能不提交任务、不下载或生成媒体，也不从“任务成功”、结果地址或文件存在推断内容质量。

## 先分清两种观察

- `input_reference`：输入参考图上可见的身份、文字、水印、裁切或地理事实；它只支持参考准入。
- `generated_result`：某个准确提示词/规格版本、参考槽位集合和制作配置下的结果观察；它可以支持
  项目内校准，但不能自动变成跨项目、跨配置或跨制作方式的定律。

两种记录都要写明被观察的媒体、观察方法、准确的文档标题引用、观察区域/时间段、限制与观察者。
生成结果还要写明对应提示词或镜头标题、参考图顺序、制作形态/配置和结论适用范围。审查只读取
项目提供的记录，不自行寻找其他项目数据。记录可复核，不代表创作内容已接受或质量通过；
证据被撤回、媒体已经换过或来源无法复核时，停止引用该记录并说明原因。

实际项目记录可以由创作者放在受保护的 `输入/生产观察.md`，也可以直接在当前请求中提供；它不属于
五份单集创作文档，也不进入文本交付包。

## 选择有内容代表性的试跑

不随机抽样，也不规定固定数量。按项目实际风险选互相有差异的代表：身份近景与全身、双人潜台词、
多人同框、手部/道具接触、可读文字、大动作/复杂路径、高难度光影、首尾帧接续，以及最重要的
lookdev 风格帧。选择理由必须对应本项目的风险。

## 从观察到诊断

逐条区分：

1. **直接观察**：被授权观察者实际看见或听见什么；
2. **文本定位**：哪个提示词、规格或镜头条目可能参与；
3. **替代解释**：参考本身、景别、动作竞争、配置或观察盲区是否也可能造成结果；
4. **有界结论**：只在当前项目与准确版本条件下，哪种写法更可读或更稳定；
5. **修订路由**：身份/地理回 assets，构图/镜头边界回 storyboard，图片规格回 image-prompts，
   动作/表演/摄影/声音实现回 video-prompts。

没有授权观察时只写“文字风险”，**不声称看见**脸部漂移、表演失败、光影吞锚点或剪辑问题。

## 诊断之后先定处置，再谈修订

诊断之后先选择处置，再决定是否修订：

| 处置 | 什么时候选 | 本环节要做什么 |
|---|---|---|
| 保留 | 镜头目的已达成，剩余瑕疵不影响信息、连续性与观众理解 | 不改文字；把已知瑕疵记进观察，不伪装成通过 |
| 后期处理 | 缺陷落在文字层、混音、调色、修剪或少量边缘帧上 | 不改提示词；交接给对应责任方并记录归属 |
| 局部编辑 | 构图、时机与表演都对，只有一层错 | 只写该层的修改项与保持项，不重写整条提示词 |
| 重新提交 | 文字经核对没有缺陷，现有证据尚未指向可控原因 | 交负责生产的技能提出有上限的尝试，保留本次任务预览与明确确认 |
| 改写 | 同一缺陷在多次结果中重复出现 | 回到诊断指出的那一层改结构：拆镜、减并发、换实现路径 |

两条判据把它们分开：

1. **缺陷是否落在文字能控制的范围内**。 落在文字之外的（渲染瑕疵、编码、少数边缘帧）不该
   由提示词承担；改提示词只会引入新变量，还会让下一次结果更难归因。
2. **同一缺陷是否已经复现过**。重复出现时重新核对参考、文本与配置等解释；诊断指向结构后，
   应交负责技能修改该结构，不能继续把同样的重投当作修复。

**不要用增加形容词的方式回应重复缺陷**。 在同一条提示词上叠加“高质量、避免变形、保持一致”
一类词，既没有改变任何可执行事实，又让下一次失败失去可比性：文本变了，但没人说得清变的是
哪一条约束。若诊断指向结构，就改结构。

处置写进观察或审查记录，说明选择依据。保留或交后期处理时，不虚构提示词改动；
选择局部编辑、重投或改写时，写清负责方须完成的动作。

选择局部编辑或改写、且缩小了原文要求范围时，修订请求须交代补拍或替代关系：在当前
`视频提示词.md` 的普通说明中引用母版，说明每项原文要求由当前版本、母版、其他补拍承担，还是退回
分镜修订。同一 `SHOT-...` 仍只对应一个正式 `MOTION-...` 和一份可复制正文；独立补拍先交分镜建立
相应镜头，再保留与母版的关系。替代候选只提出请求，由后续审查明确结论，再交负责技能更新正式正文。

## 单变量有界修订

每次只改变当前诊断需要的变量；必须联动的变量一起说明。修订 finding 至少包含准确目标引用、
诊断、`change_set`、`preserve_set`、联动理由、预期可观察变化和仍未知内容。保留剧本原文覆盖、角色
身份、镜头目的、信息权限和终点义务。同一失败不能靠重复提交完全相同的提示词解决。

例：远景里细小眉部标记不可读，不把“所有远景都改特写”提升成规则；本项目可改用轮廓与服装结构
承担远景识别，同时让近景继续保留眉部细节。三人同时独立动作导致注意中心混乱时，先保留一个主要
动作，让其他人用立场不同的延迟反应；这仍是当前 scene/shot/config 的候选诊断。

## 复核与边界

修改后让创作者确认当前版本；后续明确请求复审时，只重新读取受影响范围。观察只证明记录里直接写明的
现象，不证明市场表现、普遍模型能力或最终成片质量。私有观察保留在项目/维护者边界，公共 reference
只能通过 de-copy、反例、盲测和独立 promotion 流程吸收可迁移机制。
