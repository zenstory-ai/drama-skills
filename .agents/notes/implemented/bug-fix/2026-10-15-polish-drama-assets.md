# Agent Note: 资产参考回到单一视觉设定文档

Status: implemented

## Problem

五步精修逐份核对 `short-drama-assets` 的 13 份文档、`creator_markdown_check.py` 和现有五文档示例后，发现参考资料仍可能把当前创作带回旧结构化流程：

- `prop-and-state.md` 要求在 `decisions.jsonl` 里记录现实专名政策未决项，与阶段契约“不建立 occurrence、decision、ledger 或接受记录”相反。
- `voice-direction.md` 把 `reference: null`、`not_voice_identity` 等旧结构字段写成必填，要求同一参考的不同用途拆成多条绑定，却没有区分内部选型说明与当前人物条目的唯一 `声音参考` 行；检查器对重复声音参考行报错。它还把本场表演归到独立配音本，而当前写作拥有唯一 `剧本.md`。
- SKILL 说中文条目名始终参与代称匹配；`_visual_entries` 实际只在没有声明时回退到条目名，显式声明后只使用声明列表。混合语言项目只填英文时，中文提示词不能自动匹配该人物。
- 审查清单把可保留真实未决的阶段完成与下游引用可用混成同一条件，也把需要证据的身份/状态判断一并列为“机械检查”。

已有决定见[五文档架构](../architecture/2026-08-22-creator-first-five-documents.md)与[声音参考绑定](../feature/2026-09-28-voice-reference-binding.md)。本次修正保持其方向，不引入第二套产物或运行时改动。

## Decision

当前创作决定和状态写进唯一的 `视觉设定.md`。专名政策未定时，在对应道具条目保留未决选择、依据和下游影响；不要求旧决策文件。声音身份保留参考、用途边界、观察状态、选型判据和区分度，在一条声音参考路径下分别说明各用途，不生成第二份声音表；实际合成仍由生产技能先预览、取得明确确认后执行。

代称说明按检查器实际分支解释：未声明时回退中文条目名；显式声明时列齐各份正文使用的写法；`无` 表示主动退出名称匹配。审查清单区分结构核对与语义判断，并把资产整理完成与受未决项影响的下游工作分开。

## Alternatives considered

- **给旧 JSON/JSONL 流程补分支**：能直接复用早期模板，但会让同一项目同时维护两套资产真相，违反已接受的五文档决定。旧素材可供概念追溯，不成为当前输出要求。
- **让检查器自动把中文名并入显式代称**：可以减少混合语言项目漏写，但会改变匹配行为，影响有意排除同形常用词的项目。本轮仅纠正文档，保留现有解析规则。

## Consequences

- 收益：按需读取参考后仍可产出当前格式，不会新建隐藏决策文件、重复声音参考，或误信中文名自动参与所有语言的匹配。
- 代价：创作者仍需显式列出多语言实际称谓，并人工判断来源、身份和状态是否合理；机械通过不证明声音听感或资产判断正确。
- 改动仅限资产技能 Markdown 与 agent 说明；规则 ID、四级约束、JSON 资产与脚本字段、既有代码块和合成例保持；文档中的旧序列化要求改为当前条目写法，不改运行时或测试。

独立复核补充：1个P2已修：名称覆盖范围按_check_named_coverage各调用点列明；跨语言代称完整性保持为创作要求，不再声称所有IMG/视频正文都机械核对。
