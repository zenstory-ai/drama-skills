# Agent Note: 爽点先行的改编与项目节奏档案

Status: implemented

## Problem

维护者看完一集按本套件实跑出来的样片，结论是：选了原著最平淡的一段，改编生硬，分镜机械，没有短剧/漫剧的节奏。对 `evaluations/让你管账号/reference-run` 的诊断显示问题出在规则上，不在模型：

- **选段按时序 1:1 拉长**：20 章切出 24 个分集候选，全书第一个爽点落到 EP004。开篇替换点的判据要求「主角第一次做出会付出代价的选择」，旁观者完成的打脸因此被排除；倒叙只允许用于家庭、悬疑、关系戏；改编映射的 disposition 枚举里没有「提前」或「冷开」。
- **节奏没有 owner**：[规则分级](2026-07-16-rule-tiers-and-script-boundary.md) 否掉了通用节拍配额，并规定「数值只作为项目档案」，但没有任何阶段提出或承载这份项目档案。审查又被禁止拿数字比较，于是首钩时间、爽点密度、每分钟镜头数都无人负责。EP001 前 70 秒没有爽点，4 个反转里 3 个挤在最后 25 秒，没有人形对手。
- **类型契约被通用剧作理论覆盖**：「代价是唯一的张力来源」「先建立回报会被花掉的场合」压过了爽文的奖励先行；题材卡没有系统流、重生、逆袭。原著的奖励清单和喜剧吐槽被删，换成一条焦虑条款。
- **说而不演**：VO 占台词 57%，同一件事先演一遍、旁白再说一遍。
- **分镜不会切**：镜长由剧本字数折算而来（这个算法任何技能都没定义），平均 4.7 秒，每分钟 12.7 镜；没有反应镜和正反打，70% 是固定机位；SHT-08 禁止同一动作跨镜重复，也就禁掉了冲击剪辑。
- **表演偏微动作**：规则只允许「一两个细微信号」，还把「停留」推荐为最容易生成的表演。

落地后的纯文本对照（见 Consequences）又暴露三处，根因同样在规则：

- **固定机位仍占 92–100%**：分镜镜头块只有「景别/机位」一行，没有写运镜的位置，摄影机行为在分镜阶段从未被选择；冻结关键帧按 SHT-06 不带运动；视频提示词读到空着的运镜，按「没有动机时 lock-off 是积极选择」锁定。「推近、定格、闪白只留给峰值」又被读成「运动只留给峰值」。
- **两次候选都没选冷开**：STY-25 的判据是「观众收益最强」，候选只写「第一眼得到什么」，没有统一的尺子；两次都把冷开做成了兑现本身，再以「观众还不认识这些人」「会提前花掉后面的兑现」「集中段会再演一遍」否掉。两次都以一屏要读完的后台数字开场。
- **改写越界**：改编映射的 disposition 只有处理原著材料的取值，新增内容只能藏在 `change_carrier`、`move_earlier` 的备注里；「核心关系不可改」写在改编契约表里，却没有规则 ID，STY-07 只管合并。节奏档案的「每集至少一次有对手的反转」和题材卡的「当众压迫」在原著这一段没有对手时，把温和的上级推成了压制者，在 EP003 造出一个新对手。

外部资料给出的做法与此相反：第 1 集从危机开始、不从原著第一章开始，第 1 集结束前交代身份、危机、目标；倒叙放在集中段解释眼前的危机；每 20–30 秒一个情绪触点。一组 13,087 镜的实测里，真人短剧平均镜长 2.5 秒、每分钟约 23 镜，特写加近景约占一半；另一组实测里 5 部有 3 部在前 5 秒内给出第一个钩子。两篇论文指出，LLM 剧本偏平可以用专设的开场、结尾、中段反转审查加以抵消。

## Decision

1. **爽点表先行**（novel-analyze、develop）：`short-drama-novel-analyze` 的 `aggregation-and-entities.md` 定义爽点表，产物写进 `rhythm-and-emotion.md`（NVA-13）：按观众收益给全书情节点排名，旁观者兑现的打脸同样入表，候选集引用 `PAY-<N>`，按爽点分布而不是按章 1:1 切。开篇替换点是「观众收益最强、且能交代身份、危机、目标的一处」，更晚更强的高光报为冷开候选。develop 的首集入口至少比较三个候选，其中一个是冷开（STY-25）；大目标尽早说出口、具体到可核对，不写集号。改编映射的 disposition 增加 `move_earlier`、`cold_open`，登记时必须写 `causal_compensation`（STY-29，`reviewed_invariant`）。压缩先按爽点表取舍，再删支线、合并人物（STY-28）。倒叙与结果预演不限题材；世界设定可延后到它第一次改变选择的那一集（STY-23）。首集入口的每个候选用同一把尺子比：第 0–3 秒观众看见的那一格画面和它自己提出的问题，再比整集收益；冷开常见的三条否决理由在 §4.4 逐条回答。改编的不可改范围扩到核心人物的立场与性情、核心关系与主线：任何改编处理都不改写它们、不与原著事实矛盾，创作者接受的改动除外，提议中的改动登记为 `unresolved`（STY-07 从「合并」扩到全部处理，仍是 `reviewed_invariant`）。原著没有的人物、场景或对手登记为 disposition `add`，写 `addition_rationale` 并列进简报「原著没有、本轮新增的内容」；对手先从原著已有的人和他们做过的事里找，原著这一段没有时报出档案偏差（STY-30，`craft_default`）。
2. **项目节奏档案 `creator_authority.rhythm_profile`**：项目模板带 `{"status": "unset"}` 槽位。develop 按制作形态提出候选（STY-26，`episode-design.md` §10 是字段含义的唯一定义处），创作者接受后由 `set-authority` 写入。`set-authority` 要求十个字段齐全、类型与范围合法（`form` 两种取值，秒数为有限正数，占比在 0–1，计数为非负整数，集号 ≥ 1，拒绝布尔、NaN、inf 与未知字段）；单改一个字段要求档案已是 `accepted`，否则拒绝，防止叶写把 `proposed` 档案顺带提升。`status` 只返回合法的已接受档案，手改后不合法时返回 `{}` 并在 `rhythm_profile_problems` 列出问题。write（SCR-19、SCR-20）、storyboard（SHT-28）、review（REV-12）只对已接受的数值做算术核对，偏差不阻断；`duration_estimate.py` 在 `vo_share_max` 为 0–1 内的有限数时报告 `[VO]` 占比，`[OS]` 画外对白计入台词、不计入 VO。起点值：首钩 5 秒、触点间隔 30 秒、每集至少 1 次有对手的反转、停在峰值、接上集最后一拍、第一个大爽点在第 1 集；真人平均镜长 2.5 秒、近景类占比 0.45 有实测依据，两种形态的 `vo_share_max` 0.3 与漫剧的 3.0 秒、0.45 在表里标「未实测」。
3. **套件级数字只留在档案里**：门槛集的经验区间（8–16 / 25–30 集）只在创作者已声明门槛、并请求位置建议时作为示例出现，套件不提供默认位置（STY-27）；「大目标说出口」不带集号；对白回读删掉不承担动作或冲突的句子，不规定比例（SCR-21）。题材卡只写题材特有的内容，打脸与反转的密度、集与集的衔接指向项目节奏档案。
4. **类型契约**：新增系统流、重生穿越、逆袭三张题材卡（奖励先行、对手压迫落成当众做过的事、保留喜剧吐槽、重生开场模板）；「代价是唯一张力」「先建场合再给能力」收窄为靠代价或积累兑现的题材。
5. **剧本**：能演的不说——`[VO]` 不复述画面，内心独白外化，痛点落成具体场景（SCR-20）；已接受档案的 `end_on_peak` 为 `true` 时，集尾停在峰值上，不接余韵。每集第一拍自己成为钩子：看得见的冲突、反常画面、悬着的问题或峰值的最后一拍，静止画面只要自己提出问题也算；靠读字、认人或下一句台词才成立的信息不单独做第一拍（SCR-22，`craft_default`）。剧本不为凑档案的反转次数新增对手或改写人物立场，那是 develop 的改编决定。
6. **分镜**：镜长由声音事件与已接受的目标平均镜长推出，不按字数折算（SHT-28）；对白场默认一句一镜、给听者、正反打（SHT-29）；峰值处允许声明过的冲击重复（SHT-08 收窄）。每镜新增「运镜」一行，按本镜目的逐镜选：动作要跟、信息要进画、压力要落、峰值要强调时移动，都不成立才固定，固定也写出来；短促推近、定格、闪白是强调手段，只留给峰值，跟拍、揭示、压力缓推不算（SHT-04，`shot-craft.md`「运镜逐镜选」）。视频提示词照这一行写运镜，分镜没写的镜头按目的补选并请分镜补上，没写不等于锁定。短于执行端最短秒数的镜头按叙事长度设计，由分镜向创作者提议多镜容器、在交付档案里声明，方言要求时每切都要有已接受关键帧；未声明或方言不支持时照旧在最短秒数内到终点后保持。默认仍是一镜一生成。
7. **表演**：没有导演选择时，表演强度跟随形态与题材，漫剧与爽文峰值外放，AI 真人峰值至少一个读得出的表演拍（VID-26）；「停留」只替换精细操作，不替换表演。
8. **审查**：档案核对（REV-12）、开场/结尾/中段三道局部检查（REV-13，开场一道另把第一拍单独读一遍）、修订只打补丁并记录被润色删掉的强钩子（REV-14）。故事审查表新增「Adaptation fidelity」一节，按映射引用的原著段落核对人物立场、关系、主线与 `add` 登记；分镜审查表核对每镜的「运镜」是否按目的选。

涉及 `skills/short-drama/`（`project_tool.py`、项目模板、`SKILL.md`、`knowhow-index.md`、`creator-documents.md` 的分镜格式）、`short-drama-novel-analyze`、`short-drama-develop`、`short-drama-write`（含 `duration_estimate.py`）、`short-drama-storyboard`、`short-drama-video-prompts`、`short-drama-review` 的 references 与 stage-contract，以及 `tests/test_simple_lifecycle.py`、`tests/test_structural_validators.py`、`tests/test_creator_first_golden.py`。`examples/creator-first/EP001/分镜.md` 按新格式补了「运镜」一行。

## Alternatives considered

- **把节奏数字写成套件级硬门槛** — 最强理由：实现最简单，审查最容易执行。不用：07-16 已经否掉，而且不同题材和形态的合理节奏差异很大。这里改为项目档案，创作者说明理由即可改。
- **把门槛区间、大目标集号、删句比例保留为 `craft_default` 起点，并在本笔记里声明它们收窄了 07-16** — 最强理由：这些数字对没有经验的创作者是有用的起点，写成默认值省一轮提问。不用：`craft_default` 可以被覆盖，但它仍是套件替所有项目给出的数字，正是 07-16 否掉的形状；门槛区间降为「被请求时才给的示例」、另两条去掉数字，就不需要翻转那次决定。
- **短于最短秒数的镜头默认装进多镜容器** — 最强理由：H3 的逐切关键帧小样本里，容器以三分之一的生成次数得到接近逐镜的构图。不用：`delivery-profile.md` 规定交付路由由创作者档案声明、默认逐镜，容器还要求每切都有已接受关键帧；把它设为分镜默认会让分镜替创作者做交付决定。
- **只改示例，不改规则** — 最强理由：改动最小，示例本身的示范力很强。不用：诊断里的前三个根因都是规则直接要求 agent 那样做，只换示例挡不住规则。
- **规定第一拍必须有动作** — 最强理由：静止开场正是 reference-run 的症状，一条「第一拍要动」最容易执行和审查。不用：一件不该在那里的东西、一个揭晓画面这类静止钩子是正当的；要求的是这一格自己提出问题，不是它在动。
- **把「运镜」做成校验器必填字段** — 最强理由：字段缺失可以机械发现，和「视觉依据」一样稳。不用：出现一行不等于做了选择，校验器判断不了动机；必填还会阻断既有项目。分级按 07-16 留在 `craft_default`，由审查按目的判。
- **在节奏档案里加一个运动镜头占比下限** — 最强理由：与其他档案字段一样可做算术核对。不用：没有实测依据，占比会诱导装饰性运动；根因是没有逐镜做选择，不是缺一个数。
- **把新增内容的登记也定为 `reviewed_invariant`** — 最强理由：两次越界都是没登记的新增，登记失败直接伤到改编逻辑分。不用：不与原著矛盾的新增是正当改编，登记与列进简报是工作习惯；真正的伤害是改写人物与主线、与原著矛盾，由 STY-07 按证据判定。
- **从默认档案里去掉「每集至少一次有对手的反转」** — 最强理由：它是捏造对手的直接推力。不用：对照里有对手的反转从 0 升到 1–2，是有效的一项；改为对手先从原著里找，找不到就报偏差。
- **在 write 阶段加快节奏，不动改编** — 最强理由：只动一个技能。不用：第一个爽点在第 4 集，是选段造成的，剧本阶段「召回只补细节」，拿不回后文的高光。

## Consequences

- **收益**：选段、单集节奏、分镜密度都有了 owner 和可核对的数值；把高光提前有了合法的词汇；题材契约回到爽文本位；数值始终是创作者接受过的项目值。
- **代价**：
  - 改动横跨六个技能；`examples/creator-first/EP001` 仍是静止开场、平均镜长 6.25 秒，没有按新规则重做。
  - 已按旧规则跑完的项目没有 `rhythm_profile` 槽位，只能是「未声明，不核对」，直到第一次写入整份档案。
  - 标「未实测」的起点值需要用样片再校准。
  - `close_shot_share_min` 的景别口径只在 develop 定义，storyboard 与 review 按技能名引用，单独安装它们的读者要回到 develop 才能看到完整口径。
  - 更快的剪辑密度会增加生成次数；多镜容器能抵消一部分，但要创作者声明并备齐逐切关键帧。
  - 运动镜头比固定镜头更难生成、更容易漂；「运镜」写明起止和理由能减轻，但成片里的运动质量仍要样片核对。
  - 已写好的分镜没有「运镜」一行，下游按目的补选，直到分镜补上。
  - 冷开要额外承担时间定位与铺垫补偿（STY-29），选它的项目改动更大。

- **纯文本对照**（《让你管账号》，同一中性请求「前三集规划 + EP001 剧本与分镜」，创作者不在线、按默认值推进；

  | 核心任务钩 | 第 67 / 82 秒 | 第 32.5 / 42.5 秒 |
  | 全书第一个大爽点进 EP001 | 0 / 2 | 1 / 2 |

  | 固定机位占比 | 97% / 92% | 94% / 100% |

  里的根因改了规则（Decision 1、5、6、8）。修正后没有重跑对照，三项是否落到产出仍未验证。样本只有一本原著、
  每臂 2 次，评审与创作同属一个模型家族。
