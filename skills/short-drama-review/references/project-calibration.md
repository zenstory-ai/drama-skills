# 项目级试跑与生产反馈校准

读取创作者提供或授权形成的文字观察记录（如 `输入/生产观察.md` 或当前请求内文），在当前项目与版本边界内做诊断与单变量校准（`REV-10`、`REV-11`）。证据撤回、媒体已换或无法复核时停止引用。

## 1. 区分两类观察记录（`REV-10`）

- `input_reference`：输入参考图上可见的身份、文字、水印、裁切或地理事实，仅支持参考准入判断。
- `generated_result`：特定提示词/规格版本、参考槽位顺序和制作配置下的生成结果观察，仅在当前项目与配置下成立。

两类记录均须载明被观察媒体、观察方法、文档标题引用、观察区域/时间段、限制与观察者；`generated_result` 还须绑定提示词/镜头 ID、参考图顺序与制作配置。

## 2. 试跑抽样与五步诊断

- **代表性试跑**：按本项目实际风险选互有差异的样本（身份近景与全身、双人潜台词、多人同框、手部/道具接触、可读文字、复杂动作路径、高难光影、首尾帧接续、lookdev 风格帧），不设固定数量。
- **五步诊断**：依次写清（1）直接观察到的视听现象 →（2）关联的提示词/规格/镜头条目 →（3）替代解释（参考图本身、景别、动作竞争、配置或盲区）→（4）当前项目/版本下的有界结论 →（5）修订路由（assets / storyboard / image-prompts / video-prompts）。

## 3. 先定五类处置再谈修订（`REV-11`）

按**缺陷是否受文字控制**与**是否已重复出现**两条判据，在提出任何修改前先写出 `disposition` 与 `disposition_rationale`：

| 处置 | 适用判据 | 动作与记录要求 |
|---|---|---|
| `keep`（保留） | 镜头目的已达成，瑕疵不影响信息、连续性与理解 | `required_change` 留空，将已知瑕疵记入观察 |
| `post_production`（后期处理） | 缺陷落在文字层、混音、调色、修剪或边缘帧（不受提示词控制） | `required_change` 留空，交剪辑或后期处理并记录归属 |
| `targeted_edit`（局部编辑） | 构图、时机与表演成立，仅单一可控层出错 | 单变量修改：写出准确目标引用、`change_set`、`preserve_set`、联动理由与预期变化 |
| `resubmit`（重新提交） | 文字经核对无缺陷，尚无证据指向可控原因且未超重投上限 | 交 `$short-drama-produce` 经任务预览与创作者确认后有上限重投 |
| `rewrite`（改写） | 同一缺陷在多次结果中复现，诊断指向结构问题 | 交负责技能改结构（拆镜、减并发、换实现路径）；禁止靠叠加“高质量、保持一致”等形容词充当修复 |

若 `targeted_edit` 或 `rewrite` 缩小了原文要求范围，必须在 `视频提示词.md` 普通说明中交代补拍/替代关系及各项原文义务去向（见 [生产质量门](production-quality-gates.md)）。
