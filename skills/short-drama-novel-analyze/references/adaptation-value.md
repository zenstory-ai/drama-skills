# 改编价值与分集候选

本文件覆盖 S3（`story-units.md`、`rhythm-and-emotion.md`）与 S5（`adaptation-value.md`、`episode-candidates.jsonl`）：先将目标拆解范围内的章节收拢为因果咬合的剧情单元与爽点排序，再结合目标制作形态完成改编取舍与分集候选切分。若本轮系按创作者指定的章节范围（如前 100 章或第一季）分批拆解，所有文件开头均显眼标明本批覆盖的起止 `sequence` 章号。

## 故事框架与剧情单元

### 1. 识别故事框架

通览目标范围各章概要，在 `story-units.md` 开头点明主线结构（看不出单一框架时直写「框架不明确」及原因，不硬套，也无需强行对齐 S1 抽样初判）：

| 框架 | 切分单元依据 | 短剧排集提示 |
|---|---|---|
| 升级流 | 等级突破或地图阶段 | 破境或换地图天然适合做阶段分集卡点 |
| 复仇线 | 清算对象或反击阶段 | 每扳倒一个对手就是一次爽点闭环 |
| 单元剧 | 独立案件或事件闭环 | 最贴合几集一个小闭环的短剧结构 |
| 多线交织 | 人物线索分切，交汇处标明 | 竖屏最易看懵，排集时常需收束视角 |
| 蜕变成长 | 人物处事转变的关键事件 | 心境转变须落到具体外部动作与代价上 |

### 2. 切分剧情单元

一个合格的剧情单元须具备明确目标、具体阻力或对手、在场核心人物，以及蓄力—交锋—落定的完整回合（太碎的单章奇遇并入相邻单元，大而无当的百章空泛主题继续拆细）。每个单元记录六项：**标题**（15 字内）、**章节范围**（索引 `sequence` 起止）、**开场局面**、**核心冲突**、**付出代价**、**结束局面**。前后单元局面须因果衔接；无法归入任何主线冲突的过场或暗线伏笔，按章号列在 `story-units.md` 末尾备查，不硬塞进无关单元，也不拿固定覆盖率百分比倒逼拆合。

## 爽点表

在 `rhythm-and-emotion.md` 中梳理关键悬念推进链、情绪爆发点、连续平淡过渡段（连续多章无明显起伏处标明作者靠什么留人，供排集压缩），并把目标范围内的高光情节点按看点强度排相对先后（`NVA-13`，只排相对次序，不搞数字打分）：

| 列 | 写什么 |
|---|---|
| `PAY-<N>` | 固定编号，供分集候选引用 |
| 位置 | 所在章号（`sequence`）与情节点编号 |
| 类型 | 打脸、奇观、反转、身份揭晓、奖励到手、危机爆发、关系破冰、情感落定、喜剧反差 |
| 促成方与落点 | 谁促成（主角、对手或围观群体当场改口/撑腰）以及看点落在谁身上 |
| 开场潜质与前置依赖 | 能否一并立住主角身份、危机与目标（可作首集或冷开场备选），观众需先知晓什么前情 |

## 三类判定

在 `adaptation-value.md` 中按**剧情单元**整体评估视听转化路径（参考 S2 [载体记录](chapter-extraction.md#载体记录) 并**结合目标制作形态做条件判断**）：

| 判定 | 含义 | 后续处理 |
|---|---|---|
| `screen_ready`（可直接拍） | 在目标制作形态下，靠当场动作、表情反应、对白交锋或画面调度即可成立 | 直接进入分集候选 |
| `needs_carrier`（需改表现方式） | 戏剧冲突成立，但在目标制作形态下原叙述通道会闷场或失真 | 写明具体画面、物证或声音改法；无可行改法则舍弃 |
| `prose_only`（仅限文字） | 效果纯靠文字叙述障眼法或抽象思辨，镜头一拍就穿帮失效 | 明确写清放弃的内容与替代方案 |

### 结合目标制作形态转换表现方式

对话密集或心理描写重并非天然等于改编高风险，改法随目标制作形态而定：

| 原著写法（通道） | 目标制作形态差异与有效改法 |
|---|---|
| 主角在心里盘算对手账目破绽（心理叙述） | **实拍 / 写实三维**：改成停下签字、视线定在单据漏章处并当场追问时间差，让破绽落在动作停顿、物证特写与对手变脸上（`needs_carrier`）。<br>**二维动态漫 / Q 版**：可直接保留定格特写配高语速内心吐槽 `[OS]` 与破绽高亮框，无需删改心声（`screen_ready`）。 |
| 表面乖巧干活、内心放狠话反差 + 大段设定来历百科（心理叙述 + 设定说明） | 砍掉冗长设定百科；保留画面上吃力出糗的肢体动作，叠一句短促冷冽的反差 `[VO]`，靠视听错位出喜剧效果（`needs_carrier`）。 |
| 靠叙述者隐瞒视角人物身份或相貌制造整章误导（文字诡计） | 人物入画即亮明外貌，纯文字障眼法在任何视觉形态下均失效，直接标为 `prose_only` 舍弃，改用可见悬念替代。 |

凡归入 `needs_carrier` 的单元，逐一写明**原文通道**、**目标形态下的具体改法**、**保住的戏剧作用**与**改动折损**；同时给各单元附上场面复杂度简评与题材桥段标签，方便 `$short-drama-develop` 排优先级。

## 分集候选

按**爽点分布、单集阶段进展与集尾悬念**切分（`NVA-10`），不按章数或字数平分：平淡过渡章合并或标可删，单章连炸两个大爽点可拆两集，靠后的炸裂名场面可在交接摘要里建议提前做冷开场。

每一集候选答清四件事：**开场已知前情**、**本集兑现的进展或爽点**、**集尾留下的抉择或悬念**、**下集必须承接的事实**。结果写入 `episode-candidates.jsonl`，每行一条轻量 JSON 记录即可（包含 `candidate_id`、`chapter_range`、`story_units`、`screen_judgement`、`payoffs`、`entering_knowledge`、`promise_paid`、`exit_pressure`、`inherited_facts`，`needs_carrier` 时附简明 `carrier_change`，无需套用繁琐的十余层嵌套模板字段）。
