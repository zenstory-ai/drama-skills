# 创作参考作品的安全摄取

用户提供对标剧、小说、分镜样例或提示词时，提炼它解决问题的机制，避免把原句、独特桥段或
风格组合带入新作品。
本流程只读取用户在当前会话明确提供或授权的材料；不自行连接外部、非公开项目库。

## 1. 先声明本次参考职责

为每份材料记录：来源 locator、用户允许的用途、本次要解决的问题，以及它是主参考还是
补充参考。主参考也不天然拥有创作者权威；任何可迁移选择都要先变成候选，再由创作者接受。

- **主参考**：回答一个主要问题，例如悬疑怎样逐步缩小安全空间；
- **补充参考**：只补一个不同维度，例如群体反应或二维运动预算；
- **无关材料**：与当前问题无关时不加载，避免多部作品的表层元素混成一锅。

材料过长时先按用户问题选择相关段落和完整因果窗口，不能用关键词命中代替阅读上下文。

## 2. 从直接观察提炼机制

先区分“原材料里直接发生了什么”“agent 如何解释”“仍不知道什么”，再写去引用的
机制摘要，把表层桥段压缩成“观众状态 → 戏剧问题 → 可选机制 → 可见效果 → 失效边界”：

```yaml
reference_mechanism:
  source_ref: 输入/references/<locator>
  purpose: 本次参考要回答的问题
  direct_observation: 对功能的转述，不复制原句
  audience_state: 观众进入这一段时知道、期待或误信什么
  dramatic_problem: 要解决的戏剧问题
  optional_mechanism: 可选机制怎样改变信息、权力、关系、路线或代价
  visible_effect: 可见效果由什么行动、物件、空间或反应承载
  applies_when: 适用的观众承诺、人物状态与制作条件
  failure_boundary: 失效边界、反例或需要换法的信号
  may_influence: [因果功能, 信息释放, 场面职责]
  must_not_copy: [文风, 原句, 独特情节顺序, 专有设定, 人物关系组合]
  uncertainty: 仍需创作者决定或另找反例的部分
```

`may_influence` 只列当前项目可以重新选择的功能；`must_not_copy` 保护来源表达。若一项发现
离开人物名、专有设定或原句就说不清，它还不是可迁移 know-how，不进入写作上下文。

## 3. 下游只读取去引用候选

原材料与直接观察记录留在非公开 `输入/` 边界；开发与写作只读取经创作者接受的
机制候选：当前问题、适用条件、可选机制、可见效果、失效边界与禁止复制项。不要把原文、
“语感片段”、整段对话、独特反转顺序或多部作品的风格摘要塞进写作 prompt。

一次只召回与当前场景或分集问题直接相关的少量机制，需要补足另一维度时再读取相应卡片。

## 4. 做迁移检验再交给创作者

用完全不同的题材、人物关系、场景和措辞解释该机制；若仍能说明它解决什么、怎样观察
效果、何时失效，才算完成抽象。随后比较至少一个替代机制，说明各自制作负担与潜在副作用，
让创作者选择、组合或拒绝。

当前项目的剧本与提示词仍按自身因果、可表演性、连续性和制作可执行性接受审查；
“与参考相似”既不能证明质量，也不能单独作为否决理由。
