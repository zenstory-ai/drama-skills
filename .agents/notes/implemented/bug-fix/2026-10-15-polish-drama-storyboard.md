# Agent Note: 分镜参考说明与已接受边界对齐

Status: implemented

## Problem

分镜参考资料仍混有与现行契约不一致的说明：关键帧建议只写“与上一镜相同”，把八行检查表称作十二项并设通用字数门槛；漫剧词表让本阶段直接写回视觉设定；生产分镜资料把项目特定的 clip 编号和结构化 coverage 记录写成通用要求。对白正反打还写成在轴线两侧对切，与同技能的工作侧规则冲突。

## Decision

沿用既有四级规则与分工，修正说明而不修改机器契约和运行时。关键帧正文写清当前画面的绝对状态，参考既有帧只用于核对；取消通用字数门槛，按当前构图保留必要信息。`keyframe-template.jsonl` 的 `generic_prompt` 自然语言占位说明同步采用绝对状态写法，其余 key、schema、ID 和值不变。

项目特定编号与结构化记录限定适用路径，creator-first 继续只维护《分镜.md》。画风或画面代称未确定时交回视觉设定负责技能，由创作者接受后使用。正反打保留同一轴线工作侧，越轴按已声明过渡重新建立。

非 badcase 的合成正例仅作必要纠错：两份冻结帧例删除“与上一镜相同”和视线变化过程，直接保留当前状态；关键帧例去掉“唯一不动的东西”，避免暗示其他内容正在运动；剧本到关键帧例的来源短引改回同文件原句，连续性表明确镜内目光与机器由起点到终点的变化。去 AI 味 badcase、配对例句与其余 fenced 内容保持。

## Alternatives considered

- 保留旧说法并交给 agent 自行理解：文本改动最少；但会让当前帧缺失可执行状态，也会把旧格式带入默认五文档路径，故不采用。
- 直接改写合成示例：可以让示例与规则同步；大范围改写会影响示例的工艺含义，因此只纠正可由同文件原文和既有边界证明的具体错误，其余示例保持。

## Consequences

分镜方法与既有所有权、可复制正文和工作侧约定一致，普通路径不再被旧结构化字段牵引。结构化模板仍需根据具体项目填写；本次不扩展自动校验或验证模型表现。
