# Agent Note: 剪辑单的画面文字、音效与 Remotion 叠层的字体修复

Status: implemented

## Problem

剧本用 `[画面文字]` 写系统面板、带倒计时的任务、屏幕上的粉丝数。视频模型写不对字，分镜和视频提示词
把这些留作后期：画面里只有空白屏幕和留出的空间。剪辑阶段却只能烧字幕，留白一直空着。手工给一部样片
做过一版叠层，路上碰到两个 Remotion 问题：

- `font.ts` 的 `assertFamilyResolves` 在 macOS 上误报。浏览器的中文兜底本身就是 PingFang，
  `"PingFang SC", "__no_such_family__"` 与 `"__no_such_family__"` 测出同样宽度，字体明明在却报缺失，
  挡住了合法渲染。无头 Chrome 实测：默认字体栈、单独的 `"PingFang SC"`、`"Times New Roman"` 全被误判。
- `waitForFonts()` 挂住渲染。并发 2、合成里有 `OffthreadVideo` 时，某个渲染页里 `document.fonts.ready`
  一直不 resolve，第 415–475 帧附近 28 秒超时。改成「`fonts.ready` 与 3 秒计时器先到者」、仍在模块加载时
  注册之后，同一部样片仍在第 475 帧超时。

维护者同时要求：样片的第一版外观太粗糙，按重做后的参考实现移植；字幕句末不带标点；
样式代码按类型隔离；画面文字出现时常要配提示音。

## Decision

**剪辑单写法**（`skills/short-drama-edit/SKILL.md` 的「剪辑单要求」是唯一出处）

- `- 画面文字 N：<起>-<止> <样式> <项>｜<项>…`，样式为 `卡片` / `系统面板` / `任务面板` / `角标`。
  单条可不编号，编号规则、相对 CUT 入点的时间与字幕相同。解析与字幕共用 `_field_entries`。
- 各项的角色由样式和位置决定，不另加标记：卡片每项「名称 … 数值」；系统面板第一项是状态行；
  任务面板是标题、目标，其后形如 `<数> / <数>` 的一项是进度，其余是奖励。
- 奖励可在项末写 `（传说）` `（史诗）` `（稀有）`，缺省按稀有；只允许用在两种面板上。稀有度在解析时剥掉，
  核对的是剥掉之后的文字。
- `任务面板` 与 `角标` 可在末尾写 `（倒计时：<秒>）` 或 `（倒计时：接续）`。接续值由 render 按成片时间
  算出：上一个倒计时的值减去两者起点之差，写的人不用换算跨 CUT 的实际时长。
- 三种面板共用顶部一个位置，角标一个位置；同一 CUT 内同一位置重叠在解析时报错。
- 相邻 CUT 的同一条画面文字首尾相接（≤0.05 秒）时合并成一段，角标跨镜不重新入场。
- 字幕行末可写 `（重点：词｜词）`，词须出现在本句里、且换成显示形式后不为空，否则解析报错。
- 同一 CUT 里同一字段写两遍（包括两条不编号的 `字幕` / `画面文字` / `音效`，或重复的编号）在解析时报错，
  不再让后一条悄悄覆盖前一条。
- 字幕颜色不写进剪辑单：`_line_kind` 在 `剧本.md` 里找这句的来源，`[VO] 系统：` 为 system，
  其他 `[VO]` 为 vo，对白与 `[OS]` 为 line。
- `- 音效 N：<起>-<止> <路径>（增益：<dB>）`，增益 −40 到 +6，可省。
- 面板自带的 `【系统提示】` `【新任务】` `进度` 与倒计时里的 `天` 是样式的一部分，不走核对。

**check**（`edit_tool.py`）：画面文字每一项归一化后必须是 `剧本.md` 某条 `[画面文字]` 行的子串（只查这些行，
台词里有同样的字不算）；时间在本段区间内；「接续」之前成片里确有倒计时；音效文件存在、时间在本段内。
素材比剪辑单新的提醒扩展到画面文字与音效时间。

**render**

- 字幕、画面文字、音效共用 `_timeline`：按渲染出的分段实测时长累计，窗口按实测/声明比例缩放。
- 字幕显示形式（GY/T 288 与短剧惯例）：去掉句末标点，保留 `？！`（`SUBTITLE_KEPT_END_MARKS`），
  句中 `，。、；：` 换成全角空格，ASCII 标点句中不动（`1,000,000`）。超过 12 个字（不计空格）的句子由
  `_split_display` 在停顿处拆开再合并到不超过 12 字，没有停顿的长短语按字数均分；拆点不落在重点词中间，重点词按显示形式（`十万，现金` → `十万　现金`）匹配，
  仍找不到时 render 报错；各条按字数分这句的时间。
  SRT、ASS、叠层都用显示形式；剪辑单与 check 用原文。
- 画面文字只走 Remotion。合成 ID 为 `Overlay`：画面文字在下、字幕在上，一遍渲进透明 VP8，
  ffmpeg 叠到未改动的画面上；画面不在浏览器里解码，避开帧时间不规整素材解出的串帧
  （见 [剪辑的同场景自动接镜与坏帧报告](2026-09-27-edit-cut-continuity.md)）。字幕走 ffmpeg 路线时这一遍不带字幕，ASS 在叠层合成之后烧，压在画面文字上；
  ASS 用同样的尺寸（字高 4.3%、描边 0.42%、`MarginV` 24%）和按来源、重点词的内联颜色。
- props 只带画什么、何时画：`cues`（文字、`kind`、`keys`）与 `screenTexts`（各项 `{text, rarity}`、
  已解析的倒计时）；字体、字号、颜色归合成自己。
- 渲染前按同步过去的 `package.json` 逐个核对依赖是否装上，缺字体包也报错，给出 `cd <工作区> && npm install`。
- 音效先混成 `成片-含音效.mp4`，响度两遍测量在它上面做。`amix normalize=0`，原声不被压低；
  原声的声道布局保持不变（强制升成立体声会让单声道对白低 3 dB，测试里实测到）。
- `verify` 按分段实测时长列出画面文字与音效在成片里的起止秒，供抽帧和回听。

**Remotion 源码**（`assets/remotion/src/`）

- 外观按参考实现移植。字幕：Noto Sans SC 900，字高 4.3%，深色 0.42% 描边压在字下（`paint-order`），
  基线距底约 24%，一行显示、放不下时按宽度缩小；字色白 / `#9FE8FF` / `#3FE0FF`，重点词 `#FFD400` 并有
  120 ms 放大。系统面板：深蓝半透明、青色边与辉光、L 形角括号、移动扫描线、`【系统提示】` 标题行，
  2–3 帧故障后弹簧缩放入场，状态行 35 ms 一字打出，奖励行带稀有度色块、逐条闪入，220 ms 淡出上移。
  任务面板同一套框用 `#FF8A5B`：标题、打出的目标、稀有度色标签、进度行与细进度条、JetBrains Mono 800
  的倒计时逐秒脉冲。角标是同一套框的小号。卡片是白色圆角卡、每行色点、红色等宽大数字。
- 每种样式一个组件（`screen/Card.tsx`、`SystemPanel.tsx`、`TaskPanel.tsx`、`CornerChip.tsx`），
  同一 `StyleProps = { text }`；字体、颜色、稀有度色、入场、淡出、位置在 `screen/tokens.ts`，
  系统类面板共用的框、标题行、打字机、奖励行在 `screen/chrome.tsx`。尺寸以画面高度的 1/100 为单位。
- 字体为 `@fontsource/noto-sans-sc`（700、900）与 `@fontsource/jetbrains-mono`（800），均为 OFL-1.1，
  是工作区依赖，`Overlay.tsx` 只引入这三个字重。
- `font.ts` 的 `useFaces`：挂载时注册 `delayRender`，按 `fontLoadPlan` 对每个字重调用
  `document.fonts.load(字重, 整部片子要画的字)`，用 `settleWithin` 限时 10 秒；结果交 `fontLoadProblem`
  判定——超时、出错、某个字重加载出空列表（没有声明）、`document.fonts.check` 仍为假，都 `cancelRender`。
  就绪之前合成返回空，就绪状态提交之后才 `continueRender`。画每段字时 `assertFamilyResolves` 再测一次宽。
- `rules.mjs` 放不需要浏览器的判断，纯 JavaScript，测试用 Node 直接导入：`fontLoadPlan`、
  `fontLoadProblem`、`settleWithin`（超时解析为 `TIMED_OUT`，不当成成功）、`familyIsMissing`
  （去掉通用族名，分别接 `serif` 与 `monospace` 测宽，两边都等于兜底才判缺失，样本追加拉丁字母）、
  `typedLength`、`parseProgress`（比例夹在 0–1）、`secondsLeft` / `sinceTick` / `formatCountdown`
  （`ceil(倒计时 − 帧号/fps)`，脉冲从数字变化的那一刻起算），全是帧的纯函数。

**验证**：`tests/test_edit_screen_text.py` 覆盖解析与拒绝、check 的溯源/越界/接续、props 的成片时间与
倒计时接续及合并、稀有度、ffmpeg 字幕压在叠层之上及其颜色、缺依赖的报错、显示形式（`？！` 保留）、拆条与分时、
按剧本来源定色、重点词、音效只在窗口内且不压低原声（有 ffmpeg 时跑真实混音），以及 Node 端的字体计划、
加载判定、限时、测宽、打字、进度、倒计时与脉冲（有 Node 时跑）。32 处守卫逐条删除，全部变红。
本机实测（1080×1920 合成工程）：`check` 通过，两条字幕路线都出片，抽帧见四种样式与字幕颜色；
同一帧 25 作为新标签页的第一次截图与同页连续渲到第 25 帧逐像素相同。缺失字体族时渲染报错退出。
参考样片（`OffthreadVideo`、网络字体、并发 2）加上 `useFaces` 后渲完第 0–600 帧，越过原先 415–475 的卡死处。

## Alternatives considered

- **画面文字走 ASS 兜底，ffmpeg 路线不依赖 Remotion。** 最强理由是零依赖、默认路线就能出片。
  不用：面板底色、发光、逐条入场都要拿 ASS 绘图指令手搓，倒计时要每秒一条事件，写出来的东西还得维护
  两套外观。需要 Remotion 时明确报错比出一版难看的面板更好判断。
- **倒计时只写数值、角标各自写秒数。** 最强理由是没有「接续」这个额外概念。不用：跨 CUT 的成片时间取决于
  分段实测时长，写的人算不出来，差一帧就跳秒。
- **允许画面文字的时间越过本 CUT 出点，让角标一行跨多镜。** 最强理由是写起来最短。不用：会破坏「时间落在
  本段内」这条与字幕一致的检查，删一段或换镜序时画面文字会悄悄挂到别的镜上；改成相接合并。
- **在模块加载时等 `document.fonts.ready`，加一个计时器兜底。** 最强理由是改动最小。实测不够：挂住的渲染页里
  计时器同样没有触发，仍在同一帧超时。改为挂载时按字加载、结果逐项判定。
- **只用本机字体，不打包网络字体。** 最强理由是没有加载问题，也不用装包。不用：参考外观要思源黑体 Heavy 与
  JetBrains Mono，本机字体随机器而变，同一剪辑单在两台机器上出两种字。
- **每项或每句都显式写角色、颜色。** 最强理由是一眼可见。不用：颜色已由剧本的 `[VO]` 决定，再写一遍会与剧本
  分叉；任务面板的进度按 `<数> / <数>` 的形状就能认出。
- **字体检测只换一个兜底（`serif`）。** 最强理由是比两次测宽省事。不用：所要字体恰好像该兜底
  （`"Times New Roman"` 对 `serif`）时会误判缺失；测试里这一条会变红。

## Consequences

- **收益**：剧本里的画面文字按原文落到成片上，并由 check 追到 `[画面文字]` 行；倒计时、打字、脉冲逐帧确定；
  提示音与面板同一时刻写在同一个 CUT 里；字幕一行、按来源着色；字体随包走，第一帧就是最终字形，缺字重直接报错。
- **代价**：有画面文字的片子必须装 Remotion（及其许可证条款）与两个字体包，并承担逐帧渲染的时间与内存；
  已装过的工作区要重新 `npm install`；ffmpeg 字幕路线用本机的思源黑体粗体，和叠层的 Heavy 字重不完全一样；
  字幕颜色常量在 `edit_tool.py` 与 `tokens.ts` 各有一份；Node 端测试在没有 Node 的环境里跳过，
  真实混音测试在没有 ffmpeg 的环境里跳过；叠层产物改名，依赖旧文件名 `字幕叠层.webm` 的外部脚本要改。
- **已知上限**：重点词不拆开，含重点词的一条可能比均分的更长或更短；音效只从文件开头截取，不支持从文件中段取声或淡入。
