# 短剧审查

优先由未参与本轮执笔的独立审稿人执行；执笔人自检时如实标明自检。本技能只负责指出问题、说明影响、明确改稿标准并退回对应负责技能，不直接修改受审原稿，不调用生成接口。

## 快速开始

直接读取用户指定的稿件或看片反馈。需要落盘时，单集联审写入 `审查/EP001-审查.md`，专项审查写入 `审查/<主题>-审查.md`；只需口头反馈时直接在对话中回复。出处仅引用文件名、标题编号、行号或简短原文摘录，不建隐藏 JSON、哈希值或状态副表：

```markdown
# EP001 审查

- 范围：剧本、分镜、视频提示词
- 结论：REVISE
- 复核方式：独立审稿 / 自检

## Blocker · REV-001 · 分镜漏拍剧本中的画面文字
- 位置：剧本.md / EP001-SC002；分镜.md / SHOT-EP001-004
- 证据：……
- 影响：……
- 修改要求：交 short-drama-storyboard 补上准确的画面文字内容与景别停顿条件，保持本镜原有的人物站位与情绪反应不变。
- 规则：SHT-01 · structural_invariant
```

- 角色/场景/道具设定、连戏锁、跨时代穿帮与生图提示词：[视觉设定与生图提示词核查清单](references/rubric-assets-prompts.md)

## 工作流

1. **划定受审范围与先查硬账（`REV-01`）**：确认本次受审文档、章节或镜头范围及创作者已拍板的创作要求。先核清标题编号重漏、链接与条目引用悬空、分段与合生分组时长加总、剧本全要素落镜、跨镜连戏状态，以及是否混入私有凭据或本机绝对路径；缺某份前置材料时只跳过依赖它的判断，其余照常审。
2. **顺链条对账并凭实据开单（`REV-02`、`REV-03`）**：按 `剧本事实 → 视觉设定 → 分镜起止状态 → 首尾帧提示词 → 视频动态 → 下一镜接戏` 核查上下游是否走样（指认篡改或漏拍须成对列出上下游原文）。每条问题单写清位置、实据、实际影响、局部修法与不得误伤的保留内容、负责技能及严重程度，不空扣“有 AI 味”“不够电影感”帽子。
3. **局部补丁与亮点保护（`REV-14`）**：返修意见只针对病灶开最小局部补丁，不借局部毛病要求整集推倒重写。对比新旧稿时若发现润色压稿误删了抓人钩子、高潮金句或精妙包袱，单列 `## 被删的强钩子` 记下原位置与原句供执笔人取舍；复审时只核验返修点是否修通及保留内容是否完好，不翻已放行段落旧账。
4. **定级与结论分派**：
   - 严重程度四档：`blocker`（阻断交付的结构错误、核心事实穿帮、泄密违规或不可挽回的成片缺漏）、`major`（伤及剧情理解、连戏或成片观感的中度问题；成片审查中允许创作者拍板重抽或留用取舍）、`minor`（不卡交付的局部瑕疵或后期可修项）、`note`（审美与风格参考建议，`REV-06`）。
   - 审查结论四选一：`APPROVE`（无阻断与中度待决硬伤）、`APPROVE_WITH_NOTES`（仅有 `minor` / `note` 建议）、`REVISE`（存在 `blocker` 或需返工的 `major` 硬伤）、`PROVISIONAL`（关键材料或成片片段尚未查看到，未看过的音画素材如实标为未知，不凭文件名或后台状态猜测画质口型）。
   - 按负责技能归拢返修项交创作者拍板；下游返修与复审在用户明确指示时启动。
