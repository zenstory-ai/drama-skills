# 中文短剧 Markdown 剧本格式

## 1. 剧本管什么、不管什么

`剧本.md` 是场景切分、人物动作、对白和制作标记**唯一直接改稿的正本**。各环节职责分工与规则分级见 [stage-contract.md](stage-contract.md)；不要往剧本里塞角色/场景/道具设定总表、镜号景别与运镜、生图/视频提示词、模型参数或审查结论。

## 2. 文件、集与场景结构

### 2.1 集标题

```md
# EP001 【集名】
```

`EP001` 是固定集号；改集名不改集号。

### 2.2 场景标题

```text
## <场景ID> <内|外|内外> · <地点> · <时间/天气>
```

示例：

```md
## EP001-SC003 内 · 渡口售票室 · 雨夜
```

- **场景 ID**（`structural_invariant`）：同一项目内唯一；只改场景名时保留原编号，新增或拆出场次时顺延发放新编号。分隔符 `·` 两侧留不留空格均可正常解析。
- **空间与地点**：`内/外/内外` 标明主要演戏空间；地点写创作者一眼能认出的常规名称，不写内部资产编号。
- **时间/天气**：只写对表演、打光、动作或前后接戏有用的信息。

## 3. 动作、对白与制作标记

### 3.1 动作段落

普通段落写当下发生的具体行动与场面状态（同一动作段可跨多行，不同段落用空行隔开；完整示例见第 5 节）：

- **`craft_default`**：用现在时和具体动词；核心动作、新露出的信息或人物站位变化时另起一段。简短直观的状态提示（如“神色一凛”“手心渗汗”）只要配着可演动作即可自然带过，重点是不拿大段无法拍摄的纯心理剖析替代可见行动。连贯的成套动作或查证过程可留在同一段里写透，不必按固定字数硬切。
- **`craft_default · SCR-18`**：动作段落**开头避免写“短词组＋全角冒号”**。`第二格：一只手把杯子推过去。` 与对白写法（`角色名：台词`）字面接近，索引脚本会报 `ambiguous_dialogue_or_action`。改用破折号、逗号或直接接动词（如 `第二格换成一只手把杯子推过去。`）；句中冒号或带逗号铺垫的动作长句不受影响。

### 3.2 对白

```text
角色名（可选的语气/说话意图提示）：台词
```

- 角色名最长不超过 40 个字符，支持中文名与带空格的外文角色名（如 `Dr. Lin`、`Agent K`），说话人后使用全角冒号 `：`。
- 表演括注可使用全角 `（...）` 或半角 `(...)`，只写能与台词同步完成的语气分寸或顺手小动作（如“压低声音”“把威胁说成提醒”），上下文动作已写明白时直接省掉。
- 同场画面外的人开口标 `[OS]`，非现场主观独白或旁白标 `[VO]`，两者均可带全半角括注：`[OS] 船员（隔着门喊）：关窗！`。主角独享的系统提示音或心声写 `[VO]`，场上众人皆可听见的广播写 `[OS]`。

### 3.3 制作标记

按剧情与视听需要添加（`SCR-05`、`SCR-07`）：

| 标记 | 用途 | 边界与禁区 |
|---|---|---|
| `[VO]` | 非现场主观心声或旁白 | 不拿来重复画面已演明白的事 |
| `[OS]` | 同一场景画面外的对白 | 说话人必须明确，不能含糊 |
| `[SFX]` | 抓观众注意、推动反应或营造悬疑听感的关键音效 | 不挨个罗列与剧情无关的日常底噪 |
| `[画面文字]` | 观众需看清的载体、系统弹窗或规则字样 | 紧挨着载体亮出或人物目光落向载体的那一拍写出 |
| `[连续性]` | 前文动作已演出、后续容易漏掉且影响接戏的状态变化 | 不每场粘贴整套人物设定，也不能单靠备注断言镜头外“从未发生某事” |
| `[转场]` | 有明确叙事用意的转场衔接 | 不把整集剪辑单写进剧本 |

**`taste_option`（出场名条）**：主要角色首次亮相可加 `[画面文字] 名条：许棠｜社区打印店店主`，只写名字与核心身份（后期剪辑叠字，不塞进画面生成提示词）。

## 4. 注释与未识别格式

```md
<!-- 待确认：渡口停运年份是否影响下一集时间线。 -->
```

- Markdown 注释原样保留，解析与估时会自动跳过注释；影响拍摄制作的关键信息不要只藏在注释里。
- 遇到认不出的 Markdown 写法原样保留并给出提醒，不擅自删改。
- **`structural_invariant`**：整理旧稿格式时必须标出每一处没对上的原文段落，绝不能悄悄漏字。

## 5. 完整场次格式示例

（前情：末班江轮迟迟未归，售票员葛晴的弟弟在船上当水手；站长一口咬定“末班船因大雾已停靠对岸”，机务员游森却在站长锁着的调度台翻出一张印着明晚日期 `11月6日`、背面已用站长专用双孔钳打穿两个放行圆孔的船票副联，顺手摸出栈桥内门黄铜钥匙赶到售票窗前，要葛晴从里侧打开栈桥内门查船。）

```md
# EP001 明天的末班票

## EP001-SC003 内 · 渡口售票室 · 雨夜

售票窗已经落锁。游森从窗口底槽塞进一张湿透的船票副联，食指死死按住票面日期。

葛晴没有去接。她先把窗口旁的木质收渡时刻牌翻了个面。

葛晴（压低声音，防着走廊里的站长）：站长刚来锁了栈桥内门，说末班船半小时前就在对岸收渡了。

游森：那你看看我刚从他调度台里翻出来的这张票。

葛晴捏住票角往里一抽——票面印着明晚的日期，背面却已经用站长专用的双孔钳打穿了两个放行圆孔。

[画面文字] 票面日期：11月6日

[SFX] 雨幕深处的江面传来一声短促的货轮汽笛。

游森回头望向已经熄灯的栈桥码头，把刚从调度室摸出来的黄铜钥匙塞进窗口底槽。

游森：栈桥内门只能从你里侧开锁。想知道你弟那班船今晚被他派去装了什么货，就替我把那道门打开。

[连续性] 栈桥内门的黄铜钥匙留在售票窗内侧底槽，落到葛晴手里。
```

## 6. 时长直测与派生索引

日常写稿与改稿估时直接运行 `scripts/duration_estimate.py --script 剧集/<EP>/剧本.md`，内存直接解析剧本统计字数与秒数，无需落盘任何索引文件。仅在下游环节已建立段落引用、需要核对稳定 `BLK-...` 段落编号时，才用 `scripts/screenplay_index.py` 生成派生索引；索引器绝不反向修改 `剧本.md`。

## 7. 现成剧本整理成标准格式

创作者拿来其他排版的现成剧本时，目标是不改原意、把排版理成标准格式，绝不自作主张改戏或润色台词：

1. 先把来稿原件原封不动存为 `输入/original-script.<ext>`，记清原本的文件编码与来稿说明；
2. 只整理场次标题、动作与对白切分、标准制作标记以及跑索引必需的最少格式调整；
3. 给创作者看原稿与整理稿对照预览，把纯排版调整、动到原意的地方（增删改字句）、没对上的段落与拿不准归类的句子分开列清；
4. 创作者拍板确认后才写入 `剧本.md`。

- **`structural_invariant`**：未经创作者确认不得覆盖 `剧本.md`，原稿里的关键信息一字不漏。
- **`reviewed_invariant`**：凡动到说话人归属、动作先后、事实、因果、人物态度或潜台词留白，一律算改动原意，必须单独标明，不能混进纯格式整理；整理格式时不强求补写大纲简报或加戏。
