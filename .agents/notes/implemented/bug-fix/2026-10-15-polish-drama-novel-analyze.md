# Agent Note: 原著分析精修与阶段交接对齐

Status: implemented

## Problem

原著分析文档存在几处与既有契约不一致的执行说明：S0 只展示可选 core 发布命令，独立运行时未接上正式索引；单章失败允许继续管道，与 NVA-03 及 coverage 的缺章检查矛盾；人物归并称只有专名和绰号可合并，但同文件又允许有同指证据的“姓氏＋头衔”。逐章示例也没有说明结论怎样携带 NVA-02 要求的原文定位。

## Decision

按 prose-gap-polish 五步逐份精修本技能文档，保留代码、示例、规则 ID 和四级分类。补足独立 S0 索引发布；区分继续处理其他章与进入聚合，缺章仍按既有覆盖率门禁停止；统一人物称谓的可合并条件；明确定位可写在白描段中，不改变四段情节点格式。删除载体表行数与快评数字范围的矛盾说明。

文件名错误的提取不计入覆盖，对应章仍出现在 `missing`，先修文件名再补跑。聚合优先读提取、允许按定位回查原文，与硬事实可追溯要求一致。载体分类按能否保留戏剧功能判断，不把心理叙述或使用旁白直接判成 `prose_only`。重叠率只触发边界复核，不自动证明两个单元应合并。

## Alternatives considered

- 把单章失败当作已覆盖能让全管道继续，但空文件和失败记录都不能证明提取完成，因此不降低 NVA-03 的覆盖要求。
- 禁止所有头衔归并最容易执行，但“姓氏＋头衔”在现有表格中已有同指证据例外，因此只统一其适用条件。

## Consequences

独立安装与项目集成使用同一正式产物路径，归并和缺章处理前后一致。代价是缺失章节仍需补齐才能交付全量聚合；原文定位继续由分析者按证据填写，不把语义判断写进脚本。
