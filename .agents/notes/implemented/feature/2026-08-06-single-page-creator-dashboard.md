# Agent Note: 创作台只有一页，不提供工程模式

Status: implemented

## Problem

本地项目控制台最初是文件树加阶段目录加生命周期入口：创作者要理解存储格式才能找到剧本，`创作者决策/`、`审查/`、`交付/` 与运行记录和正文并排出现。创作者打开后答不出「哪个项目、哪一集、现在做什么、下一步是什么」。

## Decision

创作台是一页：项目标题与状态、内容目录、始终可见的当前正文、待办与导出提示。它 never 提供 tabs、弹出式文档查看器、高级模式、工程模式、raw-file view、生命周期面板或技术报告入口；选择另一项只在阅读区原地替换。`app.js` 的 `HIDDEN_ROOTS` 让 `.short-drama`、`创作者决策`、`审查`、`交付`、`事务` 没有产品导航；唯一例外是 `审查/<EP>-审查.md`，以创作者可读的审查意见展示。分组按路径规则为主、`project_tool status` 交出的 `ownership` 兜底，新增阶段的产物落进自己的组而不是「其他内容」。

保存只持久化当前 Markdown，never 确认或启动外部生产；修改、续写、审查、导出、投产的请求交回对话。问题卡用观众或生产影响措辞，不显示内部严重度名、reviewer 身份、存储路径或协议状态。实现约束：Python 标准库服务器加原生 HTML/CSS/JS，不加依赖；仅回环、Host/Origin 校验、路径包含、拒绝符号链接、原子保存、并发编辑保护为必需；浏览器 never 提交哈希、manifest 或任意输出路径；客户端 never 用第二层后缀白名单覆盖服务端的 `writable` 判断。

它读取的五份文档见 [creator-first 五文档](../architecture/2026-08-22-creator-first-five-documents.md)。

## Alternatives considered

- **把 `创作者决策/`、`审查/`、`交付/` 放回目录** — 评审曾提出，理由是既有使用方式被收紧。被否（3e469b1）：屏蔽工程细节是作者已声明并有测试覆盖的设计意图，评审只要求把这条收紧补进 CHANGELOG。
- **保留独立的宣发或媒体标签页** — 临时样片需要可发现。被否（c0634d1）：临时样片不是技能产线阶段，进「全部」即可，阶段分类保持 fail-closed。
- **引入前端框架或数据库** — 交互更丰富。被否（858bba1，0.4.0 重申）：本机文件管理不需要生产依赖；不加生产 API、供应商配置、任务提交按钮、数据库或画布编排。

## Consequences

- **收益**：十秒内答出项目、集、当前工作与下一步；分组自维护——新增阶段技能没有去处时测试会红。
- **代价与已知上限**：生命周期内部信息（`status` 的 authority 一节、`bound` / `hand_edited`）只给 CLI 与 reviewer 看；创作台不模仿它完成不了的动作，投产确认永远在对话里。将来若加 action API 缩短这个回路，它 must not 成为第二个真相来源。
