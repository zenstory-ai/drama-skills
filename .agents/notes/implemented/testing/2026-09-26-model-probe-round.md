# Agent Note: 用平台生成额度实测一批未验证的模型行为断言

Status: implemented

## Problem

技能里有一批规则的依据是「模型会怎样」，但这些行为从没用真实生成核对过，其中几条已经是硬门禁或必填项：

- `motion-recipe.md` 3.6 说秒段总和不足时，余量会被未经批准的动作填满，`motion_timing_check.py` 据此把「不足」判为失败（VID-04）。
- `motion-recipe.md` 3.6 要求写「约五厘米」这类量级，`review-and-fixtures.md` 反例 F 和 `generability.md` 却说厘米级位移执行端对不上、要改写。两处自相矛盾。
- `camera-audio-continuity.md` 说不写机位句镜头会漂。
- 默认续接路线「上一段真实视频 + 真实尾帧」只验证过尾帧那一半，当时的调用路径不支持视频参考。

外部调研又带来几条与现行写法冲突、或套件没有覆盖的做法：

- 一套外部开源短剧 skill 在 H3 一次生成里让 3–5 个切点各对齐一张关键帧，并禁止在视频正文里写角色名。套件一镜一生成，多人同框时重复角色名加资产索引。
- 一个本地部署 H3 的开源项目报告两件事：旁白镜里画中人会跟着动嘴，提示词没写到的配件会镜间闪烁。
- 同一套外部 skill 报告声景里写着的事件会被画面演出来。

另外 Wan 3.0 已在所用生成平台上线，套件没有它的方言，只能走通用路径。

## Decision

2026-09-26 在一个生成平台上跑完一轮实测，覆盖 H3、Seedance 2.5 样片档与 Wan 3.0。结果一行一观察，追加进 `evaluations/model-behavior-probes.md`。文首写明日期范围、路径与判断方式（去臂身份后盲判，判断者为同一个模型）。「执行路径限制」一节记下三件事：该平台 H3 与 Wan 3.0 的视频参考未接入，Seedance 2.5 延长可用，Wan 3.0 首尾帧不在模式列表中。原始媒体在仓库外。

据此落地的改动，每件事只在一份文档里讲完整，其余位置只链接：

- **VID-04**：等式 `structural_invariant` 和 `motion_timing_check.py` 的双向判定都保留，只改「不足」一侧的理由。A1 共 12 次，没有出现计划外动作；观察到的是已写动作被拉长去占满镜头，放杯落在 6–7 秒，补写的 3 秒定格也没有出现。所以秒点只是计划记账，不是精确落点。完整说法在 `motion-recipe.md` 3.6。`delivery-profile.md`、`performance-action-timing.md`、`production-prompt-grammar.md`、`review-and-fixtures.md` 改为引用 3.6，校验器的 docstring 与 shortfall 消息同步改写。保留等式的理由：秒段加总等于镜长，对白预算、容器算术和剪辑用的秒数才对得上同一个镜长；只写到 5 秒的计划声称动作 5 秒完成，实际落在 6–7 秒，把余量分给已有阶段能让写下的节奏和实际拉长方向一致。
- **动作终点**：`motion-recipe.md` 3.6 改为用接触点或地标写终点，并带 A3 的对照数字。可执行检查表删掉「至少一处量级」一行，写法示例去掉厘米。`production-prompt-grammar.md` 同步改写并链接 3.6。`review-and-fixtures.md` 反例 F 与 `generability.md` 原本就是这个方向，未动。
- **无起始帧时的取景**：`target-model-profile.md` 的「参考条件方式」新增一条 `craft_default`，带 B5 与 C4 的数字。`production-prompt-grammar.md` §一、`minimax-h3.md`「每张图带什么」和 `wan-3.0.md` 都链接到这里。
- **H3 多镜容器**：`minimax-h3.md` 新增「多镜容器：每切一张关键帧」一节，定为 `taste_option`，带 B1 的数字。它有三个条件：每切都有已接受起始帧；总长在 4–15 秒内并按交付形态的多镜容器记账；参考清单里关键帧按切序排在前面。第一行写对齐句。原来「一镜一次生成」改为默认，并指向该节。`short-drama-storyboard` 的 `shot-craft.md` 加一句指路，只按技能名路由。
- **画中人的旁白**：`camera-audio-continuity.md` §4 新增一条 `craft_default`，带 B3 的数字。优先让分镜把她的嘴移出画面，闭嘴句作为兜底。
- **Wan 3.0**：新增 `skills/short-drama-video-prompts/references/wan-3.0.md`。内容包括推荐档案、模式互斥、素材编号与上限、时长、多镜时间段（带 C5 的数字）、`说道：“…”` 对白与语速（带 C1、C2 的数字）、声景与配乐层（带 C3 的数字）、`prompt_extend`、编辑与延长关键词，依据两份官方文档（2026-09-26 核对）。注册位置有：`SKILL.md` 的路由句与按需知识、核心 `short-drama/SKILL.md` 的推荐档案指路；`tests/test_creator_first_golden.py` 的参考文件集合、`tests/test_shipping_boundaries.py` 的外链白名单各加一项。生产端没有 Wan adapter，本轮不加。
- CHANGELOG `[Unreleased]` 记三条 Added、两条 Fixed，链接观察摘要。

## Alternatives considered

- **删掉 VID-04 的「不足」一侧，或降为 `craft_default`**。最强理由：规则写明的危害（余量被未批准动作填满）在 12 次里一次都没出现；以一个未被观察到的后果阻断创作者，分级偏重。不用的原因有三：一是等式本身仍是对白预算、容器算术与剪辑共用的记账；二是 A1 只否定了原理由，没有证明缺口无害，秒点后移同样让计划不再描述成片；三是样本只有 H3 一个模型、一个镜头。
- **把 H3 多切容器设为默认**。最强理由：生成次数降到三分之一，切点误差 ≤0.12 秒。不用：它只在每切都有已接受关键帧时成立；一处失败要重出整组；逐镜生成保留单镜重跑与单镜审查的余地。
- **靠参考图的「不继承其构图」保留说明挡住景别漂移**。最强理由：句子短，与现有 `不得控制` 写法一致。不用：B5 的无字段臂本来就带着这一句，8 次里仍有 3 次远景、3 次中远景。
- **旁白镜只靠闭嘴句**。最强理由：不必改分镜。不用：三种写法 12 次里只有 4 次完全闭合。
- **Wan 3.0 对白沿用 Seedance 的花括号写法**。最强理由：实测 3/3 可用，两种方言写法统一。不用：官方示例用 `说道：“…”`，两者在该样本中无差，跟官方写法。
- **在技能正文里直接链接观察摘要**。最强理由：实测数字就近有出处。不用：每个技能自包含，技能内链接必须落在本技能目录里。正文沿用 H3 方言「小样本」加样本量的写法，CHANGELOG 负责链接摘要。
- **只读外部仓库的结论直接改技能**。最强理由：省钱省时间，这些外部项目星标多、踩坑记录详尽。不用：它们多为单种子轶事；本地部署 H3 的那个项目 cfg=1，负向提示词根本没接入。本轮 B4 与 B2 也没有复现外部报告的现象。
- **把额度用于给所有平台模型写方言**。最强理由：覆盖面最大。不用：维护者只决定补 Wan 3.0；每多一份方言，都要随模型更新复核。
- **每臂 8 次以上、少做几项**。最强理由：单项结论更稳。不用：本轮目标是先筛出有信号的断言；只有 B5 这类有信号的项目加到 8 次。

## Consequences

- **收益**：
  - VID-04 的理由和实测对上；两处量级写法的冲突消除。
  - 无起始帧取景、旁白镜、H3 多镜容器都有了带条件的写法。
  - Wan 3.0 进入受支持方言，语速与超长台词的行为有了实测数字。
- **代价与已知上限**：
  - 每臂多为 4 次，只能看出大效应；判断者是同一个模型，不是独立人评；测试世界只有一个旧书店。
  - Wan 3.0 的首尾帧、视频参考、编辑、延长和 `prompt_extend` 的实际效果都未实测，方言里标为官方写法。
  - 真实视频续接在 H3 上仍未验证。
  - VID-04 仍会阻断秒段不足的计划，但阻断理由从「会被填满」变成「计划不再描述成片」；如果以后有人主张降级，要拿新的证据来，并另开一篇笔记。
